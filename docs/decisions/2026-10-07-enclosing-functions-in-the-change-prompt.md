# Enclosing functions in the change prompt

Choice: At a level that reads `functions`, the change prompt carries the head's function around each hunk of a TypeScript file, after the diffs, each in a `function` block of its own with numbered lines. The compiler finds the bounds: TypeScript 7's native syntax tree, asked through `HeadProgram`, a virtual file system holding the head's text from git. The innermost named function holds a hunk: a declaration, method, constructor, accessor, or a function value that a variable, property, or default export names. A callback passed to a call has no name, so the function around it holds the hunk. A deletion belongs to the function that holds both lines it sits between. Every other case, a file in another language, a hunk outside any function, a function past 250 lines, a file past 512 KiB or past the first 200 TypeScript files, and blocks past 64 KiB, stays with the instruction: the lens reads the function with `read_file`. The instruction still says so, and names the cases. A compiler that cannot start leaves the review unchanged, with a note on the lens's record that it read the functions itself.

Why: Problem: at `functions` the lens spent its tool budget reading the function around each hunk, and `deep`'s budget of 60 tool calls was counted against reads Melian could have made. A parser for each language was the obstacle, and a guess from indentation or braces would show the model a wrong scope as fact. Solution: TypeScript is the language Melian's own repository and most customers' repositories use, and the compiler's tree is exact. The other languages keep the instruction, which was always right and only costs tool calls. The prompt gains at most 64 KiB, bounded apart from the 200 KiB diff, which a cut diff never receives. The compiler reads text from git, never the working tree and never an author's path: the virtual files carry names the compiler chooses, so a path cannot reach it. The function text enters the prompt inside a `function` boundary with the review's nonce, as every line from the head does. The reader is `HeadProgram` in `compiler-graph.ts`, beside the step 11 compiler graph of [pull request #89](https://github.com/melian-agent/melian/pull/89), so Melian has one path to a TypeScript program. The graph opens a project from a checkout; `HeadProgram` opens the same compiler over text.
