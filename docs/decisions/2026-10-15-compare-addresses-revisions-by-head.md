# `melian compare` reaches a merged pull request's stored rounds

Problem: once a pull request merges, `melian compare` and `melian findings` cannot reach its stored rounds. A range changeset's ID hashes the range's mode and the canonical names of its base and head. After the merge `origin/main` is the merge commit, so `origin/main...HEAD` collapses, and no other range names the changeset that was reviewed. A round run from a worktree on the branch is also only one revision of a branch changeset, and no command addresses any revision but the latest.

Example: the last five comparison records were written by hand. The records for [pull request #114](../../packages/evals/comparisons/2026-10-14-pr-114.md#how-this-record-was-made), [#116](../../packages/evals/comparisons/2026-10-14-pr-116.md#how-this-record-was-made), [#117](../../packages/evals/comparisons/2026-10-14-pr-117.md#how-this-record-was-made) and [#113](../../packages/evals/comparisons/2026-10-14-pr-113.md#how-this-record-was-made) each quote the refusal, `Melian has no review of <sha>; run melian review <range>`, for three or four ranges they tried. The record for [#111](../../packages/evals/comparisons/2026-10-13-pr-111.md#how-this-record-was-made) worked around it with a scratch clone whose `origin/main` was reset and a copy of the store, which reached only the latest revision. So none of these five feeds `melian compare stats` from the shared store, and its recall and precision say nothing about the pull requests they cover. The record for [#102](../../packages/evals/comparisons/2026-10-12-pr-102.md) did reach the store, because its rounds ran detached and were adjudicated before the merge, one changeset per round.

Choice: a stored round is found by what Melian recorded about it, not by the range that made it, so a merged pull request's rounds stay reachable and its record is exported from the store. `melian compare "#N"` gathers the rounds of a merged pull request, and a recurring finding can be adjudicated across them. Thread import from GitHub keeps every rule of [the comparison-sites decision](2026-10-05-comparison-sites.md), unchanged. Until this is built, records after a merge are written by hand, as now.

This decision records the problem and the direction only. The step that builds it, plan step 23, writes the full decision against the code first and has it attacked before any code. Designing the round record and its addressing here, ahead of the step, drew a new hole in each of four reviews; [the convergence rules](2026-10-15-review-loop-convergence-rules.md) say to stop at that point.

Open questions for the step:

- Round identity and numbering. Two rounds can share a changeset, a base and a head, as a delta round and the full round after it do, so a round needs an identity of its own, kept across a resume after a crash. Found by Melian's first round on [pull request #122](https://github.com/melian-agent/melian/pull/122).
- Writes name one round. `adjudicate`, `match` and `unmatch` must never select several rounds, or several storage roots, by head and base alone. Found by Codex's adversarial review of [pull request #122](https://github.com/melian-agent/melian/pull/122).
- Thread import keeps its head rule. Importing GitHub's threads still refuses a pull request whose GitHub head differs from the stored review's head, and still lists a thread from an earlier head as external-only, because GitHub carries a thread's lines forward. Raised in the coordinator's third round on [pull request #122](https://github.com/melian-agent/melian/pull/122).
- Which rounds belong to `#N`. Selecting by head alone also gathers a round with another base at the same head, such as the pre-push mutation round `AGENTS.md` asks for, or a retargeted base. Such a round must be listed as foreign and never written. Found by Melian's fifth round on [pull request #122](https://github.com/melian-agent/melian/pull/122).
- A cross-round adjudication that completes after a crash. Adjudicating one recurring ID across several rounds writes several changesets, so a crash midway must leave a state that a rerun finishes without changing what was written.

How `compare stats` counts a pull request whose rounds sit in several changesets stays [readiness question 3](../readiness-check-questions.md).
