# Review plan and routes

Choice: A committed `melian.yaml` may carry the team's default routes; `melian.local.yaml` and a user-level configuration file carry only overrides. Which model plays which role is a lookup, never a model's judgment: a deterministic resolver over pi-ai's catalogue (family, context window, price), the credentials present, and later the calibration store's per-lens scores produces a review plan at intake, a durable document that `melian doctor` prints. The plan routes each lens's finder, each candidate's verifier (a different family from its finder when available), and the walkthrough. It routes no deduper in milestone 2: the mechanical merge by finding ID and across rules runs before verification, so one defect is verified once, and detecting duplicates by meaning on a decision model is milestone 4. A route gains `accept`, the models that satisfy the tier, and `unavailable: fail | derive`, default `derive`. With `fail` and no accepted model credentialed, every check on that tier records `failed` with the reason, and the verdict is not reviewed. A local file or `--model` may route a tier outside `accept`; the review runs, and every check that ran outside policy records in its lineage the lens, the model it ran on, the model policy wanted, and the file or flag that overrode it. That record appears in the CLI's output, `melian findings --json`, the review body, and uncollapsed at the top of the ledger. Policy may set `acceptOverridden: false` for a tier. In milestone 2 the key fails closed everywhere, locally too: a check that ran outside policy on such a tier records `failed` with the reason, and the verdict is not reviewed. In milestone 3 a host completing the manifest reruns such a check instead. Routes stay overridable per path, and a local file may pin one lens to a model or cap its level. Policy, routes included, is still read from the base for a pull request.

Why: Forbidding committed routes was the blunt fix for one failure: a contributor whose credentials matched no route saw `melian doctor` pass and every review exit not reviewed. The resolver is the sharp fix. A committed route is a default, and an engineer without its credential gets a derived route and a doctor line saying so, so rolling Melian out to a team is mostly distributing credentials. Asking an LLM which model should verify a finding would add noise to a question with a right answer it cannot see; which lenses run is a judgment over content, and belongs to triage.
