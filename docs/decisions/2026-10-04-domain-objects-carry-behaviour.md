# Domain objects carry behaviour

Choice: Behaviour belongs to the object it is about. A function whose first parameter is a `Finding`, `Defect`, `Verdict`, `Manifest`, `Lens`, `Revision`, or `Changeset`, or an array of one, is a method of that class, whether it asks the object something, changes it, or transforms it: a transform from an object is `finding.toSarif()`, rendering a `Verdict` to terminal text is `verdict.render()` rather than a free function, a construction into one is `Finding.from(stored)` or `Diff.parse(text)`. The rule has no layering carve-out, but an outer package uses its own objects: a function there that adapts a core object to that package's concern becomes a method on the package's own class. github renders a finding's markdown in `ReviewComment.from(finding)`, the CLI keeps an exit code on a CLI-side object, and a stored-shape migration is a static `upgrade` on the stored shape. What stays a free function is a definition that returns data, as Pi's `defineTool` does, or a module-private helper with no domain object in sight. The list names the types as step 12 of the implementation plan leaves them: `Finding`, `Verdict`, `Lens`, `Revision`, and `Changeset` exist today and gain behaviour, and `Defect` and `Manifest` are new. Core's domain types become classes over their stored JSON, `Finding.from(stored)` and `toJSON()`, so a Pi Durable document stays JSON and the class is the runtime view, as Pi's `Transaction` is over stored entries. The guardrail `free-domain-function` holds every changed line to the rule on single-line signatures, so a function is refactored when it is touched. The Biome GritQL plugin `biome/free-domain-function.grit` catches wrapped ones, which a line-by-line pattern cannot see; it scans whole files, so it carries the grandfather list, which shrinks as each file is refactored. A conventions-lens golden follows with the refactor.

Why: The class convention this supersedes drew the line at identity, state, or lifecycle and kept transforms as free functions, which left the carve-out wide enough that `adjudication.ts` grew twenty-one free functions, thirteen of them asking a `Finding` something, and the same shape spread through `lens.ts`, `render.ts`, and `findings.ts`. A finding has an identity by construction, a verdict holds a manifest and a status, and a merged defect has a speaker: they are objects by the rule's own terms. The verifier, triage, and the ledger add behaviour to each, so they get a home first. Melian enforces the rule on itself through a guardrail today and a lint rule next, as [AGENTS.md](../../AGENTS.md) says a repeated review finding becomes a check.
