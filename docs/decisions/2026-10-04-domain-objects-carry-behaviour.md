# Domain objects carry behaviour

Choice: The class convention stands, less its carve-out for transforms. Classes for things with identity, state, or a lifecycle, named after the thing, with `close()` where something needs releasing. Plain functions and readonly data for definitions, as Pi's `defineTool` and `defineTask` are. Exported error types are classes with a `code`; a package-internal control-flow error may omit it. A class whose construction does I/O or validates input has a private constructor and a static `open`, as Pi's `SqliteStorage` does; a thin factory function is kept only where callers already use one. Methods are called on the instance, never detached, because they live on the prototype. Never a class as a namespace for static functions, and never a closure standing in for something that should be opened and closed.

To that it adds: behaviour belongs to the object it is about. A function whose first parameter is a `Finding`, `Defect`, `Verdict`, `Manifest`, `Lens`, `Revision`, or `Changeset`, or an array of one, is a method of that class, whether it asks the object something, changes it, or transforms it. A transform from an object is `finding.toSarif()`, and rendering a `Verdict` to terminal text is `verdict.render()`, not a free function. A construction into an object is a static factory, `Finding.from(stored)` or `Diff.parse(text)`. The list names the types as step 12 of the implementation plan leaves them: `Finding`, `Verdict`, `Lens`, `Revision`, and `Changeset` exist today and gain behaviour, and `Defect` and `Manifest` are new. Core's domain types become classes over their stored JSON, `Finding.from(stored)` and `toJSON()`, so a Pi Durable document stays JSON and the class is the runtime view. The rule has no layering carve-out, but an outer package uses its own objects: a function there that adapts a core object to that package's concern becomes a method on the package's own class. github renders a finding's markdown in `ReviewComment.from(finding)`, the CLI keeps an exit code on a CLI-side object, and a stored-shape migration is a static `upgrade` on the stored shape. What stays a free function is a definition that returns data or a module-private helper with no domain object in sight.

The guardrail `free-domain-function` catches the common single-line case on changed lines in every source file, so a function is refactored when it is touched. The Biome GritQL rule `biome/free-domain-function.grit` catches wrapped and other forms, which a line-by-line pattern cannot see. It scans whole files, so it carries an exclusion list of the files that break the rule today, which shrinks as each is refactored. A conventions-lens golden follows with the refactor.

Why: The class convention drew the line at identity, state, or lifecycle and kept transforms as free functions. That left the carve-out wide enough that `adjudication.ts` grew twenty-one free functions, thirteen of them asking a `Finding` something, and the same shape spread through `lens.ts`, `render.ts`, and `findings.ts`. A finding has an identity by construction, a verdict holds a manifest and a status, and a merged defect has a speaker: they are objects by the rule's own terms. This departs from Pi, whose stored records are plain data and whose behaviour lives on services. Melian differs because its domain objects accumulate behaviour across the verifier, triage, and the ledger, and a reader should find that behaviour on the object. The rest of the convention keeps its reason: a class names the object a reader holds and shows what it owns, and a closure over the same state hides both. Melian enforces the rule on itself with a guardrail and a lint rule, as [AGENTS.md](../../AGENTS.md) says a repeated review finding becomes a check.
