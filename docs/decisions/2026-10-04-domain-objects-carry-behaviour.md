# Domain objects carry behaviour

Choice: Behaviour belongs to the object it is about. A function whose first parameter is a `Finding`, `Defect`, `Verdict`, `Manifest`, `Lens`, `Revision`, or `Changeset` is a method of that class, whether it asks the object something, changes it, or transforms it: a transform from an object is `finding.toSarif()`, a construction into one is `Finding.from(stored)` or `Diff.parse(text)`. What stays a free function is a definition that returns data, as Pi's `defineTool` does, or a module-private helper with no domain object in sight. Core's domain types become classes over their stored JSON, `Finding.from(stored)` and `toJSON()`, so a Pi Durable document stays JSON and the class is the runtime view, as Pi's `Transaction` is over stored entries. The guardrail `free-domain-function` holds new code to the rule, with a grandfather list of files that shrinks as each is refactored; a Biome GritQL plugin and a conventions-lens golden follow with the refactor.

Why: The class convention this supersedes drew the line at identity, state, or lifecycle and kept transforms as free functions, which left the carve-out wide enough that `adjudication.ts` grew twenty-one free functions, thirteen of them asking a `Finding` something, and the same shape spread through `lens.ts`, `render.ts`, and `findings.ts`. A finding has an identity by construction, a verdict holds a manifest and a status, and a merged defect has a speaker: they are objects by the rule's own terms. The verifier, triage, and the ledger add behaviour to each, so they get a home first. Melian enforces the rule on itself through a guardrail today and a lint rule next, as [AGENTS.md](../../AGENTS.md) says a repeated review finding becomes a check.
