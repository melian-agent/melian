# A guard counts as tested only when a failing mutation proves it

Choice: a guard, branch, bound, or early return counts as tested only when a test fails with it inverted or removed. The author proves it by running the mutation before committing, and says so in the pull request. A fix pass that writes a test runs its mutation and records it in its report. Briefs for fix passes and implementation steps require a mutation inventory. Mutation testing becomes a static check, Stryker on Vitest, as a pinned dev dependency under the release-age rule. It runs incrementally over the changed lines of base and head, and normalises each surviving mutant to an `untested-behaviour` finding. Once it lands, a lens-raised `untested-behaviour` on code a fix pass wrote resolves to advisory, unless it guards a trust or durability contract.

Why: a test that passes with the guard gone proves nothing, and the `tests` lens can only read for that. [Pull request #68](https://github.com/melian-agent/melian/pull/68) and [pull request #85](https://github.com/melian-agent/melian/pull/85) ran seventeen and fifteen Melian rounds, each finding one or two verified test gaps. One inventory pass, with every guard proven by a failing test, found 27 unproven guards on [pull request #85](https://github.com/melian-agent/melian/pull/85) and 56 on [pull request #68](https://github.com/melian-agent/melian/pull/68). The Claude review of record found seven in one pass on [pull request #89](https://github.com/melian-agent/melian/pull/89) by running mutations. Running the mutation is cheaper than one more round. The static check moves the work from rounds to the gate, and the advisory rule stops a fix pass's own tests from restarting the loop.

The advisory rule waits for the static check. Until then every `untested-behaviour` finding keeps its severity.
