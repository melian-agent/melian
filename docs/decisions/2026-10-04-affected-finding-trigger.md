# Affected finding trigger

Choice: An `affected` finding's dismissal reopens only when the code that proved its cause changed, never because the lens cited more or fewer locations. Its trigger names the first hunk a proving `cause` location falls on, by file then hunk index, with that hunk's added lines, cut for storage, as its snippet, and carries a `proof`: every proving hunk as a `{ file, hash }` pair, the hash being `snippetHash` of the hunk's added and removed lines, each keeping its `+` or `-`. The findings document keeps, on the finding's lifecycle record, the union of the proofs every sighting has given since the finding last reopened, so a new citation joins the set without resetting it. A dismissed finding sighted again as anything but `introduced` reopens only when a hunk in that set has no hunk of equal content in the same file at the new revision; `report_finding` passes the revision's hunks into the upsert, so the check reads the diff, not the model's citations. A hunk that changed leaves the set. A trigger stored with a single `hash` reads as a one-hunk proof. An `introduced` finding's trigger and its rule are unchanged: the hunk it sits in, hashed by its added lines, reopening when that hash changes.

Why: A trigger hashed from the hunks the lens cited depended on which locations it chose to cite. Example: a change edits `src/price.ts` in two hunks; the lens reports a broken caller in `src/cart.ts` citing the first, and the maintainer dismisses it; the next push touches only another file, the lens cites both hunks, and the hash changes, so the dismissal is dropped though `src/price.ts` did not change. Sorting the cited hunks fixed only their order. Keying the proof to the hunks themselves, and checking it against the diff, ties the dismissal to the code that caused the finding. The union matters: a lens that cites one hunk on one run and the other on the next must not let a change to the first slip by while it cites only the second. Removed lines count because a cause can be a deletion, which adds nothing. The hash names no index, so a hunk that moves within its file still proves the cause.
