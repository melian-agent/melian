# dist exists only to publish

Choice: Nothing in development reads `dist/`. In a checkout, `packages/cli/bin/melian.js` runs `src/bin.ts` with Node's type stripping and a synchronous resolve hook that adds the `@melian-agent/source` condition; in the published tarball, which ships no `src/`, it imports `dist/bin.js`. Each package builds `dist/` in `prepack` and deletes it in `postpack`, so it exists only while `npm pack` or `npm publish` runs. CI still runs `npm run build`, as a publish check. tsc's build-info files live in `.tsbuild/` at the root rather than beside each package's sources.

Why: Tests and type checks already ran from source through the export condition, but the CLI and any plain `node` child resolved workspace imports to `dist/`. A `dist/` left from an earlier build ran stale code without a word. Example: fix a lens tool and watch its unit tests pass, then run `melian review` in the same checkout. The shim imported a `dist/` built before the fix, so the review ran the old tool. Every self-review of a Melian pull request needed `npm run build` first, and forgetting it reviewed the change with the code it replaced. Node 22.19, Melian's floor, strips types by default, source imports already name `.ts` files, and Melian allows only erasable syntax, so Node runs the source as it stands. A build kept only for publishing removes the stale copy rather than documenting it. The hook is `module.registerHooks`, not `module.register` or a re-executed Node: hooks on a worker let Node 22's SQLite warning print before `src/warnings.ts` drops it, and a second process would change the `process.argv[1]` that `melian doctor` reports.
