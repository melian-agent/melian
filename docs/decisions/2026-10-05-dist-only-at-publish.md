# dist exists only to publish

Choice: Nothing in development reads `dist/`. In a checkout, `packages/cli/bin/melian.js` runs `src/bin.ts` with Node's type stripping and a synchronous resolve hook that adds the `@melian-agent/source` condition; in the published tarball, which ships no `src/`, it imports `dist/bin.js`. Each package still builds `dist/` in `prepack`, so a plain `npm pack` in one package works. Its `postpack` runs that package's own `clean`, never the root's. A pack beside a build or another pack therefore cannot delete their output. `clean` deletes the build-info file with `dist/`; deleting `dist/` alone left `tsc -b` finding the package up to date, and the next tarball shipped without `dist/`. `prepack` also builds the packages a package references, and their `dist/` stays behind. That is harmless now, since nothing in development reads it. npm skips `prepack` under `ignore-scripts`, so a package packed that way ships with no `dist/` unless the root `npm run pack` built it first. A release packs with `npm run pack -- <dir>`, which builds every package and then packs each with lifecycle scripts off. CI runs it on every Node version in its matrix and checks that the cli tarball holds `bin/melian.js` and `dist/bin.js` and no `src/`. It then installs the cli, core, pipeline, and github tarballs into an empty project and runs the installed `melian --help`. No test reaches the shim's tarball branch, so this step is the only thing that does. tsc's build-info files live in `.tsbuild/` at the root rather than beside each package's sources.

Why: Tests and type checks already ran from source through the export condition, but the CLI and any plain `node` child resolved workspace imports to `dist/`. A `dist/` left from an earlier build ran stale code without a word. Example: fix a lens tool and watch its unit tests pass, then run `melian review` in the same checkout. The shim imported a `dist/` built before the fix, so the review ran the old tool. Every self-review of a Melian pull request needed `npm run build` first, and forgetting it reviewed the change with the code it replaced. Node 22.19, Melian's floor, strips types by default, source imports already name `.ts` files, and Melian allows only erasable syntax, so Node runs the source as it stands. A build kept only for publishing removes the stale copy rather than documenting it. The cost: a clone linked onto `PATH` now runs whatever its working tree holds, not a build frozen at the last `npm run build`, so a maintainer links a clone kept on `main`. The hook is `module.registerHooks`, not `module.register` or a re-executed Node: hooks on a worker let Node 22's SQLite warning print before `src/warnings.ts` drops it, and a second process would change the `process.argv[1]` that `melian doctor` reports. Node also deprecates `module.register` as DEP0205, in the documentation from 24.15 and at runtime from 26. The shim imports the CLI dynamically, the one exception to the rule against `await import()`, because the hook must be registered before the graph loads.
