# Lens budgets

Choice: A level's `budget.tokens` caps the input and output tokens of its lens conversation's model responses, cache writes counted as input and cache reads left out, and `budget.tools` caps its tool calls, `report_finding` included. A read past `budget.tools` is refused with a note, a report never is, and a lens may correct one finding three times. The round that crosses the budget goes on, so the lens can report what its last reads showed. The next round that holds a read, or a round that starts with `budget.tokens` spent, ends the conversation: every call in that round hands off, which makes Pi Durable end the run whatever the round's other calls returned, and the conversation stops with the findings reported. A call that throws, or that the lens's policy refuses, still ends the run. The lens's check record is `ended` and names the budget that ended it, its limit, and the tokens and calls used, and an `ended` check makes the verdict not reviewed. A level may set `budget.ended: count`; its lens then records `ran`, with that ending, and its findings so far count. The built-in levels do not set it. Tokens come from Pi's per-conversation usage record and calls are recorded by the tool task Pi mints for each, in the lens's own document, so a replay after a crash counts nothing twice and a provider that reuses a call ID across rounds counts each call.

Why: A lens its budget ended reviewed less than its level promised, and a required status must never turn green from reduced coverage. A large or adversarial change could otherwise exhaust a lens before it reached the defect, and the review would pass. A repository that accepts the cost of a cut-short lens says so per level. Cache reads re-read context a provider already counted, and counting them would charge a long conversation for every earlier turn again. `report_finding` reads the code at every location it cites and quotes it back, so a lens that could call it without limit could read the repository through it; counting each call, and capping corrections, bounds that, while never refusing a report keeps reading from starving reporting. Pi Durable's hooks can read documents but not write them, so the counters live where a tool's commit can keep them durably.
