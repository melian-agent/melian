# Lens budgets

Choice: A level's `budget.tokens` caps the input and output tokens of its lens conversation's model responses, cache writes counted as input and cache reads left out, and `budget.tools` caps its calls to the read-only tools; `report_finding` counts only against `budget.findings`. A call past `budget.tools` is refused. Once a round of tool calls spends either budget, every call in that round asks Pi Durable to end the run, so the conversation stops after the round with the findings it reported. The lens's check record is `ran` and names the budget that ended it, its limit, and the tokens and calls used. Tokens come from Pi's per-conversation usage record and calls are recorded by call ID in the lens's own document, so a replay after a crash counts nothing twice.

Why: A budget bounds what a level spends, so running out is the level working as declared, not a failure that should make the verdict not reviewed. Cache reads re-read context a provider already counted, and counting them would charge a long conversation for every earlier turn again. Counting `report_finding` would let reading starve reporting, when the findings budget already bounds it. Pi Durable's hooks can read documents but not write them, so the counters live where a tool's commit can keep them durably.
