# Dismissal

Choice: `melian dismiss <range|#pr> <id> --reason <text>` records the dismissal on the finding's lifecycle record in the changeset's local storage, with the git author as the dismisser, `git var GIT_AUTHOR_IDENT` without its timestamp, and the time. The reason is required, trimmed, and at most 1,000 characters. The same commit starts an adjudication over the review's own input, so the stored verdict counts the finding out at once and a later review of the revision attaches to that adjudication. Dismissing a dismissed finding replaces its reason and keeps the old dismissal in its history, as a reopened one does; the same dismisser giving the same reason again changes nothing. A finding adjudication merged from several checks' reports is dismissed whole, every report merged into it with it, and visibly: `review` and `findings` print each finding's merged reports with their severity, rule, check, and ID, `dismiss` names every report it dismissed with the finding by rule, check, and ID, and `--only` dismisses the report its ID names alone, leaving the other reports live. An ID names the finding with that exact ID first, and a dismissed report a live finding lists beside it never leads to that finding. A finding carries its dismissal and past dismissals, so `melian findings --all` and the JSON show who, when, and why. The terminal rendering ends each finding's first line with its ID.

Why: The git author is the identity the clone already has. A range has no GitHub at all, and `dismiss` reads only local refs and storage, as `findings` does, so it works offline. The record sits in local SQLite that trusts whoever can write it, so a GitHub login proved by a token would cost a network call and add no trust until the state branch, in milestone 3, binds records to a pushing identity; dismissal from a pull-request thread, in milestone 4, records the commenter GitHub authenticates. Deciding the verdict in the dismissal's commit keeps the rule that only adjudication writes resolution, and without it `findings` and `publish` would read a verdict that still counted the finding until someone reviewed again. A reason reaches a pull request thread, so it is bounded, and an old reason is evidence for calibration, so a second dismissal never erases it. Adjudication never merges a dismissed report with a live one, so dismissing only the report that spoke for a defect would raise another check's report of the same defect in its place. The merge is by site, file, normalised snippet, and overlapping lines, not by meaning, so it can join two defects on one expression; the maintainer therefore sees every report before dismissing, sees again what went with the finding, and keeps one live with `--only`. Nothing is silenced unseen.
