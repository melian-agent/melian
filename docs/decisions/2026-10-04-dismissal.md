# Dismissal

Choice: `melian dismiss <range|#pr> <id> --reason <text>` records the dismissal on the finding's lifecycle record in the changeset's local storage, with the git author as the dismisser, `git var GIT_AUTHOR_IDENT` without its timestamp, and the time. The reason is required, trimmed, and at most 1,000 characters. The same commit starts an adjudication over the review's own input, so the stored verdict counts the finding out at once and a later review of the revision attaches to that adjudication. Dismissing a dismissed finding replaces its reason and keeps the old dismissal in its history, as a reopened one does. A finding carries its dismissal and past dismissals, so `melian findings --all` and the JSON show who, when, and why. The terminal rendering ends each finding's first line with its ID.

Why: The git author is the identity the clone already has. A range has no GitHub at all, and `dismiss` reads only local refs and storage, as `findings` does, so it works offline. The record sits in local SQLite that trusts whoever can write it, so a GitHub login proved by a token would cost a network call and add no trust until the state branch, in milestone 3, binds records to a pushing identity; dismissal from a pull-request thread, in milestone 4, records the commenter GitHub authenticates. Deciding the verdict in the dismissal's commit keeps the rule that only adjudication writes resolution, and without it `findings` and `publish` would read a verdict that still counted the finding until someone reviewed again. A reason reaches a pull request thread, so it is bounded, and an old reason is evidence for calibration, so a second dismissal never erases it.
