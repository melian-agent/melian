# Standards trust requires matching commit provenance

Date: 2026-10-06
Supersedes: 2026-10-06-worktree-standards-boundary.md

A host could pass head standards under base policy, or flat text under revision policy. Source kind alone promoted that contributor text into trusted instructions.

Standards retain the resolved commit of their reading. The pipeline validates the policy source and trusts standards only when both commits match. Equivalent ref names resolve to the same commit. Flat arrays have no provenance, so they render inside untrusted boundaries. Worktree and mismatched revision standards use those boundaries too. Per-section boundaries and the injection-attempt lead-in remain.
