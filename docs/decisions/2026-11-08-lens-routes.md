# A lens names its own model route

Status: accepted on 2026-11-08 by the maintainer, in the builder's session for plan step 37 ([issue #243](https://github.com/melian-agent/melian/issues/243)). An attacking review on 2026-11-08 found ten breaks in the rule's first form, and this form closes each.

Amends: [2026-10-24-design-lens-on-codex-route.md](2026-10-24-design-lens-on-codex-route.md), whose option C this is.

## Problem

A lens level names a tier, and a tier's route serves every lens on it. One lens cannot get a model of its own without taking a tier from the others. Example: to run the design lens on Codex's model and effort, Melian's own repository routed `medium` to `gpt-5.6-sol` at `high` and moved seven lenses' `quick` levels to `light`, through extension files under `.melian/lenses/` that exist only to move tiers. A team that wants a second lens on its own model has no tier left to free.

## The rule

1. **Shape.** `lenses.<name>.route` takes the same keys as `models.<tier>`: `model`, `thinking`, `fallbacks`, `accept`, `unavailable` and `acceptOverridden`. Only the root `melian.yaml` sets the last three. A preference file may set `model`, `thinking` and `fallbacks`. A nested `melian.yaml` that sets any key of a lens route is a config error naming the file: the plan reads only the root's load, so a nested route would reach no review. The checks on `models.<tier>` apply unchanged: fallbacks need a model, an `accept` is not empty, and `acceptOverridden: false` needs a model or an `accept`. A lens route exists only when the merged route names a `model` or an `accept`. A route that sets only `thinking` or `fallbacks` is a config error naming the file.
2. **Precedence.** A lens with an effective route runs every level on it, in place of the level's tier. The route sets the model and the thinking for every level, so escalation from `quick` stays on the route. A `lenses.<name>.tier` on a routed lens is ignored, in the plan and in `Lens.configured`, so it neither moves a level nor changes the lens's `version`. `melian doctor` says it is ignored, naming the file. The tier a level declares still stands for a review whose configuration routes no such lens.
3. **Policy.** The committed route, from the root `melian.yaml` alone, judges the lens: its `accept`, `unavailable` and `acceptOverridden`, as a tier's do. A committed lens route inherits `acceptOverridden: false` and `unavailable: fail` from every committed tier its levels declare that sets them, unless the route states its own. So a route never quietly lifts a guard a maintainer put on the tier. A preference file that changes a committed route's model, fallbacks or thinking is recorded as `by` that file, and the route's own guard applies to it as a tier's does. A preference file that gives a route to a lens whose committed files route none moves the lens, as a preference `tier` does today. Each level is then judged under its committed tier's policy, as a moved lens is today. It is refused when that tier sets `acceptOverridden: false` and either the route's thinking differs from the tier's committed thinking, or the route's first model is outside the tier's `accept`. Fallbacks outside that `accept` are dropped, and a run that finishes on one is marked `failed`. `melian doctor` names each level a route is refused at, so a route refused at one level only is visible.
4. **`--model`.** It replaces every lens route, as it replaces every lens tier, and the lineage records `by: --model`. A lens route whose guard is `acceptOverridden: false`, its own or inherited, refuses it unless its `accept` lists that model.
5. **The plan.** `StoredPlan` gains `lensRoutes`, one resolved route per routed lens, keyed by the lens's name and scope. Each is resolved by the code that resolves a tier, with the same statuses. `PlannedLevel` gains `route: true` on a routed lens's levels. `routes()` stays tiers-only, for triage, the walkthrough and the summariser. A new `plan.lensRoute(name, scope)` returns a routed lens's resolved route. Every site that today takes a level's route from its tier asks it first: the lens run's models and thinking, `routeOf`, an escalation's next route, triage's `routed` predicate for `runnableLevels`, the `noAvailableModel` gate, and `used()` for warnings and `lines()`. So a routed lens whose own tier is unrouted still runs and draws no tier warning. `providers()`, `judge()` and `mark()` read lens routes too. A lens route is never a verifier's route. `verifierRoute` and every family check read finder families from `lensRoutes` as well as from tiers.
6. **Stored shape.** The plan is stored in a verdict's provenance, in each round of `melian.rounds`, and in `melian.adjudication`'s input. All three take their next version, so an older Melian refuses a record whose plan it would misread, and each gets a reopen test from a fixture its current version's code recorded. A plan stored before the step has no `lensRoutes` and reads as it did. `LensTask`'s input already carries each run's resolved models and thinking, so its shape does not change.
7. **Lineage.** `CheckLineage.moved` names a lens route as `lens route`, as in `moved: { by, from: "heavy", to: "lens route" }`. A run on its committed lens route records no lineage. A run on a fallback outside that route's `accept` does, as for a tier.
8. **Identity.** A route is not part of a lens's `version`, as a tier's route is not today. The review index already keys each run by the models it resolved and its thinking, so a changed route runs the lens again. Findings keep their IDs and dismissals, since no lens version or model enters a finding's ID.
9. **`melian doctor`.** It prints a `route` line for each routed lens beside the tier lines, and a level as `careful on lens route (openai-codex/gpt-5.6-sol)`. The inversion check compares only budgets between levels that share a route.
10. **Melian's own policy.** The root `melian.yaml` gives `design` its route: `openai-codex/gpt-5.6-sol` at `thinking: high`, falling back to `anthropic/claude-opus-5-5`, accepting both. `models.medium` returns to Terra at `low` with the light route's fallbacks and `accept`, so every `quick` level keeps the model and effort it runs today. The `quick: { tier: light }` lines leave `contracts`, `conventions`, `correctness`, `removed-behaviour`, `tests` and `trust-boundary`. `durability`'s `quick` returns to `medium`. `design` drops `tier: medium` and keeps its tools, budget and body. The extension files stay where they still hold budgets.

## The maintainer's rulings, 2026-11-08

- The rule is accepted as written.
- A committed lens route inherits a guarded tier's `acceptOverridden: false` and `unavailable: fail` unless it states its own, rather than the combination being a configuration error.
- The eight lens versions rule 10 changes are accepted, with the rerun cost the consequences below describe.

## Why

A route on the lens is the smallest unit that answers the problem: it moves one lens and nothing else. A sixth tier would solve one lens and touch every tier order, as the earlier decision says. A route per level would let one lens split across models, which no one has asked for, and would put a model choice into every level's identity.

Reusing the tier's resolution code keeps one rule for derive, fail and refusal. Ignoring a tier on a routed lens, rather than refusing the configuration, lets a preference file that retiers every lens keep working beside a committed route.

## Consequences

- Behaviour stays the same for Melian's own rounds: `design` keeps Sol 5.6 at high, and each `quick` level keeps Terra at low.
- Rule 10 changes eight lenses' versions, since their files change: the six that lose a `quick` line, `durability` and `design`. No stored verdict changes, and its findings and dismissals stand. The next review of a head Melian already reviewed finds no stored run of those eight lenses under their new versions, so it runs them again once. A new head runs every lens anyway. Measurements kept by lens version start a new series for the eight.
- Triage changes at one edge. A contributor with no credentials for the light route's models today falls through to `medium`, Sol 5.6 or Opus. After the rule, `medium` repeats light's models, so triage falls through to `heavy`.
- A verdict, round or adjudication written by this Melian cannot be read by an older one. This is the usual cost of a version bump.
- A preference route on an unrouted lens is judged by its committed tier, so `acceptOverridden: false` on that tier still holds.
