# Tool provisioning

Choice: A `tools.yaml` manifest in Melian pins each external tool's version and per-platform URL and sha256, under the same release-age quarantine as npm, and a bump is a reviewed pull request; one manifest builds a local cache verified by hash for trusted runs and a container with no network, a read-only worktree, and resource limits for untrusted heads; a tool whose configuration loads repository code comes from the checkout's lockfile install or else Melian's own copy, a standalone analyser from the manifest, and either executes inside the environment; never a host-installed analyser; Opengrep, the LGPL 2.1 fork of the Semgrep engine, not Semgrep's registry rules, with no rules shipped at first, and gitleaks as the fast tier's secrets check

Why: Version drift changes rules and so breaks finding identity, and a binary on the host is outside the trust boundary; since 13 December 2024 Semgrep's registry rules are under the Semgrep Rules License v1.0 (https://semgrep.dev/legal/rules-license, and the LICENSE of https://github.com/semgrep/semgrep-rules), which allows only internal business use and forbids distributing the rules or offering them as a service, while the engine stays LGPL 2.1 (https://semgrep.dev/blog/2024/important-updates-to-semgrep-oss/); Opengrep's fork of the rules (https://github.com/opengrep/opengrep-rules) keeps their earlier licence, LGPL 2.1 with the Commons Clause, which forbids selling them
