# A lens with no paths is an allowed skip

Choice: A lens of the manifest whose paths match no changed file, counting a renamed file under its old path and its new one, records `skipped` with the reason `no paths`, and the skip is allowed, whether or not another lens ran, as a `decisions.*` check's is while no provider is configured. A review of a change that touches only paths every lens excludes therefore passes on its deterministic checks. The terminal and JSON output list each such lens with its reason.

Why: Melian's own `melian.yaml` keeps every lens off `packages/evals/goldens/**`, so seeded defects are never reviewed as Melian's code. A pull request that changes only goldens then selected no lens, and the old rule recorded each lens as `no lens covers these paths`, a skip `allowSkip` did not excuse, so the review read not reviewed for a change no lens was meant to see. An exclusion in `paths` is the repository saying a lens has nothing to review there; that differs from `enabled: false`, which switches a lens off everywhere and stays a skip the repository must allow. The guardrails and static checks still run, and the skip stays visible with its reason. A renamed file counts under both paths because the skip passes: selected on new paths alone, a pull request that only moved `.npmrc` or a source module into the goldens ran no lens and passed, so the head's author would choose by file name whether any lens read the change. Such a lens also covers the moved file's head path for that review: its configured paths still exclude the destination, so `report_finding` refused a defect there, and the old path no longer exists at head, so the lens ran, saw the move, and could report nothing in it.
