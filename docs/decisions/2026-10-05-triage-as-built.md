# Triage as built

Choice: A lens's key is `name@version@level`, and its findings' `source.version` is `<version>@<level>`, so the review index's selection, the lens task's children, attempts, and results, each request ID, and each producer of sightings tell levels apart; a record an older Melian stored keeps its keys and stays readable, and no review after the upgrade attaches to it. A lens task an older Melian left running resumes with its runs' levels stripped, so its findings keep the bare version. Triage is a `melian.decision` task per revision and question set, attached to by a repeat review and asked again after a failure only with `rerun`, so the levels a first review chose are the levels a crash or a second review keeps. A decider that fails, times out, or answers what it was not asked leaves every lens at its default level within its band, never `skip`, and each lens's record says so. The band is read from the policy source for every file a lens reviews, and a policy that cannot be read fails the review before any lens runs. Escalation runs inside the lens task, in a new conversation created in the commit that records why. The run it escalated to stands for the lens: its record, with a note naming the trigger, and its findings. That run is given the quick run's findings at or above `escalateAt` to confirm or refute. A finding it restates counts once, from it. One it refutes is dropped. One it does neither still counts, attributed to the quick run, until step 6's verifier judges it. A pull-request review's default floor is `careful` until a calibrated decision model answers, and a range review keeps `quick`. A review in which every lens stayed at `quick` says so on each record. Without a review plan, the CLI's LLM fallback runs on the cheapest lens tier routed to a credentialed model. The review records every `decisions.*` check itself; with `decisions.provider` set, the record is a skip the review does not allow, and the CLI refuses the provider before anything runs, until milestone 4 brings an adapter.

Why: A key without the level let a careful review attach to a quick one, and an escalated rerun overwrite the quick run's sightings or be deduplicated as the same request. A decision asked afresh on every call would change the selection and rerun every lens after a crash. Failing closed to `skip` would turn a provider outage into lost coverage. A band read from unreadable policy could not be trusted, and guessing the default would let a lens run below a floor policy set. Reading the escalated run's findings alone let a quick blocker vanish when the higher run merely left it out, so escalation could turn a blocking review into a pass; an explicit refutation is the only way out. The head of a pull request writes the change triage reads, so an uncalibrated model it can steer must not send every lens to a quick look. A configured provider with no adapter left `decisions.fast` with no record ([issue #24](https://github.com/melian-agent/melian/issues/24)); refusing it says what to do, and the recorded skip keeps a library caller from reading "no record".
