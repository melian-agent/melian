# Melian's first read of a miss is computed when a comparison is read, never stored

Choice: the cause of each valid miss, one of `not covered`, `cut short`, `never shown`, `seen, not reported`, `reported, refuted`, `reported, not matched` and `no record`, is computed from the round's own telemetry, diff and verdict each time `melian compare export` or `melian compare stats` reads the comparison. It is labelled Melian's first read, and the export says it is as of that export. No stored shape changes, and matching is untouched.

Why: a stored cause would freeze the rule that made it. Example: a miss read `never shown` under today's rule could read `seen, not reported` once `read_file` records finer ranges; a stored label would keep the old answer and need a migration to change it. Reading on demand keeps one rule, `MissLines` in the pipeline, which the evidence store and the evals' `Miss.unscoped` share, and lets every record re-export under a fixed rule. The cost is a git diff per round with a valid miss on each export or stats call, and a clone that lacks the round's commits or telemetry reads `no record`. `ComparisonCauses` holds the computation apart from the comparison reader, so the adjudication never reaches the telemetry. The core modules the adjudication does reach changed, so their code hashes were recorded again, and each stored head's adjudication decides again once, with no model call.

The coordinator chose computing on read on 2026-11-21, for [issue #559](https://github.com/melian-agent/melian/issues/559), item 2. That is a coordinator's choice of approach, not a maintainer's ruling.
