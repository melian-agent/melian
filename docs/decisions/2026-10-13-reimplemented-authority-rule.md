# The re-implemented authority rule and its boundary

Choice: the `design` lens rule `reimplements-an-authority` reports hand-written code that parses a format, or re-derives an answer, that a dependency of the base already parses or answers. An authority is a package the base's manifest declares or a tool the base's code already runs. A dependency the reviewer knows of and the repository does not use is not one. A finding names the authority and the base line that declares or uses it, the hand-written lines, and one input the hand-written code reads wrong that the authority reads right.

Three cases are not findings. The base has no such dependency. The change calls the authority. Or the authority cannot run where the answer is needed and the change states the gap, as [ask the authority](2026-10-12-ask-the-authority.md) allows. The lens keeps the exemption only when code it reads supports the stated reason. A gap with no reason, a reason the code shows false, or a reason nothing in the repository supports leaves the finding standing. Under a gap that holds, the hand-written code stays `design`'s: it reports an input the code answers wrong, or guesses at, where it should refuse or take the safe wide answer.

`design` owns the defect against `correctness`, which carries a `design` hand-off for it and so leaves it only when `design` reviews the same files. `correctness` keeps a wrong result only where the repository has no such dependency. It leaves one under a stated gap to `design` too, since a rule that split the gap between two lenses would have both report a guessing fallback. `conventions` owns it where a standard says in words to use the dependency: `design` hands that case over, stated gap or not, and `conventions` is unchanged. A written standard allows no exception the standard does not state, so a gap that satisfies `design` does not answer it.

Why: the rule has no decision file to judge against, unlike the lens's other nine, so its baseline had to be named: the base's own dependencies. A baseline of every library the model knows would flag any parser, in any repository. Requiring one misread input keeps the finding grounded, as the lens's other rules require a failure scenario. The lens traces the hand-written code's reading through the code. What the authority returns is the one step it may take from what the model knows, labelled as inferred, because a dependency's source is not in the repository and the lens has no tool that runs code. The author of a change does not write the excuse for it, so a comment that states a gap is a claim to check, not an exemption.

The boundary is stated on both sides because [the lens backlog boundaries](2026-10-04-lens-backlog-boundaries.md) measured what happens otherwise: two lenses report one defect under two rules. Example: a header parsed by splitting each line at a colon returns a quoted title with its quotation marks. That is a wrong result, which `correctness` claims, and a re-implementation, which `design` claims. Each round of [pull request #102](https://github.com/melian-agent/melian/pull/102) reported one such wrong result, and none named the cause. `design` reports the hand-written code once and lists the inputs.

What this gives up: the hand-off changes the version of `correctness`, so a stored review by it reads as an older lens. Where a standard names the dependency, the finding is a `conventions` breach at P2 or P3, with no list of the inputs the hand-written code reads wrong. The `design` lens sits outside the default `full` tier, and where it does not run the hand-off does not render, so `correctness` keeps what it had.

One defect can go unreported. `correctness` hands the whole class to `design` where `design` runs, and `design` drops a finding when it is not sure what the authority returns. Example: a hand-written parser beside its dependency gets a rarely used feature of the format wrong. `design` cannot be sure how the dependency reads that feature, so it drops the finding, and `correctness` has already left the parser to it. Neither reports the bug. The trade is accepted: a hand-off cannot say "report it yourself if the owner drops it", since no lens sees another's findings.
