# Dismissal publication

Choice: A finding posted on a pull request and then dismissed is resolved with its dismissal: publication replies in its thread `Dismissed at <head>:` with the reason, or, when it was posted in a review's body, names it with the reason under "Dismissed since the last review" in the next body. It then leaves the set of findings open on the pull request, so a changed trigger that reopens it posts it in a new thread. The reply never names the dismisser. A finding dismissed before it was posted is never posted. The status counts every dismissed finding out. This replaces milestone 1's rule in `planPublication`, recorded in no decision file, that a dismissed finding was neither posted nor resolved and kept its place in the open set.

Why: The thread is where the author and reviewers asked about the finding, and a finding that stopped counting with no word there reads as Melian dropping it. A reopened finding is a new question about changed code, so it earns a thread of its own rather than a reply under an answer that no longer holds. The dismisser Melian records is a git identity whose email does not belong on a pull request, and GitHub already shows whose token posted the reply.
