# Dismissal publication

Choice: A finding posted on a pull request and then dismissed is resolved with its dismissal: publication replies in its thread `Dismissed at <head>:` with the reason, or, when it was posted in a review's body, names it with the reason under "Dismissed since the last review" in the next body. It then leaves the set of findings open on the pull request, so a changed trigger that reopens it posts it in a new thread. The reply never names the dismisser. Each reply is keyed by the finding, its thread, and, for a dismissal, the dismissal's version, a hash of its reason, dismisser, and time, so dismissing the finding again with another reason posts a reply of its own in the thread. Who dismissed a finding, why, and when stay out of the verdict's fingerprint, so a changed reason posts no review: a round can be its replies alone, with the status unchanged. A finding posted in a review's body has no thread, so a changed reason for it is not posted. When adjudication merges reports that were dismissed apart, each keeps its own dismissal on its `alsoReportedAs` entry, and its thread is answered with that one; only a merged report without a dismissal of its own takes the finding's. A finding dismissed before it was posted is never posted. The status counts every dismissed finding out. This replaces milestone 1's rule in `planPublication`, recorded in no decision file, that a dismissed finding was neither posted nor resolved and kept its place in the open set.

Why: The thread is where the author and reviewers asked about the finding, and a finding that stopped counting with no word there reads as Melian dropping it. A reopened finding is a new question about changed code, so it earns a thread of its own rather than a reply under an answer that no longer holds. The dismisser Melian records is a git identity whose email does not belong on a pull request, and GitHub already shows whose token posted the reply. The thread is the pull request's record of why a finding stopped counting, so a reason that changed only in local storage would leave it saying something no longer true; a review whose only news is that reason would repeat the last one. A merged report's thread heard its own reason; answering it with the reason another report was dismissed for would tell it something nobody said about it.
