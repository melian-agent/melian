# Spans time a review's work between tasks

Amends: [reasoning capture](2026-10-18-reasoning-telemetry.md), which restates the stage timing contract, for the orchestrator's own work between durable tasks.

Choice: the host opens a `PrepareSpans` recorder at its process's start, from `performance.timeOrigin`, and the review's steps between tasks join it. Each span is `{ name, startedAt, endedAt, durationMs, parent? }`. One step is open at a time. `step(name)` ends the open step and opens the next. `end()` closes it before a wait that a task's own timing covers. `time(name, work)` times nested work, such as unlocking credentials or the Enola graph and query, with the open step as its parent. Before the verdict prints, the host stores the record as one `melian.prepare` document-family member, version 1, in the root conversation, keyed by revision. The next review of the revision replaces it. `melian telemetry` and review JSON show the record beside the stages, list the spans in time order, and name every stretch over a second that neither a span nor a stage covers. Each model stage also carries `modelMs`, the summed response time of its answers, read from the transcript; the rest of its duration is tools and orchestration. An answer without a duration leaves `modelMs` absent, not short. Publication runs in another command, so its stage never covers a review's untimed time, and a record with no stage still prints.

Why: telemetry recorded only durable tasks. On [pull request #186](https://github.com/melian-agent/melian/pull/186)'s final round, 14.5 seconds between the checks and triage and 5.6 seconds between triage and the lenses left no record, and nothing before the first check was measured. Spans are not tasks: the work they time runs again on every call and nothing resumes it, so a task would add scheduling with nothing to replay. A document family member keyed by revision fits Pi Durable's convention for task-free durable values: it lives in a commit, survives the process, and reads through the detached storage API that `TelemetryReader` already uses. Storage grows with revisions, not calls, since each review replaces its revision's record. The record is new, so no existing document version changes. Stage telemetry's rule that no shared root timing document is stored was about stage timing; this record holds only the host's spans and never enters an input, an attach key, a verdict or a fingerprint.

A scripted review on the fake model proves coverage: its spans and stages leave no gap over a second from process start to the verdict, and no span overlaps a task. A gap the next change opens shows in `melian telemetry` as `untimed`.

Deferred: spans inside `static.enola`'s own task (provisioning, graph build, query) need a record in the check task's terminal commit. The caller query the review runs outside any task is timed now.
