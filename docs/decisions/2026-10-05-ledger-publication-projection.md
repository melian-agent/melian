# Ledger publication projection

Choice: The walkthrough settings live under `publish.walkthrough`, as the step 8 brief names them. The stamp names the plan by a fingerprint of the recorded manifest, routes, levels, budgets and standards paths. The visible run details render those values. The stamp also fingerprints the rendered projection, so a changed reason, walkthrough switch or history edits the same comment.

Why: The brief uses `publish`, where the earlier decision used `publication`. Keeping both names would give one setting two sources. A plan copied whole into the hidden stamp could consume GitHub’s body limit before any visible section. Its fingerprint names the plan without taking that space.

The rest of the ledger decision stands. The summarise task was absent from the checkout, so this step adds it in the review harness. Publishing reads its stored output and holds the provider credentials alone. A small sequence-diagram syntax allowlist keeps diagram text from becoming links or executable directives.

The agent prompt uses one fence containing every open finding. Its opening untrusted-data rule applies to all findings, and an agent can copy the whole block. Timings remain deferred because the existing run record does not store them; successful lens usage supplies models, tokens and cost. Full plan lineage depends on the review-plan change landing on main.
