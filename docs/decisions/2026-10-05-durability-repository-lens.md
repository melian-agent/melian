# The durability lens is a repository lens

Choice: `durability` lives in Melian's own repository, at `.melian/lenses/durability/LENS.md`, not under `packages/core/lenses/`. It reviews `packages/pipeline/src/**`, `packages/github/src/**`, and `packages/cli/src/**`, where the CLI opens each harness and so decides which tasks a resume restarts, and Melian's root `melian.yaml` names it in the `full` tier beside the built-in lenses. Its goldens build their own repositories, so each carries a copy of the lens under the inert name `.melian/lenses/durability/LENS.golden.md`, and a test fails when a copy differs from the original.

Why: its rules are the contracts of Pi Durable, the runtime Melian's pipeline is written on: a tool's commit and its result land separately, `beforeTool` runs only in the call phase, memos end with their task, a `requestId` holds within one conversation, documents are strict JSON copied in on assignment, and Pi migrates a live task but never a finished task's result. A repository that does not run on Pi Durable has none of these contracts, so a built-in lens would spend every user's tokens on them and report findings no one could act on. A repository lens is read from the revision the host chooses, as policy is, so a pull request cannot rewrite the lens that reviews it, and Melian dogfoods the repository-lens path a user would take for their own runtime's rules. The built-in default tiers name only lenses that ship, so the lens joins the `full` tier through Melian's own `melian.yaml`. The goldens carry a copy because a golden's repository is built from its own trees, where Melian's `.melian/` is not, and the copy uses an inert name because a `LENS.md` inside the corpus would be a live lens for the folder holding it when Melian reviews itself.

The hand-off is one-sided, against the rule of [the boundaries decision](2026-10-04-lens-backlog-boundaries.md) that a boundary is stated on both sides. `durability` hands a defect that needs no crash, replay, resumed task, or stored record to `correctness`, but neither `correctness` nor `removed-behaviour` hands anything to `durability`, so both restate its defects under their own rules. [The seventh live run](../../packages/evals/runs/2026-10-05-live-goldens-7.md) measured the cost: `durability` found every seeded defect with no extra of its own, and its goldens still fell to a worst precision of 0.44 against the bar of 0.8, every extra another lens's. A hand-off from the other side would not render today. A hand-off renders only when the neighbour reviews every file the handing lens reviews, and `correctness` reviews every file a Melian pull request changes, documents included, while `durability` reviews three source folders. The remedy is a hand-off that names the files the neighbour covers and holds for those files alone; [the plan](../design-implementation-plan.md) schedules it in milestone 2 after step 12, which moves lenses onto objects.
