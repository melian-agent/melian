# Actions complete the manifest

Choice: Recorded now for milestone 3. The Actions host relies on local review records. `melian publish` pushes the changeset's storage, with its sightings, verdicts, and check records and their lineage, to the state branch; the Actions host opens it, runs only the checks the tier names that lack a record for the run identity, and publishes. A local record counts only when the push came from an identity with write permission on the repository and the record's lens version, tool versions, and policy hash match the run identity; the model is lineage, shown in the ledger, not identity. Every record carries lineage: host, actor, Melian version, lens and tool versions, model, credential name, snapshot IDs, and timestamps. Subscription credentials work on Actions through the credential pool, and their terms are the user's contract. The single-writer rule holds through the concurrency group plus a lease check on push; a local publish during a running Action waits.

Why: A maintainer who reviewed locally with every lens should not pay twice, and the manifest already has the shape: a check with no record is not reviewed, so Actions completes the manifest. Whether a range review can seed a pull-request review stays a separate open question.
