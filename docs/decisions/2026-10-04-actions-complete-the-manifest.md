# Actions complete the manifest

Choice: Recorded now for milestone 3. The Actions host relies on local review records. `melian publish` pushes the changeset's storage, with its sightings, verdicts, and check records and their lineage, to the state branch; the Actions host opens it, runs only the checks the tier names that lack a record for the run identity, and publishes. Writers are trusted: a commit status or a local review record from an identity with write permission on the repository counts, and `trust.writers: false` in `melian.yaml` turns that off, so that only a trusted host's run counts. A local record counts only when the push came from such an identity and the record's lens version, tool versions, and policy hash match the run identity; the model is lineage, shown in the ledger, not identity. A pull request from anyone without write permission never relies on a local record, and the trusted host, the Actions host in milestone 3, runs the full gate for it. Every record carries lineage: host, actor, Melian version, lens and tool versions, model, credential name, snapshot IDs, and timestamps. Subscription credentials work on Actions through the credential pool, and their terms are the user's contract. The single-writer rule holds through the concurrency group plus a lease check on push; a local publish during a running Action waits.

Why: A maintainer who reviewed locally with every lens should not pay twice, and the manifest already has the shape: a check with no record is not reviewed, so Actions completes the manifest. A commit status set with a user's token can be set by any writer, so the milestone 2 gate rests on trusting writers; milestone 3 binds the required check to the GitHub App as its expected source. Whether a range review can seed a pull-request review stays a separate open question.
