# Review plan resolution

Choice: A route's `accept`, `unavailable`, and `acceptOverridden` come only from committed `melian.yaml` files; a preference file that sets one is a configuration error naming the key. Without `accept`, a committed route accepts its own model and fallbacks. The resolver substitutes and derives only for a committed route: when none of its models has credentials, the first accepted model with credentials stands in; failing that, `unavailable: fail` fails the tier, and `derive` takes the same model from another provider with credentials, matched by its catalogue name with any provider prefix and parenthesised qualifier removed and a name without a qualifier preferred, then the model with credentials whose price, input plus output per million tokens, is nearest on a log scale, alike in reasoning and with a context window at least the wanted model's or 200,000 tokens, ties to the larger window, then by provider and ID. A route from a preference file or `--model` is never replaced. A check on a tier `unavailable: fail` or `acceptOverridden: false` refuses never runs: it records `failed` with the reason, and a refused route also drops every fallback outside `accept`. A check records lineage when a preference file, `--model`, or a derivation moved its tier off a committed route's model, inside `accept` or outside it, and never where no committed route names the tier. The plan's JSON is stored in the verdict's provenance. Secrets files hold `api_key` credentials only; a tracked `melian.secrets.yaml` is refused, and a command source is read only from a file the user owns that neither group nor others can write. The user-level files live in `$XDG_CONFIG_HOME/melian/`, else `~/.config/melian/`.

Why: The [review plan decision](2026-10-04-review-plan-and-routes.md) set the keys and the outcomes but not the order of the lookup. A preference file that could set `acceptOverridden` would let the override it carries wave itself through, so `acceptOverridden: false` would fail closed only for those who chose to obey it. A maintainer who names a model in their own file, or on the command line, has said what they want; swapping it for another behind their back would spend their money on a model they did not choose, so a missing credential there fails as it always has. Deriving the same model from another provider first is the case the plan exists for, a contributor holding only Bedrock credentials. Price stands in for capability until calibration scores arrive in milestone 4. Running a check whose result cannot count spends tokens for nothing, so a refused check fails before it asks a model. pi-ai's catalogue names no model family, so the verifier's cross-family route reads one from the name in step 6.
