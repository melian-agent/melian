# Enola

Choice: Enola (enola.tech, `enola-labs/enola`, Apache 2.0, Go) is the first tool in the manifest, used two ways. As a static check: `enola check` on a baseline Melian builds from the base, run against the head, emitting SARIF diffed like Biome's. As lens input: the callers of changed symbols outside the diff, from `impact_analysis`, rendered into lens prompts as data and offered as candidate `affected` evidence the lens confirms or drops. Enola executes in the execution environment, like every tool that loads repository configuration, never in the Melian process. Its configuration files, for intent, constraints, suppressions, linking, and the `providers:` block that names an executable Enola runs, are policy read from the base and join the policy-change list; a committed baseline is never used. The spike decides whether Melian runs Enola with providers disabled. The graph is a cache, not state: keyed by Enola's own snapshot key (facts, Enola version, configuration hash), kept in a Melian-owned cache under the git common directory locally and in the Actions cache on runners, never on the state branch. The base snapshot is shared by every pull request on that base, a miss recomputes because Enola's output is byte-identical for the same inputs, and the check record stores the snapshot IDs and receipt. Search becomes break-glass: where Enola's coverage report says the graph cannot resolve a file's calls, `search` is free; where it can, `search` keeps a per-lens call budget, and each call carries a reason the hook records. Three kinds of coverage artifact, graph coverage from Enola, test coverage of changed lines (which runs the head's tests, so an untrusted head waits for container isolation), and review coverage computed from lens transcripts, live in the same cache keyed by commit and tool version, with their IDs in the check record. Enola is pinned in the manifest and refuses to compare across its own versions, which matches Melian's identity rule. Milestone 2 takes it as a spike with an exit criterion: its TypeScript extractor resolves Melian's own imports and calls, with gaps the coverage report names.

Why: A private repository's review skill measured a search walk timing out at 600 seconds twice where the precomputed blast radius finished in 331. The maintainer has used Enola on two projects. It is deterministic and its extractors are compiled in, though its `providers:` block can make it run an executable the configuration names ([research/2026-10-04-enola.md](../research/2026-10-04-enola.md)). The risks: it is pre-1.0, at v0.4.26 with a release every two or three days, and a documented TypeScript alias bug left thousands of call edges dangling.
