# Enola

Choice: Enola (enola.tech, `enola-labs/enola`, Apache 2.0, Go) is the first tool in the manifest, used two ways. As a static check: `enola check` on a baseline Melian builds from the base, run against the head, emitting SARIF diffed like Biome's. As lens input: the callers of changed symbols outside the diff, from `impact_analysis`, rendered into lens prompts as data and offered as candidate `affected` evidence the lens confirms or drops. Enola executes in the execution environment, like every tool that loads repository configuration, never in the Melian process. Its configuration files, for intent, constraints, suppressions, linking, and the `providers:` block that names an executable Enola runs, are policy read from the base and join the policy-change list; a committed baseline is never used. The spike decides whether Melian runs Enola with providers disabled. The graph is a cache, not state: keyed by Enola's own snapshot key (facts, Enola version, configuration hash), kept in a Melian-owned cache under the git common directory locally and in the Actions cache on runners, never on the state branch. The base snapshot is shared by every pull request on that base, a miss recomputes because Enola's output is byte-identical for the same inputs, and the check record stores the snapshot IDs and receipt. `search` stays unrestricted until the spike defines per-file call coverage for the graph and measures it against ground truth, for TypeScript the imports and calls tsc resolves on Melian's own tree; only then may coverage budget `search`, with a per-lens call budget where the graph covers a file's calls and a reason on each call that the hook records. Enola's own `coverage_report` cannot serve: it measures edges between repositories, needs two or more in one graph, and an absent edge is not proof that no relationship exists. Three kinds of coverage artifact, graph coverage as the per-file coverage the spike defines, test coverage of changed lines (which runs the head's tests, so an untrusted head waits for container isolation), and review coverage computed from lens transcripts, live in the same cache keyed by commit and tool version, with their IDs in the check record. Enola is pinned in the manifest and refuses to compare across its own versions, which matches Melian's identity rule. Milestone 2 takes it as a spike with an exit criterion: per-file call coverage for the graph is defined and measured against the imports and calls tsc resolves on Melian's own tree, with every gap named.

Why: A private repository's review skill measured a search walk timing out at 600 seconds twice where the precomputed blast radius finished in 331. The maintainer has used Enola on two projects. It is deterministic and its extractors are compiled in, though its `providers:` block can make it run an executable the configuration names ([research/2026-10-04-enola.md](../research/2026-10-04-enola.md)). The risks: it is pre-1.0, at v0.4.26 with a release every two or three days, and a documented TypeScript alias bug left thousands of call edges dangling.
