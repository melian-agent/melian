# Each finding names its repeated shape

Choice: every lens, built in or Melian's `durability`, reports each instance of a repeated shape as its own finding, and each finding names the class. A shape either repeats in the change, or the change cannot close it case by case, as with a deny-list each new spelling slips past. In each finding the lens says it is one of a class and how many instances it found. It cites the other instances as `context` locations, up to the ten `report_finding` takes. When the findings budget runs short, the lens reports the instances it allows and names the rest in each explanation. For a shape closed case by case, the failure scenario names every input the lens found that slips past. "One strong finding beats several weak ones" still holds, for weak findings that are not instances of one class. The verifier judges each claim at its own file and line; a cited instance is a claim of its own.

Why: rounds found one instance of a class a round, so the fix took a round per instance. Example: each round of [pull request #116](https://github.com/melian-agent/melian/pull/116) found one more spelling past the re-scope check's name matching: an alias, a default export, a binary file, a Unicode escape, a comment inside `export default`. Each early round of [pull request #117](https://github.com/melian-agent/melian/pull/117) found one more input missing from one attachment key. The lenses told the model that one strong finding beats several weak ones, and a findings budget capped the rest. A lens that saw the second instance had no instruction to report it, or to say there was a class.

One finding per instance, not one for the class. The first version of this choice folded the instances into one finding citing the others as evidence. Codex's adversarial review and two Melian rounds on [pull request #121](https://github.com/melian-agent/melian/pull/121) showed what that breaks. A finding's ID, its trigger and its verdict come from its reported instance. So a dismissal of the folded finding would hide an instance a later push adds, since the reopen reads the reported hunk only. A verifier that found the reported instance guarded would refute the rest with it. Each patch to those edges added another, which is the sign of a class. Kept apart, each instance keeps the identity, dismissal and verdict it always had, and naming the class in each still shows the reader the whole class in one round.

What this gives up: a class of eight instances costs eight findings of the budget, and a golden scores each. A reader sees the class repeated in each finding's explanation. A grouped finding, with an identity, cause and status per instance, would show it once, and is not built.
