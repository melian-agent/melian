# Unasked fakes belong to the tests lens

Choice: the `tests` lens gains `fake-answers-unasked`. A fake, stub, or scripted reply the change adds or edits answers a question the real request never asks, or relies on an input the real request never carries, so its test passes whatever that request holds. The lens reads the code that builds the request the fake stands in for, the instructions and the fields it sends, and names the input the request lacks. It reports the defect once, at the fake, under this rule and not also as `vacuous-test`, and cites the line that builds the request as `context`. The request that lacks the input is a second defect: a wrong result in changed code, which `correctness` owns. One defect hid the other, so each has its owner, as a removed guard has two.

Why: on [pull request #116](https://github.com/melian-agent/melian/pull/116) the verifier was asked to lower a severity it was never shown, and every lowering golden was scripted, so no test saw it. [Its comparison record](../../packages/evals/comparisons/2026-10-14-pr-116.md) called the defect unowned and suggested `contracts` if it repeated. The evidence points at `tests` instead. The defect showed through the test: the review of record found it by capturing the verifier's first request on the fake model. The `tests` lens already names the mutation every test lets through, and "remove the severity from the request; every test passes" is that statement. It reads the code under test and the fakes beside it. `contracts` reports a dependant that relies on a declared contract the change altered, and an instruction string has no caller and declares no contract, so the rule would have to stretch to reach it. AGENTS.md already says a fake answers only what the request asks; this rule makes a lens check it in any repository.

What this gives up: `correctness` has no rule that names a request missing an input, so it may miss one; the `tests-fake-answers-unasked` golden expects both findings and will show whether it does. The two findings sit in different files and never merge, so a reader sees the defect and the test that hid it apart.
