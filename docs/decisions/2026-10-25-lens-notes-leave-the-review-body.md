# Quiet review body: lens notes out, caveats once, folded sections

Status: accepted by the maintainer, 2026-10-25, in [issue #212](https://github.com/melian-agent/melian/issues/212).

Amends: [Findings read in one register, with emojis and a set English](2026-10-24-finding-register.md), rows 21 and 24 of "What every renderer keeps", the notes of lenses that ran and the review body's sections.

## Problem

The review body listed every lens that ran with a note, and the note in full. The notes are for someone tuning Melian. A reviewer cannot act on them, and they change nothing about what the review covered.

Example: [pull request #201](https://github.com/melian-agent/melian/pull/201)'s published review repeated seven "Callers unavailable for <file>: line N: directory-scoped name is ambiguous" notes, and "triage input was cut, so no lens could skip", under each of eight lenses: about 50 lines. Caller context is an optional input; a note records why one site got no answer. A cut triage input let no lens skip, so every lens ran. Neither narrowed the review. A lens that a budget ended, failed or skipped already appears under the checks that did not run. The README promises that Melian is quiet; this broke it.

## Decision

1. The pull-request review body, and the ledger's summary, which renders it, no longer list "Lenses that ran with a note".
2. Every note stays where someone tuning Melian looks: on the check record's `reason`, so in `melian findings --all --json`, `melian review --json` and the terminal verdict with `--notes`, and in the ledger's collapsed run details. There each distinct note appears once, beside the lenses that carry it. A reason joins notes with `; `; split on that separator before removing duplicates, so lenses that share one note but differ in another still list the shared note once.
3. A caveat reaches the review body: a note that changes how far the reader can trust the whole review. It is one line, `Reach: <caveat>.`, after the summary and before the status mapping, however many lenses carry it. Two conditions qualify, because each held for the whole review and narrowed what every lens could see:
   - no changed site got callers: the caller context was absent or unavailable, or each changed site was a test file or its caller query failed. The caveat reads "callers were unavailable for every changed site, so no lens saw who calls the changed code", then the reason.
   - triage chose quick for every lens of a review whose change can steer triage.
   A note about one lens or one site is not a caveat, and neither is one that widened the review, such as a cut triage input.
4. A check record carries its caveats in a `caveats` field, so a renderer reads them rather than matching note text. The lens task's caller input and the review index carry the caller caveat beside the caller notes, so a repeat review keeps the first call's caveat as it keeps its notes.
5. The caller query skips test files. Nothing calls a test's callbacks, so the query only produced ambiguity notes and spent Enola time ([issue #208](https://github.com/melian-agent/melian/issues/208)). A test file is one whose name says so, `.test.` or `.spec.`; a directory such as `fixtures/` or `test/` is no evidence, since production code can live there. Vitest knows which files are tests but does not run in the caller query, so the name is the one sign it trusts. The mutation selector keeps the wider `testPath`, which also sets aside those directories, because it chooses what not to mutate. Each skipped file is named as a caller issue, so a change of test files alone still raises the caveat.

6. A section stays open when it asks the reader to act, and folds into `<details>` when the reader needs it only to dig in; its summary is a count and a noun, never a sentence. The maintainer ruled it on 2026-10-25. In the review body, the verdict, the status mapping, the checks that did not run and every finding that blocks or needs an acknowledgement stay open. The advisories fold under "N advisories". The attested dismissals fold under "N dismissed, M reasons". [Pull request #202](https://github.com/melian-agent/melian/pull/202)'s review listed twelve dismissals, eight with one reason. Inside the fold, dismissals that share a reason are one decision, so the reason appears once, followed by the findings it covers, each with its ID, rule and file. A dismissal with its own reason keeps its line. Attestation is unchanged: the same dismissals, the same signed marker. Inline comments stay open, since each is one finding on its line.

Where this decision and rows 21 and 24 of the register's table conflict, this decision wins. The terminal follows the [high-signal decision](2026-10-25-high-signal-low-noise.md)'s terminal rule: `melian review` and `melian findings` omit lens notes by default. `--notes` shows each distinct note once, naming its lenses. Checks that did not run keep their reasons without the flag.

## Stored shapes

`CheckRecord` gains an optional `caveats`; the verdict document moves to version 13 and the adjudication task to version 6. The lens task's caller input gains an optional `caveat`, moving that task to version 5; the review index's caller record gains one, moving it to version 4. An older record holds a caveat only as a note, and an upgrade must not drop it: a verdict published again after the upgrade would otherwise lose its notes from the body and gain no `Reach:` line in their place. So each migration reads the two notes Melian wrote for the two caveats, "Callers unavailable: <reason>" and the light-triage note, and adds the caveats they stand for. No structured field held them before, so this is the one place Melian reads its own notes. A note about one file's callers, "Callers unavailable for <file>", is no caveat. A verdict's fingerprint leaves caveats out, since the reason already holds what they say, so an upgraded verdict hashes as it did and is not published again. The rounds document moves to version 2 and upgrades each round's verdict copy the same way, because publish refuses a round whose copy differs from the verdict document's. `packages/pipeline/test/caveats-reopen.test.ts` reopens a store main wrote at `460f68f0` and finds its caller note read as a caveat.
