# Pin Enola 0.4.40

Amends: [Restore the Enola clauses that partial supersessions retired](2026-11-08-restore-enola-clauses.md), its clause that pins official Enola v0.4.27: the pin is now v0.4.40.

Status: accepted on 2026-11-13 under [issue #346](https://github.com/melian-agent/melian/issues/346), a step a writer opened, through [pull request #385](https://github.com/melian-agent/melian/pull/385).

## Problem

`tools.yaml` pinned Enola v0.4.27, from 2026-10-05. Upstream has since shipped thirteen releases. They include a richer TypeScript call graph, fewer false performance results, and code symbols in place of Markdown files in fan-in. The restored clause still named v0.4.27, so moving the manifest without a decision would leave the decision log saying one version and the build running another.

## Decision

Melian pins official Enola v0.4.40 for Darwin and Linux, on amd64 and arm64. Each digest is the release asset's, and the release's publication time comes from GitHub's release API. The release is past the release-age window, so the pin carries no exception. Every other clause of the restored decision stands.

## Why

On `main` at `0bde70ca`, the spike matches 1,887 of 23,596 call pairs against tsc, where v0.4.27 matched 1,418, and the same 608 of 1,651 imports. The commands, flags, exit codes, SARIF, receipt and impact JSON Melian reads keep their shape.

## What it gives up

Enola finding IDs would have changed with the symbol spans v0.4.37 added. [The one-line identity decision](2026-11-13-enola-results-keep-one-line-identity.md) keeps them as they were. Performance results differ from v0.4.27's, by upstream's rework in v0.4.28.
