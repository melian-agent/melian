# Triage questions are versioned and measured

Choice: `triageQuestionSet.version` stands for the questions triage asks. A hash of every shipped lens's question, with and without a `skip` option, is recorded by version in `packages/evals/triage/questions.json`, `{"1": "<hash>"}`. A gate test fails when the current questions hash differently from the entry for `triageQuestionSet.version`, or has no entry, so a reworded question needs a new version with its own entry. It also fails when an entry recorded at `origin/main` is missing or different in the working tree, so a version's hash is never rewritten. Where git cannot read `origin/main`, such as a shallow clone, or main has no record yet, only the first check runs. Reading the two files in one change cannot catch a re-recorded hash under an old version; the comparison with main can. A corpus of six changes, each with the right level for two lenses, measures the levels the LLM fallback decider chooses: exact share, mean distance in levels, and the count of choices below the right level. A scripted run proves the plumbing. A live run on a real model, three passes by default, prints the measurement, writes it as JSON, and compares it with an earlier one: a lower mean distance is better, then a higher exact share, and a worse measurement exits 1.

Why: Problem: the question set carried a version that nothing held to the questions, and nothing measured whether the LLM fallback chose well. Example: rewording what `quick` means in `levelMeanings` changes every triage decision, yet stored decisions and the plan's identity keyed by version would not have moved. Solution: tie the version to the questions mechanically, so a change cannot ship unversioned, and measure the decider against levels a person judged, so a change can say whether it chose better. The corpus is small by design: the right level is a judgement, six cases cover the three levels and the two lenses that differ most, and the live comparison reads only the direction of change. Distance rather than accuracy alone, because `quick` for a change that needed `deep` costs more than `careful` does, and the under-look count is kept apart because an under-look lets a defect through.

Does not supersede an earlier decision: triage's questions and their version existed, and this adds the check and the measure.
