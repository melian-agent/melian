# Coverage and delta review

Being built in milestone 2, plan step 24, with the shared ledger in milestone 3. [The decision](../decisions/2026-10-23-coverage-ledger-and-delta-review.md) holds the exact rules, the voids, and the numbered list to attack before any build.

Problem: a round after a fix pass reviews the whole pull request again. On [pull request #174](https://github.com/melian-agent/melian/pull/174), five fixes of under 50 lines each took five rounds of about 35 minutes: lenses, the verifier and Stryker over every changed line, each time. The rounds also sample, so a full round can miss the lines the fix changed, and the rule that the last round before the queue is full costs a whole round at the end of every pull request.

Example: round 1 at head `A` finds an untested guard in `publish.ts` line 40 and a wrong default in `config.ts` line 12. The fix pass edits `config.ts` alone. Round 2 should read the `config.ts` hunk, keep the `publish.ts` finding open without reading it again, decide whether the default is fixed, and, if it is, let the pull request pass.

Solution: a coverage ledger, `melian.coverage`, in the changeset's storage. For each changed line of the diff and each check that applies to it, the ledger says which round covered the line, at what level, under what identity. The delta is every changed line some check has not covered. `melian review` reviews exactly the delta, and a review is valid when the delta is empty and nothing above advisory is open. The maintainer's words: "any series of reviews that together cover the full diff at the configured level for the files in the diff, are a valid review."

## What covers a line

A changed line is a line a hunk adds at the head, or a line a hunk removes from the base. A changed file with no hunks, such as a binary update, a mode-only change, an empty file, a pure rename or a type change, and any mode or kind change beside hunks, is a file unit of its own, taken from the changeset's `ChangedFile`. A lens covers a unit only when the ledger shows its input carried every field: path, status, modes, kinds and binary flag, a symlink's bounded target, and whether the file is empty. The prompt's diff block carries them, and a unit outside the diff cap gets a compact metadata block of its own; a content read never covers a field. Until then the unit is a gap, and no lens skips it as nothing uncovered. A finding on a unit sits at its path, line 1, at the base when deleted. A round covers it for a check when the round reviewed the same base under the same policy and standards; the line maps unchanged through git from the round's head to the current head; every lens that applies to the file received the line, in the prompt's hunk or through a read, in a run recorded `ran` at or above the file's required level; and every finding on the line is settled at the current head. Guardrails, Biome, tsc and Enola run over the whole range every round and cover the whole diff at that head. Mutation coverage comes from verification records, as [the mutation-evidence decision](../decisions/2026-10-24-mutation-evidence-by-enumeration-and-verification.md) defines them: a verification record is one immutable batch, a test's three control windows and both mutated results for every candidate in one round, and it is evidence only at the head it names, only whole under its batch ID, and only when its executor (the local ID Melian stores beside the install that ran it), its installation identity (the lockfiles, the test runner's version, the Node version, the platform and the architecture), its adapter identity, its policy digest (the SHA-256 of the effective base-sourced mutation policy, declared environment variables included, and the resolved test-command argv) and its test's full component array each equal the reader's; a record that differs in any is rerun, never reused, and no mutant's result is reused outside its batch. Nothing mutates in a round, and mutation coverage never maps or carries, because a change to `b.ts` can make a mutant in unchanged `a.ts` survive that an earlier head's record killed. A line is covered for mutation when every mutant on it is killed in a whole batch at the head, the subject of a settled survivor finding, or dismissed; config-ignored mutants and `invalid` records cover with a note. A set-aside file covers nothing and raises a P2 `mutants/unmutated` finding at its first changed line, or at its file-unit location when it has none, until a maintainer settles it. An `invalid-claim` or `flaky` record, a comment-ignored mutant and an `equivalent` claim cover nothing; the claim stays unresolved until a maintainer dismisses it. Records are read only under writer leave or `--trust-head`, the only reviewer leave, and `trust.writers: false` refuses only writer leave. The delta prompt renders the hunks that fit, smallest file first. A hunk no prompt can carry reaches each lens in bounded chunks through `read_file`, and stays uncovered for that lens until its reads deliver every line. No policy notice supplies a lens's coverage, a lockfile's or an analyser configuration's included. The one escape is a maintainer's dismissal naming the check and the uncovered lines, recorded as a dismissal, never as coverage.

## The ledger

The review-coverage artifacts already record, from durable transcripts, which lines each lens read or searched and which hunks and declarations those reads touched. They prove delivery, count tool reads alone, live in the cache outside the state branch, and are written only when Enola's graph is present. The ledger therefore reads the lens transcripts and stored prompts itself. It adds a document in the store: per record, the producer's identity, an explicit algorithm version in its compatibility identity, so a changed mapping or delivery rule voids or recomputes the coverage rather than reading it as current; per round, the base, head, tier, policy fingerprint, standards paths, Melian version, writer leave and the git mapping from the last decided round's head, by mint order; per lens, its `name@version@level`, status, and the hunks and lines delivered per file, under both paths of a rename; per whole-range check, that it ran at this head; for mutation, the verification records relied on per line at this head, with their executor, installation identity, adapter identity and policy digest; and the coverage carried from the last decided round in the head's coordinates, so one record answers for a head. `melian findings` and `melian review` print a `Coverage` section, complete with its rounds or incomplete with each gap and its reason, and the JSON carries the same.

## What a round does

1. **Computes the delta** at intake from the ledger at the last decided round and git, per check, and fixes it in the round's input, so a resume reviews the same lines.
2. **Carries the last decided round's lens findings.** Each lens sighting is copied per producer under a `carried/` prefix at the new head, mapped by git; a deterministic check re-sights at the new head, and a `--cold` round deletes the carried producers at its key. One whose cited lines the delta left alone carries with its verification. One whose lines the delta changed, or whose file git reports deleted, is changed, never gone, and is re-judged at the first new-side line after its hunk. The carry never resolves, lowers or reopens a finding; cause is recomputed against the whole diff.
3. **Runs lenses on the delta.** Each lens whose delta is not empty runs, at the higher of the last decided round's level and its default within its band, without triage. Its prompt holds the delta's hunks, then the rest of the diff as context within the cap, then the pull request's file list. It is handed every carried finding of its own, as escalation hands a quick run's findings to the next level, and restates, refutes or leaves each. A restated finding keeps the stricter severity. A refutation is a verifier candidate, never a drop, stored as a verification on the carried claim, which the trust floor reads; a protected claim keeps its minimum through it, and at a `verify: false` level a refutation never lowers. A changed finding the lens leaves goes to the verifier. A carried copy keeps one `carried/` prefix and its first `carriedFrom` across heads. A lens whose delta is empty is skipped with leave.
4. **Runs the checks.** Guardrails and static tools run over the whole range. Mutation evidence is read from verification records at the current head; nothing mutates in a round, and the tests lens probes what has no record.
5. **Adjudicates the whole head**, carried and new findings together, with one more check record, `review.coverage`: `ran` when the ledger now covers every changed line, otherwise `skipped` without leave naming the gaps, which leaves the review not reviewed. It joins every manifest without a tier entry, and a file naming it in a tier or `checks.allowSkip` is refused in every layer the loader reads, nested and preference files included.

A repeat review whose delta is empty under an unchanged identity attaches to the current round and spends nothing. `--rerun` runs the failed checks and lenses again. `--cold` reviews the whole diff from nothing.

## Voids

Coverage from a round is void, whole or in part, after a base change, a force push, rebase or a head that cannot be resolved, a merge commit between the round's head and the current head, a policy or standards change, a review-identity change, a failed or ended lens, a check record that did not run, a mutation record from another head, executor or installation identity, or under another base's mutation policy, a `static.mutation` audit's provisional record or its dependency, configuration and test change list, a `melian/injection-attempt` finding, which voids its whole file for every lens until a round reviews the file afresh, since a lens that met injected text may have been steered, or a delta over 1,000 lines or half the diff, which runs cold. The decision says which void all coverage and which void one lens or one check's. A void leaves lines uncovered; the round reviews them. The ledger records no coverage from a fork's head, whoever runs the round and whatever flag they pass, so such a review is never valid; the agent refuses any record whose head is not a writer's or the App's.

## The status

`melian/review` passes when the ledger shows an empty delta and nothing above advisory is open. An incomplete ledger leaves the review not reviewed and the status `error`, naming the gaps. The merge-group job is unchanged. `melian publish` posts the current decided round; its body and the ledger comment say which lines the round reviewed and which rounds cover the diff. A round reviewed the changed lines its own lenses received, context hunks included, since the ledger counts a delivered line as covered. The body lists twenty gaps and twenty reviewed files and counts the rest, and `melian.published` version 10 keeps each ledger round's coverage. A round an earlier build decided wrote no ledger record and shows no coverage. A carried finding has a sighting at the head, so it stays open with its thread.

## Round identity

Every round's key comes from one method, core's `Revision.key(sides, scope)`, whose one scope today is the whole diff, `diff`, and gives `<base>..<head>`; a scope it does not know is `ChangesetError` `unknownScope`, and no caller, storage or display, builds the key by hand. It takes the base and head as a stored record names them, since most callers hold a record, not a `Revision`. `Revision.parseKey` reads a key back, and `Revision.display` cuts each side to twelve characters for a reader. The `hand-built-revision-key` guardrail in the root `melian.yaml` refuses a new `${...}..${...}` in package source. The key carries no approval: a review passes only on an empty ledger delta, which no key can forge. Rounds at one head are told apart by their IDs, as step 23 built them. `melian.rounds` records each round's scope and ledger record, and the findings document holds carried sightings beside new ones.

## Sharing, in milestone 3

The ledger is why the state branch exists. A writer's `melian publish` pushes the changeset's storage to `melian/state`; the Actions host opens it, verifies each round's head writer and policy fingerprint itself, computes the delta from the ledger, runs that, and publishes under the GitHub App. Writers and the App may push; one writer holds a changeset's lease at a time, a writer that fetches a live lease refuses to run, and a refused push keeps its results locally and resumes by taking the branch's copy and running again, which costs the delta the branch lacks. The agent never accepts a round of a fork's head, a worktree policy, a non-writer's push, or a status; a round whose head GitHub no longer holds is void, and the agent never reuses a local verification record and verifies again every mutant it relies on. No signature is needed while writers are trusted and push permission alone writes the branch.

## What it costs

The residual, in degree: N full rounds sample unchanged context N times, delta rounds once, then as context within the cap. A defect whose cause spans a delta hunk and an earlier-covered line is read together only when that line reaches the prompt as context or a read fetches it; a cross-round golden demonstrates this. A defect in unchanged code that no round reached waits for a maintainer or a `--cold` round. The whole-range static checks run every round. Each head needs its mutants verified again, minutes a head, since no record carries. An oversized lockfile hunk costs each lens its chunked reads or a maintainer's dismissal. `--cold` remains the reviewer's choice for lenses.

## As built so far

Build 1 writes a `melian.coverage` record for every decided round and prints the `Coverage` section in `melian findings` and `melian review`, text and JSON. [The build 1 decision](../decisions/2026-10-25-coverage-ledger-build-1.md) records four choices the design left open: the review writes the record after the verdict, once per round; a whole-range check, `static.mutation` included, covers only the head it ran on; a record of another coverage algorithm is void; and the policy fingerprint leaves out the mutation run's own identity.

Build 2 makes a round after a decided one review its delta, carries the decided round's lens findings, adds `review.coverage` to every manifest, and lets a maintainer dismiss a named gap with `melian dismiss-gap`. Every prompt now names each file's modes, kinds, binary flag, symlink target and emptiness, and renders smallest file first, so a file unit is delivered and a large file no longer keeps a small one's hunks out. [The build 2 decision](../decisions/2026-10-25-coverage-ledger-build-2.md) records six choices: a repeat review of the same head is no delta and attaches; a delta lens runs at the higher of its last level and its default; every round renders the new prompt; `review.coverage` points at a check that did not run; a changed finding sits after its hunk; and a gap dismissal takes effect at the next review. Mutation rows still wait for step 34's verification records.
