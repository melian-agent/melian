# Mutation evidence

Planned for milestone 2, plan step 34, with the other-language adapters in milestone 3. [The decision](../decisions/2026-10-24-mutation-evidence-by-enumeration-and-verification.md) holds the exact rules, what it amends, and the numbered list to attack before any build. Each part is tagged: **[Melian's flow]** is the product, **[Building Melian]** this repository's own process.

Problem: a test counts as proof only when it fails with the guard it covers removed, and the only thing that ran the removal was a whole Stryker run, 15 to 70 minutes a round. The `tests` lens named "the mutation every test lets through" in prose, and nobody ran it. Enumeration reached TypeScript and JavaScript alone.

Example: on [pull request #168](https://github.com/melian-agent/melian/pull/168) a builder's hand inventory covered 18% of 242 mutants, and all ten of Stryker's survivors sat in the rest. Once builders enumerated first, six passes left Stryker nothing real to find, and every claim it could check held.

Solution: mutation evidence is a record that a named test killed a named mutant at a named head, made by applying the mutant and running that test. Melian enumerates, a builder or a lens claims, and a verification run checks. The `tests` lens backs each `untested-behaviour` finding with a probe. Stryker leaves Melian's own tiers and stays as an opt-in audit.

## The commands **[Melian's flow]**

`melian mutants list <range|#pr>` enumerates the mutants of the changed production lines into a versioned inventory, without running a test or any head code. `melian mutants sample <inventory>` prints the probes a classified inventory owes, by the deterministic rule of [the sampling decision](../decisions/2026-10-21-builder-inventory-sampling.md). `melian mutants verify <inventory> [--all]` applies each sampled mutant, or every claimed one, runs the named test, and records the outcome in the inventory and in the repository's mutation cache. It exits `0` when every claim held, `1` when one did not or a `new-test` claim still waits, `2` when it could not run. [The CLI guideline](../guidelines/cli.md#commands) gets the rows.

The inventory, `melianMutants: 2`, carries the range, each adapter's identity, the installation identity, and one row per mutant. A row holds its identity fields, the hex SHA-256 of `[file, line, column, endLine, endColumn, mutatorName, replacement]` as `id`, the builder's `claim`, `evidence` and `survivorClasses`, and its `verification`. A `killed` claim's evidence is `{ test: { file, name } }`; an `equivalent` claim's is `{ reason }`. The version-1 inventory with string evidence is refused by `verify`.

## Adapters **[Melian's flow]**

A `MutationAdapter` lists mutants for changed lines, brings one into effect, names the command that runs one named test, and classifies an outcome as `killed`, `survived`, `invalid`, `invalid-claim`, `load-error` or `timeout`. `invalid` is `apply`'s parse verdict alone; a module the runner cannot load is `load-error`. A test's identity in a report is `ancestorTitles` plus `title`, never the space-joined `fullName`. An adapter that must build the head to enumerate, as PIT and cargo-mutants do, declares it and enumerates only under leave. An adapter declares `applies: switch` or `applies: text`. The TypeScript adapter is a switch adapter: two attacks found a universal oracle, a `toString()` snapshot or a whitespace-stripped `git show HEAD:` comparison, that kills every spliced mutant. So it applies a mutant as Stryker does, by writing the instrumenter's switched build over the source once, every mutant compiled in behind `stryMutAct_9fa48(id)`, and setting `globalThis.__stryker__.activeMutant` from a prepended setup file, as `stryker-setup.js` in `@stryker-mutator/vitest-runner` does, when the file loads rather than in `beforeAll`, so module-level mutants activate. The setup file is the same text in both runs and sets `hitCount: 0`, `hitLimit` and `activeMutant`, which is `null` in the baseline, never `undefined`, and the child environment never carries `__STRYKER_ACTIVE_MUTANT__`, which the instrumenter's header would otherwise read. `hitLimit` is 100 times the mutant's baseline `stryCov` count, unset when that count is 0 or unknown; the baseline runs the same build with no mutant active, so no test can tell them apart by the file, and one that compares with `HEAD` fails its own baseline. A test can still read the switch's state. The `forged-mutation-kill` guardrail flags the literal names, and every test that killed runs once more with an inert mutant active, an ID Melian adds behind a branch whose two sides are the same expression; a test that fails under it makes every claim on it `invalid-claim`. It costs a larger file that loads slower, and a dependency on the instrumenter's helper names. Its operator set excludes the mutations named in the `stryker.config.json` read from the policy source, never the head's copy. The test pattern is the ` > `-joined name, regex-escaped and anchored, since `-t '^suite works$'` matches nothing and skips every test. `{file}` and `{name}` substitute into argv elements, never a shell string. Other adapters wrap a dedicated tool, cargo-mutants, mutmut, PIT, Stryker.NET or mutant, or fall back to tree-sitter with a fixed operator table, as [issue #170](https://github.com/melian-agent/melian/issues/170) proposes. A text adapter's kills are weaker evidence: the `forged-mutation-kill` guardrail gains patterns for a changed test that stringifies an imported function in an assertion, spawns `git show`, or reads a production source path, at P2 acknowledge. For every adapter, the review body lists every test that killed on more than one file. A repository names its languages and test commands under `mutants.languages` in the committed root `melian.yaml`, the only file that may, since a test command executes.

## Verification **[Melian's flow]**

A verification run executes the head's tests in a scratch worktree, under the leave [the unconfined decision](../decisions/2026-10-14-static-checks-run-unconfined.md) requires: a writer's head or `--trust-head`. `melian mutants verify` runs only when the inventory's head is the checked-out `HEAD`, exit `2` otherwise, which is why it needs no flag; it records leave `reviewer`. `trust.writers: false` refuses a probe. A kill is a test that appears exactly once in the runner's report of both runs, passes unmutated and fails mutated; `skipped`, `todo`, absent or duplicated is `invalid-claim`. The baseline runs the probe's own command with no mutant active. A mutant `apply` cannot parse is `invalid`. A module the runner cannot load is `load-error`, and so is a test file that fails to collect mutated while the test was present in the baseline. A run past `mutants.timeout`, or one whose `hitCount` exceeds `hitLimit`, is `timeout`, whatever the test read. None is `killed`. `--jobs` runs one scratch worktree per job; a baseline that fails under load is rerun alone, and a kill by such a test needs two mutated failures. Records live in the mutation cache keyed by head, adapter and installation identity, and are evidence at that head alone.

## The tests lens **[Melian's flow]**

The lens receives the enumeration of its files' changed lines, with each mutant's record at this head, inside the review's boundary under the label `mutants`, bounded to 400 mutants and 64 KiB. Two tools join it: `list_mutants(file)` and `probe_mutant(id, test?)`. `probe_mutant` always runs; a cached record is context, never the outcome. A probe without a test runs the tests Vitest relates to the file; its first failed test is the killer only after it is run alone by its ` > ` name and passes with the mutant inactive and fails with it active, else the probe reruns without it. Spawned-only code relates to no test, and widely imported code relates to most of the suite, so a probe whose selection is empty or times out falls back to the whole suite under `mutants.suiteTimeout`, at most `mutants.suiteRuns` times a round, 1 by default, with Melian's counter, since a detached round is its own changeset; that restores Stryker's `NoCoverage` fallback within a budget of up to 20 host minutes a round. An `untested-behaviour` report names a probed mutant whose record reads `survived`; one naming a killed mutant is refused, and one naming none is refused while a probe is available. The refusal applies only to a mutant on the finding's line whose probe read `survived` or `killed`. A `timeout`, `invalid` or `invalid-claim`, a line without a mutant, or a spent probe budget makes the probe unavailable, and the finding goes to the verifier as today. Refused reports are notes on the lens's record, and the review body lists the kills that refused one. A verifier may refute a `survived` finding only by naming a test, which Melian runs; the record decides, and the verifier may lower a standing finding one step. The probe is a third verification executor, `probe`; its refutation keeps the trust floor. `budget.probes`, 12 by default at `careful`, bounds a run; a refused probe is a note, the record stays `ran`, and the lens goes on.

## Stale kills **[Melian's flow]**

A later change to `b.ts` can make an earlier-killed mutant in `a.ts` survive. The choice: a record is evidence for its exact head and no other, and every claim is verified again at the head the review passes on. Measured on four recent pull requests: 72 to 328 mutants. A named unit test costs about 3 seconds with process start, a CLI test 2 to 60 seconds, and a related probe on widely imported code runs most of the suite. The cost is bounded by `mutants.timeout` and the probe budgets rather than assumed. Re-verifying only claims whose test's import closure changed was rejected: imports are not the only thing a kill depends on, and the list of what else is kept growing.

## Coverage **[Melian's flow]**

Until [the coverage ledger](coverage-and-delta-review.md) lands, adjudication writes a `mutants` check record from the enumeration and the records at the head. Under `mutants.evidence: required`, which Melian's own `melian.yaml` sets, an unverified mutant on a changed production line leaves the review not reviewed, naming the count and the command. Under `advisory`, the default, the record counts. Melian writes it; it joins every manifest without a tier entry, and a `melian.yaml` naming it in a tier or `checks.allowSkip` is refused. The same step turns a `survived`, `timeout` or `load-error` record into one `mutants/untested-behaviour` finding per mutant. Its discriminator is the SHA-256 of `[mutatorName, replacement, column, endColumn, text of the range, occurrence]`, with the trigger hash supplying the line, so code moving above it keeps the dismissal. The finding carries no snippet, so the discriminator is its ID input, and the occurrence index among equal tuples in the file keeps two identical lines apart. A dismissal names the mutants it covers, and a surviving mutant it does not name reopens the line. An `invalid` record covers with a note. The ledger absorbs it: a production line is covered when every mutant on it has a `killed` record at the current head, a settled survivor finding, or a dismissal. The decision names what [pull request #185](https://github.com/melian-agent/melian/pull/185) must change.

## What happens to static.mutation **[Melian's flow]**

It leaves every tier of Melian's `melian.yaml` and stays in the product, unchanged, as an opt-in audit: the one exhaustive run and the only measure of what claims and probes miss. The `forged-mutation-kill` guardrail and the policy rules for Stryker's files stay with it.

## Customers **[Melian's flow]**

The three skills gain a "Prove the tests" section telling a builder agent to list, classify, sample, verify and relay, and never to write a claim as held until `verify` says so. `melian doctor` gains a `mutants` line per configured language naming the adapter, the enumerator's source and version, the test runner and `mutants.evidence`.

## This repository **[Building Melian]**

Briefs use `melian mutants list`, `sample` and `verify` in place of the scripts. The host mutation-only run before a branch's first full round goes, and so does the cold final run. A Codex task's seatbelt denies writes under `.git/melian/`, so its `verify` writes no records, and the host runs `verify --all` after a Codex pass. The decision lists each `AGENTS.md` line that changes once this is built; none is edited now.
