# State branch guidelines

`packages/state-git` is the git adapter of core's `RecordStore`, `GitRecordStore`. It keeps the shared record on the repository's `melian/state` branch, by rule 12 of [the shared record decision](../decisions/2026-11-13-shared-record-behind-a-store-port.md) and [the decision that amends it](../decisions/2026-11-14-git-record-store-refuses-by-location.md). Read both before changing it.

## How it works

- `RecordRepository` is a bare repository of Melian's own, `records.git` in the clone's state directory. It is never the clone: a fetch writes nothing into the clone's refs, and the clone is never made shallow.
- Every call fetches the branch's whole history into a ref of its own, and deletes the ref once it has read the tip from it, or failed to. A call whose deadline runs out first leaves the ref, as a killed call does. Two processes can share one `records.git`, so never fetch it shallow: another process's fetch one commit deep cuts the history a landed check reads, and a push that landed reads as lost. A plain fetch keeps a shallow repository shallow, so a `records.git` an earlier build left shallow is refused when it opens, with the advice to delete it.
- Each fetch then points `refs/melian/last` at the tip, in `records.git` alone. A fetch names what it holds by its refs, and the fetch ref is gone by then, so a repository with no ref is sent the whole history again. A host's first fetch receives all of it, which grows with every write until [issue #361](https://github.com/melian-agent/melian/issues/361) bounds it. With the ref, an unchanged branch sends nothing and a grown one sends what is new. The ref is a hint: no call reads it to answer, it is never pushed, and two calls updating it at once lose only the hint. An update that fails twenty times is given up, and the call goes on. Nothing deletes old objects, so `records.git` grows with the branch's history; [issue #451](https://github.com/melian-agent/melian/issues/451) tracks collecting them.
- A call names its temporary index, its half-made repository and its fetch ref after its owner: a hash of the host's name and its pid, then a UUID. Opening the store sweeps the state directory and removes such a leftover once core's `ProcessTable` lists no process with that pid, as [the sweep decision](../decisions/2026-11-16-record-store-sweeps-what-a-killed-call-left.md) sets. It lists the leftovers before it reads the table, so a call that starts in between keeps its own. It keeps, and `GitRecordStore.sweep` names for `melian doctor`, what it cannot prove gone: a pid the table lists, the owner's or a reuser's, another host's, an unowned or unparsed name, and an entry not of the kind the store makes, a link included. It sweeps nothing when the table cannot be read. It shares the open's deadline: once none is left it removes nothing more and counts what it did not reach as `unswept`, which the next open removes. A state directory shared across hosts is not supported: two hosts with one host name read as one.
- `StateTree` judges every entry of the fetched tree before a call answers or builds a commit. An entry is known when it is a mode `100644` file at `changesets/<changeset>/cell.json` holding a cell Melian writes, or at the path a record's own bytes give. A stray in one changeset's folder refuses that changeset; a stray anywhere else refuses every changeset. A handle remembers what it judged by mode, type, object ID and path, so it reads each blob once, and an entry whose mode changes is judged again. A refusal or `melian doctor` names a path that is not UTF-8 in git's quoted form, as `git ls-tree` prints it, so two such names never read alike.
- A write builds one commit with `read-tree`, `hash-object`, `update-index` and `commit-tree` on a temporary index, and pushes it with `--force-with-lease` on the tip it read. A lost race waits a random time below a bound that doubles from 50 ms to 8 s, and reads again, until the deadline.
- A push Melian stopped before git ended, at its deadline or once it wrote more standard error than core's `git` keeps, counts as landed only when its commit is the tip or an ancestor of it, in the history the check fetches. A tip that has not moved since the push proves nothing, because the lease still holds and a transport that outlived git can land the push later, so the call fails as `unreachable`, saying it may have landed. A push that git ends with no refusal of the ref, as when the connection drops, may have landed too, and fails the same way. A push whose ref git refused fails as `unreachable`, naming the refusal's class, unless the refusal is a race.
- `deadlineMs` sets one deadline for the whole call, a `Deadline`, and `RecordRepository.run` takes it as a required argument. Each git command gets only the time left, and none starts once none is left. A backoff waits the smaller of its own time and what is left. A push ends by three quarters of what is left, inside the call's deadline, so a push that stalls still leaves the landed check a quarter to learn whether it landed. Core's `git` returns the moment its timer fires, without waiting for git to exit, so a call whose every command is slow ends a few milliseconds past its deadline; `test/deadline.test.ts` allows 250 ms.

## Rules

- Run git only through `RecordRepository.run`. It checks the repository's configuration bytes and passes `overrides`, the settings that would run a program or start background work. A new setting with that power goes on that list with a one-line reason, and a test proves it holds with the configuration check mocked out, as `test/overrides.test.ts` does. Its environment turns off replacement refs and the graft file, since either in `records.git` would make a read or the landed check see objects the remote never sent; `test/repository.test.ts` plants each.
- Every command reads the user's own system and global git configuration, because a fetch and push authenticate through it: a credential helper, an ssh command, a URL rewrite for a mirror. Code that can write that configuration already runs as the user, so reading it gives that code no new reach. Melian checks only `records.git`'s own configuration, which it writes, and `overrides` turns off what would run a program there. The maintainer accepted this on 2026-11-15.
- Pass `--end-of-options` before the remote, or any other argument a caller supplies. A remote spelled as an option, such as `--upload-pack=<program>`, otherwise makes git run that program on the host.
- A message from a command that talks to the remote quotes none of git's text and none of the remote's, and names the remote as "the clone's origin". Git prints a URL's query, a URL the user's configuration rewrote and whatever the remote sends, and any of these may carry a token, which `melian doctor` would print. Such a message names the operation, git's exit code and, for a refused push, the class Melian reads from the porcelain line. It ends by naming the git command that shows git's own words. A new command that reaches the remote follows this rule. A command that runs on `records.git` alone keeps git's text, and a check that reads git's text to decide, as the fetch's absent-branch check and `#deleteRef`'s retry do, never prints it. The maintainer chose this on 2026-11-15, in the coordinator's session.
- Remove a leftover only by the sweep's rule: its owner is this host's and the table lists no process with its pid, and it is the kind of entry the store makes under that name. Never follow a link, never remove by age or by a start time `ps` prints, which moves with the time zone, the locale and the clock, and never remove a name the sweep cannot parse; a sweep that may remove more than that deletes a live call's index.
- Never read a stray entry's bytes into a record, and never rewrite or remove one. A commit carries it along by its object ID.
- A failure to reach or answer from the remote is `RecordError` `unreachable`; never answer from a tree read in part.
- A git command that writes more standard error than core's `git` keeps is stopped, and the call fails as `unreachable`, naming the command. Core never hands back a cut message, so a remote that prints `couldn't find remote ref` or `cannot lock ref` and then floods is never read as an absent branch or a held lock. A push stopped this way may have landed, as the rule above says.
- The location rule protects what a call reads, not whether the store stays available. Every call fetches every blob of the tip before it judges any, so a writer who pushes a very large file to the branch can make every call slow or fail. A writer who deletes the branch does not make calls fail: every call reads it as empty, and the next write creates it afresh holding that write alone, so earlier records and disposal marks are gone. Rule 6 accepts that until [issue #463](https://github.com/melian-agent/melian/issues/463) protects the branch, as [the decision's table](../decisions/2026-11-14-git-record-store-refuses-by-location.md#what-one-call-uses-and-what-bounds-it) says. A fetch that runs out of time or disk fails as `unreachable`, naming the branch. Git writes each object whole, under its own hash, and writes the fetch's ref last, so a later call reads only what a whole fetch named. `test/fetch.test.ts` cuts a pack part-way; a full disk stops the fetch at the same point, before the ref, so it needs no test of its own.
- A call holds every record and cell of the tip in memory, so a tip whose records and cells total more than 256 MiB, `tipLimit`, fails the call as `unreachable`, naming the branch, the total and the limit, before it reads a blob. A blob counts at every path it sits at, since each path's record or cell is held apart: one cell's bytes copied into many changesets' folders count once per folder. The read itself stops at the bytes the sizes git reported. The limit bounds bytes, not the heap: a call holds each blob as bytes, text and parsed objects, so it uses several times the total. The limit is provisional: [issue #455](https://github.com/melian-agent/melian/issues/455) designs a read that does not hold the whole tip, with [issue #361](https://github.com/melian-agent/melian/issues/361).
- A call holds every entry of the tip too, so a tip of more than 65,536 entries, `entryLimit`, fails the call as `unreachable`, naming the branch, the count and the limit, before it reads a size. The listing is bounded first: git is stopped once it prints 64 MiB, `listingLimit`, a KiB a line on average, and the call fails the same way. A write measures the commit it built by both limits before it pushes, and again after it rebuilds on a tip that moved, so no write of Melian's takes the tip past one; a write that would fails as `unreachable` and pushes nothing. Dispose only shrinks the tip, so it works at either limit, and making room before a write is its job. Past a limit, every call fails, dispose included, and a writer brings the tip back under by removing changesets or strays from the branch with git. A new resource a call takes goes in [the decision's table](../decisions/2026-11-14-git-record-store-refuses-by-location.md#what-one-call-uses-and-what-bounds-it), with what bounds it or who accepted it unbounded.

## Testing

- `test/fixtures/remote.ts` makes a bare remote in a temporary directory and opens handles with state directories of their own, as hosts are. `Remote.plant` commits entries by hand, as a writer outside Melian would.
- The fixture turns off git's automatic maintenance in the remote, which every handle pushes into. Newer git detaches it after a push, and a run that outlives the test fails the test's clean-up. The store starts none in `records.git`: its fetch passes `--no-auto-gc` and `--no-auto-maintenance`, and the plumbing it builds commits with runs none.
- A hook in the test remote runs, though `RecordRepository.run` passes `core.hooksPath=/dev/null`: git clears `GIT_CONFIG_PARAMETERS` for a local transport's `receive-pack`, so the client's `-c` settings never reach the remote. The flood tests rely on it, with a `post-receive` hook that writes past `stderrLimit`. Stand in for a slow or refused push with a spy on `RecordRepository.prototype.push` that calls the real push, or plants a commit, before it answers, rather than a hook whose timing races the push.
