# Enola

What Enola is, how it is built and shipped, and what a repository under review can do to its results.

Two projects share the name. [docs.enola.dev](https://docs.enola.dev) is an unrelated Java project, an agent runner and an RDF knowledge-graph toolkit, with no code analysis. This note is about [enola.tech](https://enola.tech) by [enola-labs](https://github.com/enola-labs/enola).

Sources: the [enola-labs/enola](https://github.com/enola-labs/enola) repository, its README, `ARCHITECTURE.md`, `LICENSE`, releases, and the `docs/` files `CLI.md`, `SNAPSHOTS.md`, `INTEGRATING.md`, `EXTENDING.md`, `LANGUAGES.md`, and `BLIND-SPOTS.md`; enola.tech's [reference](https://enola.tech/docs/reference), [workflows](https://enola.tech/docs/workflows), [change control](https://enola.tech/docs/change-control), [CI](https://enola.tech/docs/ci), and [examples](https://enola.tech/examples) pages; the blog posts on [graph memory](https://enola.tech/blog/what-a-code-graph-costs-in-memory), [package metrics](https://enola.tech/blog/package-metrics-on-enola), and [policy as code](https://enola.tech/blog/policy-as-code); and [enola-labs/enola-action](https://github.com/enola-labs/enola-action).

## What it is

A deterministic code-graph tool that runs locally, written in Go, Apache 2.0, copyright 2026 Dejan Menges. About 256 stars and 22 forks. It is pre-1.0: v0.4.26 shipped on 29 September 2026, releases come every two or three days, and commits are GPG-signed.

It ships as release binaries for darwin and linux on amd64 and arm64 with SHA256 checksums, a curl installer, `pip install enola-cli`, a RubyGem that downloads the checksum-verified binary on first use, a self-updating `enola upgrade`, and the GitHub Action `enola-labs/enola-action@v2`. Homebrew is unconfirmed; there is no npm package and no Docker image.

## The graph

Enola parses more than twenty languages, among them Go, Java, Kotlin, TypeScript and JavaScript, Python, Ruby, PHP, Rust, C and C++, .NET, Swift, and Dart, plus OpenAPI, gRPC, GraphQL, Terraform, and Ansible. Python, Ruby, PHP, Rust, and Dart go through tree-sitter and produce call and dependency edges. TypeScript has its own extractor, which reads `tsconfig.json` and `package.json` and knows monorepos, Next.js, and Express sub-routers. No matrix says which languages produce `calls` edges and which only import or route edges.

Nodes are modules, symbols, routes, storage, dependencies, and services. Edges are declares, imports, calls, implements, and depends_on. Nothing in the graph comes from a model, and output is byte-identical for the same commit and configuration.

The TypeScript extractor has a documented gap. `BLIND-SPOTS.md` describes a bug that silently dropped exact tsconfig `paths` aliases and left 4,847 call edges dangling in one monorepo. v0.4.21 and v0.4.26 were still fixing alias handling and caller attribution. The same file lists gaps on a Rails codebase, where tree-sitter misses edges made by metaprogramming; violations there go unreported rather than failing.

## Interfaces

The command line needs no MCP. `enola --generate <repo>` writes `.enola/` with `facts.jsonl`, `insights.json`, `receipt.json`, `snapshot.meta.json`, and `llm_context.md`, about 16K tokens. `enola check` takes `--format=text|json|sarif|annotations`, `--fail-on`, `--min-confidence`, `--focus`, and `--baseline`, and exits 0 clean, 1 on a regression, 2 on an error, and 3 when two snapshots are not comparable. `INTEGRATING.md` recommends running it as a subprocess and reading the artifacts, which carry a `format_version` that changes only on a breaking change. From Node, that means spawning the binary and parsing JSON or JSONL.

An MCP server claims 22 tools, among them `impact_analysis`, which returns everything that depends on a target grouped by hop count, to a depth of 1 to 10 and up to 500 nodes; `plan_check`, which takes paths, symbols, or a unified diff and returns the constraints that apply and the impact; `coverage_report`; `diff_snapshot`; `query_insights`; and `find_path`.

Built-in explainers cover cycles, layers, intent, constraints, cross-repository links, god classes, hotspots, dependency depth, dead methods, and unused routes. Package metrics are Martin's Ca, Ce, I, A, and D. Constraints are YAML under `enola/constraints/` in 21 rule forms, such as `forbid_reach`, `forbid`, `protect`, and `cap`. Each has a mode, strict, advisory, or ratchet, and a required `because`; an exemption records an owner and a date. A private Rails repository runs Enola in CI as an architecture gate, failing on cycle and constraint regressions against an intent file.

## Base against head

A snapshot ID is a SHA-256 over the facts, the Enola version, and the configuration hash; the receipt records the commit. To compare, pin the base with `baseline pin` or `--baseline=<path>` and run `check` or `diff_snapshot` against the head. Enola refuses with exit 3 when the Enola version, the repository identity, or the ignore configuration differs. The GitHub Action builds base and head and reports only what the pull request introduced.

## Cost

The Go heap needs about 3 KB per fact at peak and 0.7 KB while serving, at 10 to 25 facts per file. On an M4 Max, dotnet/runtime, 398K facts, peaked at 1.45 GiB; the Linux kernel, 1.89M facts, at 5.2 GiB; a small service took 374 ms and 13 MiB. Re-indexing an unchanged grafana tree took 4.8 seconds.

A private repository's review skill measured the alternative: a reviewer walking callers by search timed out at 600 seconds twice, and the same review fed Enola's callers finished in 331.

## What the repository under review controls

`EXTENDING.md` says extractors are compiled in, nothing is loaded dynamically, and no code is executed. The repository still supplies configuration that changes what Enola reports:

- `enola.yaml` or `mcp-arch.yaml`: ignore globs, and a `linking:` section that can remove an edge.
- `enola-intent.yaml`: the declared layers.
- `enola/constraints/*.yaml`, including `exempt:` entries.
- `.enola/suppressions.yaml`.
- tsconfig `paths`.
- Any committed `.enola/baseline/`.

A pull request can add an exemption or a suppression, loosen a rule, or ignore its own files. The documentation does not say whether the Action reads configuration from the base or the head.
