# Request keys hold the installed packages each producer runs

For [issue #470](https://github.com/melian-agent/melian/issues/470), each producer's key now holds `packages`, a digest of every installed package beneath what its code imports. The lens run keys the packages beneath pi-ai and Pi Durable, in place of their two versions. A run offered `list_mutants` keys the instrumenter's packages, Babel included. The checks and adjudication key the packages their own modules import as they load. The coordinator chose the approach on 2026-11-20 and [recorded it on the issue](https://github.com/melian-agent/melian/issues/470#issuecomment-7028716067); [the decision](../decisions/2026-11-20-keys-hold-installed-packages.md) holds it, and the identity guideline's rows for the lens request, the adjudication key and the check request say what each leaves out and what a miss costs.

`scripts/code-hashes.mjs` records which packages each producer imports, from Node's resolver while the producer's entry loads in a child process, and the gate fails when the record drifts. At run time `installedPackages` walks from those imports with `findPackageJSON`. A package that does not resolve, or a manifest that cannot be read, fails the key and names the package.

The failing test came first. On main at 56f7fb059, a lens request and a check request kept their keys when a package beneath pi-ai, or `yaml`, moved; on the branch both keys change.

`adjudication-key-reopen.test.ts` reopens a version 8 task that main's own code left pending, captured by `capture-pending-8.mjs` from `git archive 56f7fb059`. It fails, and the next review decides again with no model call. In the other direction, main's code at 56f7fb059 resumed a pending task this build wrote with `packages`: it failed on its `code` check, made no model call and did not crash, since the task has no input schema. So `packages` takes no task version, and [issue #562](https://github.com/melian-agent/melian/issues/562) keeps version 9.

The coordinator chose on 2026-11-20 to stop keying what each producer's imports reach, after Melian's round at `da6be0769` and Codex's fifth review found three more layouts the walk missed: a platform build's own dependencies, an entry in a nested package, and an npm alias, which failed every review. `fd8410ed0` keys one digest of Melian's whole install instead: every copy and every link in the `node_modules` trees Node searches beneath the install root, read with no link followed, bounded at 50,000 directories. It removes the walk, the dependency-field rules, the platform shortcut, the per-producer roots and the import record in `code-hashes.ts`, and keeps the place lines, the link lines and the outside-link handling. Codex's precedence finding goes with the dependency-field rules it was about. A link out of the install now keys a fixed line and leaves the install unidentified; checks, lenses and adjudication then reuse nothing, through `checkReusable`, `runLenses`'s `reusable` and the adjudication attach, and identity rule 6 stands unamended. [The decision](../decisions/2026-11-20-keys-hold-installed-packages.md) states the guarantee and what it gives up: any install change reruns everything, a dev dependency's included, which in this repository is 20 of `main`'s last 299 commits.

The failing tests came first. Against main's walk at 56f7fb059, a scratch test showed the hand-made nested `node_modules`, the platform build's needs, the nested entry and a moved dev dependency each keeping the digest, and the alias failing the key. All seven collisions and the alias are named tests in `installed-packages.test.ts`, each passing on `fd8410ed0`. Writing the static-proof cases found that `checkReusable` read `"yes" && true` as `true`; it now compares each install flag to `true`. Each place that carries the flag has a test that two reviews on one unidentified install share a key and reuse nothing.

Codex's sixth review, of `fd8410ed0`, found that the text lines could be forged: a link to a directory named `nowhere` wrote the line of a link that names no directory, a space in a place moved where a link's target began, and an `@` in a manifest's name moved where its version began. The coordinator chose the structured form on 2026-11-20. `543ee4417` keys each place as a list of strings and hashes core's `canonicalJson` of the sorted list, so no field can stand for another. Each forgery is a named test that gave equal digests on `fd8410ed0` and passes now.
