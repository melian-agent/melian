[Pull request #314](https://github.com/melian-agent/melian/pull/314), the high finding in Codex's adversarial review of d03f2750.

- Only a publication of a pull request's legacy SQLite storage took the copy lock, through its reservation, so a review, a dismissal, a comparison write or a read in the same clone could open the storage while a publication posted from it, and replace the verdict it was posting. Every command on legacy storage now takes the copy lock that a checkout of the pull request would take, in the copies' directory, and releases it when it closes or when the storage cannot be opened; a publication's reservation holds it instead of a second one. state-git exports `CopyLock` for this.
- `refuses a write of legacy SQLite storage in the same clone while a publication holds it`, `refuses a read …` and `refuses a publication of legacy SQLite storage while another command in the clone writes it, and lets it in after` failed first on d03f2750. Removing the lock from writes, from reads, its release on close, or its release when the storage cannot be opened each fails a named test; the last needed `releases the lock when legacy SQLite storage cannot be opened for another command`.
