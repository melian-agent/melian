# Melian's git reads no replacement objects

For [pull request #525](https://github.com/melian-agent/melian/pull/525), on [issue #502](https://github.com/melian-agent/melian/issues/502). Codex's review of #525 at `cda4c916` found that a ref under `refs/replace/` could put a looser `melian.yaml` behind a full commit ID. The maintainer ruled on 2026-11-17, in the coordinator's session, that every git call Melian makes runs with replacement objects off, in a pull request of its own. [The decision](../decisions/2026-11-17-git-reads-no-replacement-objects.md) records it.

Failing test first: at `origin/main`, the two new tests in `packages/core/test/replace-objects.test.ts` and the new test in `packages/cli/test/repository.test.ts` failed. Each read `P2: advisory`, the replacement's policy, for the original commit's ID. `b8890115` sets `GIT_NO_REPLACE_OBJECTS=1` in core's git environment and the CLI's git helper, and the four affected files then passed, 74 tests.

Mutants: the enumerator lists `git.ts` as unmutated, since it sends signals. Its only signalling is a bare `ChildProcess.kill()`, and `grep` finds no `process.kill` or signal name, so its mutants came from the instrumenter, under the ruling of 2026-11-16. There are two on the changed line. `{}` is killed. `""` is equivalent: git turns replacement off whenever the variable is present, and an empty value or `0` read the original commit on git 2.43. `repository.ts` has four generated mutants, all killed by its new test, and two string literals the configuration ignores. Each mutant ran by hand at `b8890115`, against its named test alone, which passed unmutated first. The inventory is `2026-11-17-git-reads-no-replacement-objects-mutants.json`.

A review briefed as unit tests checked replacement under another ref base, grafts, shallow files, alternates, a mislabelled object, a forged commit-graph, and caller variables. In each case it built a clone and asserted which tree Melian read. The decision lists what each does. None changed the policy `loadConfig` reads for a full ID. Its tests stay out of the repository, since several pin how one git version treats deprecated features.

Second pass, after Codex's review at `32ceb5ab`. The static checks' own git helper, in `packages/pipeline/src/static.ts`, still honoured `refs/replace`. So `git worktree add <commit>` checked out the replacement's tree, and Biome, tsc, Enola and the mutation check ran on it. Failing test first: at `32ceb5ab`, a new test in `static.test.ts` read the replacement's `a.ts` from the static worktree. `2fe1af20` sets the variable in that helper's command, and the static suite passed, 43 tests. `static.ts` is on the enumerator's signal list, so its two mutants on the changed line came from the instrumenter. Both change only the git command string and touch no pid or signal code. They ran here in a cloud container, against that test alone, which passed unmutated first. The emptied command is killed. `join("")` is equivalent: the shell runs with only `PATH`, `HOME`, `TMPDIR` and `LANG`, so no `GIT_` variable reaches it for the `unset` to remove.

Third pass, after Codex's review at `4c0edcc6`. Store prune removed every `GIT_` variable from its environment, `GIT_NO_REPLACE_OBJECTS` with them, so a replacement ref resolved a live commit to another tree, and `melian store prune --apply` would remove the live tree's graph and coverage once they were seven days old. The decision had said prune decides nothing by a tree, which was wrong. Failing test first: at `4c0edcc6`, a new test in `store-prune.test.ts` planned to remove the live commit's graph. `cdea711f` sets the variable after the filter, and the two store-prune suites passed, 75 tests. Store prune removes stored caches, so its mutants owe a hand proof. The enumerator lists six generated mutants on the changed lines, which a formatting pass rewrapped. Each ran by hand at `cdea711f`, in a worktree of its own, against its named test alone, which passed unmutated first, and all six are killed. The emptied filter first ran against the variables test and survived, since git still starts with no `PATH` in its environment; the test of a `PATH` with no git kills it. The inventory is `2026-11-17-git-reads-no-replacement-objects-prune-mutants.json`. The decision now names store prune, and links [issue #539](https://github.com/melian-agent/melian/issues/539) for the two follow-ups, which stay unfixed here.
