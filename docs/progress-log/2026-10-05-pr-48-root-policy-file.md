[Pull request #48](https://github.com/melian-agent/melian/pull/48) closes the gap [#42](https://github.com/melian-agent/melian/pull/42) left in the rule that no `melian.yaml` switches off the review of itself. A nested one was judged under the configuration of the directory above it, but the root's has none, so it was judged under its own settings, and a root that switched policy-change-review off hid every edit to itself. `policyChanges` now judges the root `melian.yaml` under its own configuration with the defaults as a floor: the guardrail stays on for that file, and its severity is the stricter of the root's and the default `P2`, so a root can make the review of itself stricter but never switch it off or soften it. What the root sets still governs every path beneath it. The pipeline resolves a policy-change-review finding under the configuration that judged it, and `resolveFinding` never resolves one on a `melian.yaml` below `acknowledge`, so no `melian.yaml` silences the review of a change to itself. [The decision](../decisions/2026-10-05-root-policy-file-review-floor.md) records the choice.
