# Core's git stops once its standard error passes 4 MiB

[Issue #469](https://github.com/melian-agent/melian/issues/469): core's `git` runner capped standard output with `maxBytes` but kept standard error whole. A fetch or a push carries there whatever the remote or a credential helper sends, so a remote that wrote without end could fill memory inside any deadline. [Pull request #472](https://github.com/melian-agent/melian/pull/472) keeps at most `stderrLimit`, 4 MiB. One byte past it, the runner kills git by the pid it spawned, closes its own end of the stream, and rejects with `ChangesetError` `gitOutputTooLarge`, naming the subcommand and the limit. It never resolves with a cut message, because callers match git's message to recognise a missing remote ref or a held lock. A survey of the whole test suite, 111,982 git calls, found none that wrote more than 250 bytes to standard error.

The one-past test failed on the unbounded code: the runner resolved, and no error came back. The two tests that write without end were not run against that code, since there they exhaust the test process's memory. `melian mutants list` sets `git.ts` aside because it sends signals, so the mutants came from `scripts/instrument-mutants.mjs`. Each of the 21 mutants on changed lines ran against its one named test. Twenty were killed. The survivor removed `clearTimeout` from `stop()`, a call that changed nothing, since every ending reaches `finish`, which clears the timer. `d3c16c12` deletes that call, and the rerun of `stop()`'s five mutants killed all of them. The rows, with the head each ran at and its named test, are in [2026-11-15-pr-472-hand-mutants.json](2026-11-15-pr-472-hand-mutants.json).

Testing the record store against the bound showed that a stopped command's error named the repository path where the subcommand belongs. Core's `subcommand()` skipped the value only of `-c` and `-C`, and the store runs every command with `--git-dir <path>` first, so a failed store command's message read `git /path/to/records.git failed`. `8f3de199` skips the value of `--git-dir`, `--work-tree`, `--namespace` and `--config-env` too. Its four new cases failed on the old code, naming the option's value, and pass after it. `subcommand()`'s 22 mutants, again from the instrumenter, are all killed. Two of them turn the loop into one that never ends. Each hung its named test alone past 60 seconds, and the runner stopped the processes it had recorded, by pid. Those rows are in the same file.

[Pull request #433](https://github.com/melian-agent/melian/pull/433) landed the record store on `main`, and this pull request merged it. [The amendment](../decisions/2026-11-15-git-bounds-its-standard-error.md) retires the decision row that left git's standard error unbounded. [The store's entry](2026-11-15-pr-472-record-store-bound.md) records how the store reads a stopped command, and the tests that a cut stream is never read as an absent branch or a held lock.
