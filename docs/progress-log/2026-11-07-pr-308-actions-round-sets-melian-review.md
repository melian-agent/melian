An Actions round now sets `melian/review` on the head it reviewed, so a builder can mark its pull request ready and queue it without the coordinator, on [pull request #308](https://github.com/melian-agent/melian/pull/308) for [issue #304](https://github.com/melian-agent/melian/issues/304). [Pull request #300](https://github.com/melian-agent/melian/pull/300) showed the gap: its round found nothing blocking, and it still waited for the coordinator's `melian publish`. The report job re-reads the pull request and sets `success`, `failure` or `error` from the round's verdict, in the shape `melian publish` uses. It uses a machine user's token that only the `melian-round` Environment holds, by the maintainer's ruling, so the merge group copies the status as a writer's and no branch's workflow can forge one it accepts. An acknowledge finding does not fail it; the builder asks the maintainer to read such findings first. 79 enumerated mutants and 8 hand mutants of the step are each killed by their named test alone, recorded in [2026-11-07-pr-308-mutants.json](2026-11-07-pr-308-mutants.json).
