[Pull request #310](https://github.com/melian-agent/melian/pull/310), fixes for the Actions round on 097409fe, [run 42529237499](https://github.com/melian-agent/melian/actions/runs/42529237499), and an own-build round run in the builder's session, under the maintainer's rulings of 2026-11-08.

- P1, hooks: state-branch git commands ran the clone's hooks, which a head can supply through `core.hooksPath`, with the review's environment and its credentials. Every state-git git command now runs with `core.hooksPath=/dev/null`, and core's `gitOutput` and `gitOutputBytes` take options so the read commands carry it too. `runs no hook of the clone's, which a head can supply, while it fetches, pushes or moves a ref` failed first on 097409fe, with `pre-push` and `reference-transaction` both run. Leaving the key out of the count, or `update-ref` without the environment, fails it; an empty path is equivalent, since git then finds no hooks either.
- P1, the holder label: a live lease of the caller's own `holder` label was taken over as a crashed run's, though another copies directory, under another copy lock, could give the same label. As the maintainer ruled, the branch mints the clone's identity itself: an unguessable ID in the copies directory's `holder` file, written owner-only, which the CLI already kept there. A lease names its clone by the label and that ID, so the label is now 1 to 163 characters. `refuses a live lease to a branch of another copies directory, though its label is the same` and `keeps one identity for a copies directory across branches, so a crashed run's lease is taken over` failed first on 097409fe; `refuses a copies directory whose clone ID was damaged, rather than mint another` covers the guard. Judging by the label, accepting any ID, a readable ID file, or dropping the ID from the lease each fails a named test. Eight older tests named the clone by its label alone, or listed the copies directory without the ID file; each now matches the label and ID, and the label bound moved from 200 to 163.
- P1, a push its deadline stopped: git's transport can finish a push after the deadline stops git, so the branch could move after Melian reported `pushFailed`. As the maintainer ruled, a push stopped at its deadline fetches the branch again, and counts as landed when the tip is the commit it sent. `counts a push its deadline stopped as landed when the branch's tip is the commit it sent` failed first; `names a push its deadline stopped when the branch cannot be read again to see whether it landed` covers the other side. Dropping the re-read, always counting it landed, or letting the second fetch's failure through each fails a named test.
- P2, two vacuous tests:
  - The deadline test asserted only that the promise resolved, so a deadline that stopped waiting without stopping git passed. `stops the git process itself, not only the wait for it` reads the git process's own pid from its transport, through `ps`, checks it is a real pid above 1, and waits for it to be gone. Removing `child.kill()` fails it.
  - The filename cases planted unsealed blobs and asserted only `invalidBranch`, which a failed decryption also gives, so a name check that accepted leading zeroes survived. They now assert the name refusal's own message, and both the branch's and the copy's cases include `doc-01.jsonl` and `task-01.jsonl`. Allowing leading zeroes fails five of them.

Fixes for the Actions round on 8ae33370, [run 42561642932](https://github.com/melian-agent/melian/actions/runs/42561642932):

- P2, a race on the clone ID: two first checkouts of one copies directory could race on its `holder` file. An exclusive create leaves the file empty until its ID is written, so the second read it empty and failed with `invalidHolder`. The ID is now written whole to a file of its own and linked into place, which fails when another run linked first. `gives two first checkouts of a copies directory the one clone ID, though the first is slow to write it` makes the first writer pause with its file empty, and failed first on 8ae33370. Rethrowing a lost link, or leaving the minted file behind, each fails a named test.
- P2, the main-log comparison untested for equal lengths: every damage case deleted or cut the log, so dropping the byte comparison survived. `refuses at checkout a main log of the branch's length but other bytes, though the storage opens it` and the same at push accept any bytes in the storage, so only the comparison decides; dropping it fails both.
