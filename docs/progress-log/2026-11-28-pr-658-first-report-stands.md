# Pull request 658 keeps a claim's first verifier report

Builder agent, for [pull request #658](https://github.com/melian-agent/melian/pull/658) and [issue #657](https://github.com/melian-agent/melian/issues/657).

A verifier that reported one claim twice lost its first report: a later unlowered report at an equal verdict replaced it whole, so a placeholder reason such as "Duplicate placeholder; see the lowered report." became the finding's only reason and could undo a lowering. The maintainer agreed both changes on 2026-11-28, in the coordinator's session. `VerificationRecord.refusal` in core now refuses a later report of a claim unless its verdict is stronger, and takes a replay of the stored one; `upsertVerification` applies it in the report's commit, so a refused report writes nothing. `report_verdict` refuses a lowering with no evidence at the head in `prepareArguments`, before anything is stored, so the verifier can send its one report again. [The decision](../decisions/2026-11-28-a-claims-first-report-stands.md) replaces the old rule, and the tests and verifier goldens that pinned it change with it, as the pull request lists. The failing tests came first, in 5f24cce08; the fix is 2947dccb0, and 181057aa8 moves the goldens and the older tests to the new rule. [The inventory](2026-11-28-pr-658-first-report-mutants.json) at 181057aa8 lists 47 mutants of the three trust files and `code-hashes.ts`: 37 generated and 10 string mutants the configuration ignores. All 37 claim a kill by a named existing test, and all 37 were run by hand at 181057aa8, each against its named test alone, which passed unmutated with one test collected and failed mutated.

A later round, [run 46105212847](https://github.com/melian-agent/melian/actions/runs/46105212847), found that the rule also froze a claim's sameness answers. A verifier that answered `same` for a dismissed finding, then read further and answered `different` at the same verdict, was refused, and the live finding inherited the dismissal against its last judgement. The maintainer ruled on 2026-11-28, in the coordinator's session, that `different` from any report of a claim wins ("A"). 9f6a71f54 makes it so: `VerificationRecord.after` keeps a `different` answer from either report, a later report at an equal or weaker verdict is taken for a `different` answer the stored report lacks and keeps nothing else, and `report_verdict` says only that answer was kept. Before the fix, each new test failed at 63751cb04 for the reported reason: the correcting report was refused, and in `restatement.test.ts` the restated finding left the attention set. [The second inventory](2026-11-28-pr-658-different-wins-mutants.json), over 63751cb04...9f6a71f54 with claims in `packages/core/src/verification.ts` and `packages/pipeline/src/findings.ts`, lists 54 mutants in those files: 49 claim a kill by a named test, one is equivalent, and four are string mutants the configuration ignores. All 49 were run by hand at 9f6a71f54, each against its named test alone, which passed unmutated with one test collected and failed mutated.

The next round, [run 46147132647](https://github.com/melian-agent/melian/actions/runs/46147132647), found that a replay of the correcting report was refused with a message saying the first report stands, though its `different` answers were already stored. The coordinator answered, as a coordinator's answer and not a ruling, that the message should say they are recorded. 75f2750a4 adds that clause when the refused report gave a `different` answer; before it, the new test in `packages/core/test/verification.test.ts` failed at cf10d7fec on the missing clause. [The third inventory](2026-11-28-pr-658-replay-message-mutants.json), over cf10d7fec...75f2750a4 with claims in `packages/core/src/verification.ts`, lists six mutants: one generated, which claims a kill by that test, and five string mutants the configuration ignores. The one was run by hand at 75f2750a4 against its named test alone, which passed unmutated with one test collected and failed mutated. cf10d7fec fixes the core guideline, which still gave the first-report rule alone.
