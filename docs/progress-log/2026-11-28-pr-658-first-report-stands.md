# Pull request 658 keeps a claim's first verifier report

Builder agent, for [pull request #658](https://github.com/melian-agent/melian/pull/658) and [issue #657](https://github.com/melian-agent/melian/issues/657).

A verifier that reported one claim twice lost its first report: a later unlowered report at an equal verdict replaced it whole, so a placeholder reason such as "Duplicate placeholder; see the lowered report." became the finding's only reason and could undo a lowering. The maintainer agreed both changes on 2026-11-28, in the coordinator's session. `VerificationRecord.refusal` in core now refuses a later report of a claim unless its verdict is stronger, and takes a replay of the stored one; `upsertVerification` applies it in the report's commit, so a refused report writes nothing. `report_verdict` refuses a lowering with no evidence at the head in `prepareArguments`, before anything is stored, so the verifier can send its one report again. [The decision](../decisions/2026-11-28-a-claims-first-report-stands.md) replaces the old rule, and the tests and verifier goldens that pinned it change with it, as the pull request lists. The failing tests came first, in 5f24cce08; the fix is 2947dccb0, and 181057aa8 moves the goldens and the older tests to the new rule. [The inventory](2026-11-28-pr-658-first-report-mutants.json) at 181057aa8 lists 47 mutants of the three trust files and `code-hashes.ts`: 37 generated and 10 string mutants the configuration ignores. All 37 claim a kill by a named existing test, and all 37 were run by hand at 181057aa8, each against its named test alone, which passed unmutated with one test collected and failed mutated.
