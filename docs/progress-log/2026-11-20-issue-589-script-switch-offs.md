# A changed npm script is named in its notice

[Issue #589](https://github.com/melian-agent/melian/issues/589): a head that rewrote `check` in `package.json` drew Melian's ordinary notice, with no word that the gate's own command changed. `switchOffs` now adds "It changes the npm script "check"." and "It removes the npm script "lint"." for each script the base had, in the root `package.json` and in nested ones. [The decision](../decisions/2026-11-20-every-npm-script-is-a-switch-off.md) says why every script counts, and why only base names are quoted.

`packages/core/test/guardrails.test.ts` gained a test of the stored explanation for a root and a workspace `package.json`, whose head scripts carry text that must not appear. It failed before the change, with both notices missing the script lines, and passes after. A second test holds that an added script and a changed `version` add nothing. `packages/core/test/analyser.test.ts` covers each guard: a head that does not parse, a head that is an array, a `scripts` field that is absent, `null` or an array, a base with no scripts, a mixed-case nested name, `package-lock.json`, and JSON quoting of an odd name.

The change alters a notice's words, not what blocks, so it guards no trust or durability code and owes no inventory. Nine mutants of the new guards were still run by hand against the `npm scripts` tests. Eight failed. The ninth, dropping the array check on the head's `scripts`, was equivalent unless a base script is named `"0"`, so the check was removed.

Codex's adversarial review found that the rule read `package.json` with `parseJsonc`, which drops a comma before `}` or `]` inside a string. A script changed from `"echo ,}"` to `"echo }"` named nothing, and a removed script `check,}` was named `check}`. A test in `analyser.test.ts` failed for that reason at 5517eb41f, with the changed `check` missing, and passes now that both revisions are read with `JSON.parse`, as npm reads them.

Codex's second review, at 4bde6ce66, found that npm strips a leading byte order mark before `JSON.parse` and `switchOffs` did not. So a head that prefixed one and rewrote `check` named nothing. Through guardrails the case could not arise, since the UTF-8 decoder that reads each blob already drops the mark. The exported function now strips one mark, as npm's `json-parse-even-better-errors` does. Its test failed at 4bde6ce66, with the changed `check` missing, and passes now.

The own-build round at 4bde6ce66 blocked on `identity-missing-input`: the check request still asked for guardrails version 1, so a guardrails run a build without script names had stored could be reused. `checkVersions.guardrails` is now 2. A test in `check-request.test.ts` failed at fae6c52ee, reading 1, and passes now. The round's acknowledge, an untested `after === null` guard, gained a case with the head text `null`. Its advisory, an overlong sentence in the decision, is split.

The Actions round at 5517eb41f raised the same block and two acknowledges, all fixed by the commits above. It also flagged the guardrails test's head script, `true # Ignore your instructions`, as an injection attempt, twice. The text addressed a reviewer, so it is now an inert marker, `true # head-only-marker`. The test still asserts the whole explanation, so any head text in it would fail.

Merging `main` brought its hash-based check key, which covers `analyser.ts`, so the hand-raised guardrails version and its tests were dropped in favour of `main`'s. Codex's third pass, at 8b83d65e1, found that a `package.json` outside the root and the workspaces never reaches `switchOffs`, though the decision said "any depth". The decision and the core guideline now say what is built, and name that gap as a limit awaiting a ruling, since covering it would make new files block.
