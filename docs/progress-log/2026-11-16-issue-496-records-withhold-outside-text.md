# Shared records withhold text a tool, a provider or the head wrote

For [issue #496](https://github.com/melian-agent/melian/issues/496), by the coordinator's answer of 2026-11-16 on approach. `ReviewRecords` copied each check's reason, error and notes into its record, along with a lens's or a verifier's reason, error and caveats, and a triage failure. `failure()` in `packages/pipeline/src/checks.ts` fills a failed check's error from the thrown message, and Stryker's and Enola's messages embed their tools' output, so a login a head's tests printed could reach a record any reader of the store fetches.

[The outside-text decision](../decisions/2026-11-16-shared-records-carry-no-outside-text.md) sets the rule: each string field of a record is an ID, key or hash, a code from a closed set Melian defines, a repository path, or a finding's own text. The export now keeps a reason or an error only when it is such a code, and writes a fixed sentence, `withheld`, in its place otherwise. It writes a check's notes empty, and keeps only Melian's two fixed caveats. A failed check's reason that is no code becomes `unexpected`. The full text stays in the reviewing host's store and terminal. No verdict changes, since a verdict decides from names, statuses and the account's skips. A reader of records shows the fixed sentence where it showed the host's text.

`test/review-records-withheld.test.ts` feeds a made-up token through every outside-text input of each record kind: check results of every status, a lens's outcome and its decided check, a verification's candidates and check, a triage failure, and an account's filled checks. At 4adc374f all eight leak tests failed with the token in the record's bytes. With the fix they pass, beside tests that hold each code of the closed set and the exact withheld forms. The tests that held a reader's verdict to the host's whole verdict now go through `test/fixtures/shared-verdict.ts`. It compares every other field whole, and allows only the fixed sentence, or `blindCallers` for a caveat, where the host kept text.

The [mutant inventory](2026-11-16-issue-496-withheld-mutants.json) lists the 65 mutants of commit 1366b09f, none omitted. The 29 string-literal mutants are ignored by configuration. Each of the 36 generated mutants was run by hand against its named test in `test/review-records-withheld.test.ts` alone, after that test passed unmutated, and all 36 were killed. Two survived the first pass, at `review-records.ts:480` and `:482`, because no test held an exhausted lens outcome's exact form. A test of it, added before this entry, killed both. The test of a verifier's outcomes now passes them out of order, so removing their sort fails it.

Codex's review of [pull request #524](https://github.com/melian-agent/melian/pull/524) found that the decision's four kinds of string left out a walkthrough's prose, which a record exports as written. The decision now names a walkthrough's summaries, diagram and note as review content beside a finding's text, which a head can steer and which can quote it; no behaviour changed. A test pins the walkthrough fields a record exports. Adding a field to `Walkthrough` or to its file entries fails `tsc` on that test, and exporting `note` as null fails it at run time; each was run by hand.
