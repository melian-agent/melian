[Pull request #310](https://github.com/melian-agent/melian/pull/310), fixes for Melian's Actions round on 325383fc, [run 42477347414](https://github.com/melian-agent/melian/actions/runs/42477347414), under the maintainer's rulings of 2026-11-08.

- P1 and two P2s, the transfer bound: git's `http.lowSpeed*` limit counts throughput, so a remote that drips a byte a second never trips it, and SSH ignores it. Core's `git` takes a `deadlineMs`; once it passes, it stops the git process it started, by the pid it spawned, and resolves at once with `timedOut`, since a transport such as ssh can hold the output pipes open after git stops. state-git runs every fetch and push under `transferMs`, two minutes by default, and names a fetch or push that ran past it. `stops git once the deadline passes, and says it timed out` timed out first; `stops a fetch that runs past its deadline, whatever the transport, and names it` uses git's `ext::` transport over a command that never answers. `gives every fetch and push a deadline of two minutes by default` and `names a push that ran past its deadline` cover the rest. Ignoring either timeout, the option, or the deadline, or moving the default, each fails a named test. `core/src/git.ts` stays unmutated, as it sends a signal; its tests use a real git process the test started.
- The backoff test's `setTimeout` fake ran every timer at once, the deadline's too, so it now shortcuts only the waits of a second or less.
- P2, a shared fetch ref: every fetch of one `StateBranch` wrote `refs/melian/state/<run>`, so two operations of one run on different changesets, each under its own copy lock, could delete the ref under each other. Each fetch now writes a ref of its own. `checks two changesets out through one branch at once` failed in two rounds of three on 325383fc with `git rev-parse failed: fatal: Needed a single revision`, and passes in all three.
- P2, a vacuous test: `refuses a file moved to another changeset or name on the branch` read the sealed blob as Latin-1 and wrote it back through git's UTF-8 input, which corrupted the ciphertext, so it passed whether or not a seal is bound to its place. It now transplants the exact bytes, to another changeset and to another valid name. Sealing without binding the name, as additional authenticated data, fails both cases.
