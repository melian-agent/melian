The eleventh review of [pull request #74](https://github.com/melian-agent/melian/pull/74) found that renaming a root .env file bypassed its read deny. A file-write* deny now protects the worktree and checkout paths after all write allowances. It names both each literal path and its resolved target, so a symlink cannot be moved either. Profile tests pin the ordering and both names. Sandbox tests attempt reads, renames, removal and creation using synthetic files in the throwaway repository.
