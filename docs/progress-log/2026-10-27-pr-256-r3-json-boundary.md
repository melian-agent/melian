# Step 23 build 3: preserve the final JSON escaping boundary

The second review of [pull request #256](https://github.com/melian-agent/melian/pull/256), for [issue #231](https://github.com/melian-agent/melian/issues/231), reproduced raw reviewer controls after membership was added to an escaped comparison record. Parsing the comparison JSON decoded its escapes; the final serialization emitted raw bidi and C1 controls. The CLI now reapplies core `visibleText` to each line after that last serialization, before either stdout or file output. A genuine build-1 SQLite fixture and current writers cover all 79 unsafe code points in reviewer keys and values, snapshot diagnostics and audit history. Both output destinations fail before the fix and pass after it. Parsed values, literal escape text, indentation and structural newlines remain intact, and Markdown stays safe. This restores the existing escaping contract without changing a core API, stored shape or JSON format.
