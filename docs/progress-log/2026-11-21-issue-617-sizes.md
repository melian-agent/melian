# Issue 617, pull request B: report melian/state's size

Builder agent: this is the second of three pull requests for [issue #617](https://github.com/melian-agent/melian/issues/617). It reports how much the tip of `melian/state` holds against each of the store's three limits, and warns past half of any, as the maintainer ruled on 2026-11-21. The limits are 65,536 entries, 256 MiB of records and cells, and 64 MiB of listing.

`GitRecordStore.size()` measures the tip as every read does, with the same listing and the same size lookup, and reads no blob. It answers on a tip past a limit, where every read refuses, since that is when the numbers matter most. A listing that passes its own limit is stopped there, so the size says so and counts nothing else. `TipSize` holds the counts, their line and the warning. It lives in a module that imports nothing, so the round's comment script reads it on plain Node, and the store, doctor, the command and the comment all use one set of words.

Three places show the size:

- `melian doctor` prints a `tip size` line after the record store's line, every time. Past half of a limit it warns and names each measure. On a tip past a limit, the record store's line says the branch is unreachable and the size line beside it gives the totals.
- `melian records size [--json]` prints the line, or the counts as JSON.
- The `melian round` workflow's report job, which runs no head code, reads the size with the default branch's build. It holds no token, since the branch is public. The comment reads the counts back through `TipSize.parse`, which accepts whole numbers alone, so no text from the branch reaches it. Past half of a limit the comment adds doctor's warning, and below half it adds nothing. A size it cannot read gets "melian/state's size could not be read", and the comment still posts.

Until pull request C adds the prune, the warning says that nothing removes records yet and links the issue, so it names no remedy that does not exist. Pull request C adds the prune's sentence back. A listing past its limit reads "not counted", and the warning there says the listing was too large to read and so the store is past its listing limit.
