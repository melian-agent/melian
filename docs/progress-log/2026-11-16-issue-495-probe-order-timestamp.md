The probing level's test that probes run one at a time failed on every macOS machine, because each probe logged its start with the shell's `date +%s%3N` and macOS `date` has no `%N`, so the gap read as NaN whatever the code did ([issue #495](https://github.com/melian-agent/melian/issues/495)). The test now takes each start time from Node, `process.execPath -e 'console.log(Date.now())'`, and checks that the log holds exactly two finite numbers before comparing them. On Linux it passes, and it fails with a gap of 13 ms when `run_probe`'s `executionMode` is switched to `parallel`. `packages/pipeline/test/probing-level.test.ts` joins the named suites of the `check (macos, 24)` job in `../../.github/workflows/check.yml`, so CI proves it on macOS, and that job's guard that the Linux report shows a skipped test now counts six named files, not five. AGENTS.md's Learnings records the lesson.
