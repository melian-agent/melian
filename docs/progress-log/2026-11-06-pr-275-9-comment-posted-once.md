A rerun of the `melian round` workflow's report job now updates the comment its run already posted, in fix pass 2 of [pull request #275](https://github.com/melian-agent/melian/pull/275). Melian's round on fix pass 1 found that the job always created a comment, so a post GitHub accepted before the job failed would be posted again by "Re-run failed jobs", against the design's rule that every step reruns safely. Each comment now opens with a marker naming its run. Before posting, the job lists the pull request's comments, and `scripts/round-own-comment.mjs` finds one that `github-actions[bot]` wrote under this run's marker, which the job then updates. A comment by anyone else never counts, and comments that cannot be read fail the job rather than post twice. No local test can make GitHub accept a post and then fail the job; a dispatched rerun stands in, and the script's tests prove the rule.
