[Issue #481](https://github.com/melian-agent/melian/issues/481): a dismissal lived only on the machine where `melian dismiss` recorded it. Another host reading the same record store saw the finding live and blocking.

A review's export now adds a dismissal record for each finding the findings document holds dismissed with a frozen sighting. Every field comes from what `melian dismiss` stored, its time and head included, so exporting twice writes the same bytes and the same ID. A candidate's dismissed roots carry their records' IDs, and the verification request, and so its key, includes them; the verification record lists them in `dismissals`. `RecordedRound` reads every counted dismissal record of the changeset, takes the latest for each finding, and reads the finding dismissed while every sighting still meets the record's trigger under `reopens`. [The new decision](../decisions/2026-11-16-a-dismissal-record-holds-what-melian-dismiss-stored.md) amends the shared record decision's rule 2.

The maintainer ruled on three points on 2026-11-16, in the coordinator's session, recorded [on the issue](https://github.com/melian-agent/melian/issues/481#issuecomment-6910821952). A dismissal replaced while a review runs is another verification request, so the same review asks the verifier again; the two restatement tests that pinned the old behaviour are rewritten for it. The reader applies the unverified cap only when the round's account names the verifier, which closes a hole where a host round with every finding dismissed exported no claim and a reader that did not count the dismissal read a P1 as advisory. Three differences from the host stay, and [issue #506](https://github.com/melian-agent/melian/issues/506) closes the first two before build 5: a dismissed finding carries no earlier verification, a restatement dismissed by inheritance reads live, and a dismissal record is never withdrawn.

Pricing. The verification task's input is version 5. A version-4 task names no dismissal record, so a candidate with a dismissed root builds another key and its verifier runs once more after the upgrade; one with none keeps its key. `verification-dismissal-reopen.test.ts` reopens a store `main`'s code wrote. A dismissal stored before findings document version 11 holds no frozen sighting, gets no record, and reads live on another host.

Failing test first. Each step's tests failed at the head before its fix and passed after: the export's two tests in `review-records-export.test.ts`, the head test in `review-records.test.ts`, the record ID test in `restatement.test.ts`, and the reader's three tests in `recorded-round.test.ts`, which also fail with the cap rule reverted.

The builder ran all 98 by hand at `050dcce3`, each against its named test alone, which passed unmutated first. 90 were killed. 8 are equivalent: four guard a findings document that `recordRevision` always writes first, three guard a dismissed root with no record, which only a version-4 task holds and which never attaches here, and one lets records of another kind into a map that is looked up only by finding ID. New tests in `recorded-round.test.ts` and `restatement.test.ts` killed most of them, and two refactors removed needless code: defaults no caller used, optional chains on values always present, two sorts, and a comparator branch no input reached.
