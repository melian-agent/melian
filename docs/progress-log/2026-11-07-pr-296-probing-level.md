A trust-boundary level that runs probes, first part, [issue #288](https://github.com/melian-agent/melian/issues/288), in [pull request #296](https://github.com/melian-agent/melian/pull/296), stacked on [pull request #289](https://github.com/melian-agent/melian/pull/289). A lens level's `probe` makes it run as a planner, which records an attack plan with `record_plan`, and a prober, which receives the plan alone and answers each attack with `run_probe` or `skip_attack`. The built-in `trust-boundary` lens's `deep` level probes. A prober's finding names a probe that failed. The review runs each claim's probe again before verification and stores the run on the root, and `report_verdict` refuses to confirm a claim whose probe did not fail again. Where probes may not run, the level runs as it did before, without probes, and says why. Stage telemetry names each conversation's role and the prober's probes, and the check record counts the attacks, probes and skips. [The decision](../decisions/2026-11-07-trust-boundary-level-that-probes.md) records the maintainer's rulings and what this gives up.
