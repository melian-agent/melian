For [pull request #296](https://github.com/melian-agent/melian/pull/296), fix pass 34 fixes four things the reviews at `bd9d3f8b` found. Each fix began with a failing test.

- **A model failure during a reminder could let a review pass** (`4fa30c9b`). When Melian reminded the planner or the prober, it waited for the reminder but ignored how it ended. So a reminded prober that ran a failing probe and then hit a provider error counted its attack as answered, and the lens recorded that it ran with no finding. Now a reminder that does not finish ends the lens, and the lens's record names which reminder failed and why. Both reminders' tests passed the review before the fix and leave it not reviewed after. The `melian round` at `bd9d3f8b` raised it as `5578d885281c5aa8`, a P1 block. The coordinator chose to fail closed, with no failover to another model.
- **Two reviews sharing one lens run could stop each other** (`3b9df417`). After its probe reruns, a review checked that it still owned the rerun task by ID. A second review attached to the same lens task starts a new task for the same probes once the stored one has ended, so the first failed as superseded. It now checks the probes the reruns hold. The test failed as superseded before the fix and verifies after. The Opus review of record at `bd9d3f8b` raised it as R1, P3.
- **A change to Melian's probe runner reused old probing runs** (`fccda709`). The probing protocol held the runner's numeric limits but nothing of what it gives a probe. The probe's read and deny lists, its command and its environment are now built by small functions from its paths. A real probe uses them with its real paths, and `probeRunnerSample` uses them with fixed ones, which the protocol hashes whole. So a release that changes any of them runs a probing level once more, on purpose. The protocol held nothing of the runner before the fix and holds it after. The `melian round` at `bd9d3f8b` raised it as `bd501f98f7a9b7de`, a P2 to acknowledge; the coordinator chose this fix. The finding's other half, the sandbox's own version, is answered by the identity guideline's exclusion list. The probe-reruns decision said the key left out the sandbox, and the trust-boundary decision said probing needs a base policy that trusts writers. Neither is true now, and both say so. The attach-key decision records the host value. The review of record raised it as R2, P3.
- The lens conversation and its reminders now word an unfinished request through one function (`869100a2`).
