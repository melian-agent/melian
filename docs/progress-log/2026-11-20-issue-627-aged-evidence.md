[Issue #627](https://github.com/melian-agent/melian/issues/627): `melian store prune` now lists each round of a valid miss's evidence that nothing wrote for more than 90 days, with its size, and `--apply` removes none of it. The maintainer agreed on 2026-11-21, in the coordinator's session, to removal by age under `--apply`. That removal waits for an exclusion between an evidence write and a removal, which [the store retention decision](../decisions/2026-11-14-store-retention.md) requires before prune removes anything durable, and which [issue #633](https://github.com/melian-agent/melian/issues/633) builds as the local lease store rule 2 of [the coordination decision](../decisions/2026-11-08-how-melian-coordinates.md) plans. So this pull request amends nothing in the retention decision; [the new decision](../decisions/2026-11-20-aged-evidence-is-listed-before-it-is-removed.md) amends the evidence decision for the listing and for the issue the budget refusal names. The identity guideline's row for the evidence stage file now records the gap [issue #632](https://github.com/melian-agent/melian/issues/632) closes: a changeset's storage file made again would mint its round and conversation IDs again.

`packages/pipeline/src/store-prune.ts` and `packages/cli/src/store.ts` guard durability, so their mutants were proved by hand. `melian mutants list` over the feature commit generated 44 mutants in those two files. Each ran against its named test alone, which passed unmutated with one test collected, and 43 failed. The survivor set the evidence-folder flag's start to `true`: `children` already lists nothing for a missing path, a link or a file, so the flag repeated it, and the next commit removes it. That commit generates no mutant. Every claim's named test is one of the four aged-evidence tests in `packages/pipeline/test/store-prune.test.ts`, the graph-removal test there, or the two `melian store prune` output tests in `packages/cli/test/store.test.ts`.
