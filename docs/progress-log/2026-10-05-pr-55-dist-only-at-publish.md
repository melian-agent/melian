[Pull request #55](https://github.com/melian-agent/melian/pull/55) takes `dist/` out of the development loop, as [decisions/2026-10-05-dist-only-at-publish.md](../decisions/2026-10-05-dist-only-at-publish.md) records. A `dist/` left from an earlier build made the CLI run code a change had since replaced, so every self-review of a Melian pull request needed `npm run build` first. The committed shim now runs `src/bin.ts` in a checkout, with a synchronous resolve hook adding the `@melian-agent/source` condition, and runs `dist/bin.js` only from the published tarball. Each package builds `dist/` in `prepack` and deletes it in `postpack`; tsc's build-info files move to `.tsbuild/` at the root; CI packs every package with a new `npm run pack`, installs the CLI's tarballs into an empty project, and runs the installed `melian --help`; the CLI test no longer builds; and `.vscode/settings.json` hides what a build leaves. The gate passes on a tree with no `dist/` at all.
