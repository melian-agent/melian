Two questions on [pull request #433](https://github.com/melian-agent/melian/pull/433) went to the maintainer, who answered "agree" to each on 2026-11-15, in the coordinator's session.

- Git reads the user's own system and global configuration on every command, so a fetch and push can authenticate. The maintainer accepted it, since only code already running as the user can write that configuration. Since 98cc2444, [the state-git guideline](../guidelines/state-git.md) says so, and the decision's table lists it.
- A fetch or push failed with git's own text, and git prints a remote's query string, a URL the user's configuration rewrote with `insteadOf`, and whatever the remote sends. Any of these can carry a token, and `melian doctor` prints the message. Removing the user and password from the URL Melian was given caught none of them. The maintainer chose that these two commands quote none of git's text and none of the remote's. Since 12fc09d3, their messages name the clone's origin, git's exit code and, for a refused push, the refusal's class from the porcelain line. Each ends by naming `git ls-remote origin refs/heads/<branch>`, run in the clone, to see git's own words. `shown` went with the URL it named. The six commands that run on `records.git` alone keep git's text, and the fetch's absent-branch check and `#deleteRef`'s retry read git's text and never print it. The guideline states the rule for any new command that reaches the remote.

Eleven tests failed on 98cc2444 and pass now, six of them existing tests whose expected message changed. A remote with a user, password and query token reached the fetch, deadline, push and doctor messages. A remote that the user's global configuration rewrote to a URL holding a token reached the fetch message under its rewritten name. Melian strips `GIT_CONFIG_COUNT` from git's environment, so the test writes the rewrite in a global configuration file, the route a user's own would take. Two more tests fake git's porcelain line to name `[rejected]` and an unknown class, which the real hook test does not reach.

[The inventory](2026-11-15-pr-433-remote-words-mutants.json) lists the 30 mutants of `98cc2444...12fc09d3` and one by hand: the fallback for a porcelain line with no summary field removed. Its 15 generated claims fail their named tests at 12fc09d3, each checked passing unmutated first, and the configuration ignores the 15 string rows. The hand mutant survives, and is equivalent: git prints every `!` line with its flag, refs and summary, so the summary field is always there.
