Three fixes on [pull request #433](https://github.com/melian-agent/melian/pull/433) since the third round.

- CI failed three concurrency tests on every head of this branch. Git 2.55, which CI runs, reports a push that loses the race to create the branch as `[remote rejected] (reference already exists)`. The lost-race pattern did not match it, so the losing writer failed as `unreachable` instead of reading the new tip and trying again. Since dcd19059 the pattern matches it. The new case in `repository.test.ts` failed on ebb74ffe and passes now.
- Two processes share one `records.git`, and a fetch one commit deep cuts its history back. When another process fetched between the landed check's commands, a push that landed under later commits read as lost, and a cell write that landed returned false. The maintainer chose, on 2026-11-15 in the coordinator's session, to fetch the whole history. Since a63479d0, every fetch takes the whole history, and the landed check is one fetch and one ancestry question. A tip that has not moved since the push still leaves the call unsure. The race test, where a second handle on the same repository fetches before each check, failed on dcd19059 with `expected false to be true`, and passes now. The fetch's retry loop went with the depth: it retried on `shallow.lock` and the shallow file changing under it, which no longer happen. A plain fetch keeps a shallow repository shallow, so a `records.git` an earlier build fetched shallow is refused at open, with the advice to delete it. The cost is a host's first fetch. On a probe of 10,000 commits, each adding one 300 to 900 byte record across 500 changesets, the whole history took 1.3 s and 9.6 MB, against 0.5 s and 3.2 MB one commit deep. It grows with every write until [issue #361](https://github.com/melian-agent/melian/issues/361) bounds it, and the decision's table lists it.
- A fetch or push that failed or ran out of time named the remote as given, so an origin such as `https://user:token@host/...` put the token in the error, and `melian doctor` printed it. Since 2bf966da, Melian's three messages name the remote with its user and password removed. Five tests failed on a63479d0, the doctor's among them, and pass now; 3e7f368d adds two more, for a password alone and for a remote with neither, named exactly as given.

The audit for that class found nothing else. Git's own messages already leave the user and password out. `melian doctor`'s records line prints the store's message, and its repository line prints the owner and name it parsed. No record stores the remote, and the package logs nothing. A git that cannot start carries its arguments, the remote included, in the error's cause, and nothing Melian prints shows a cause.

[The whole-history inventory](2026-11-15-pr-433-whole-history-mutants.json) lists the 35 mutants of `ebb74ffe...a63479d0` and five by hand: the new race alternative removed, the landed check's ancestry answer forced each way, and the check for an absent branch forced each way. Its 25 claimed rows fail their named tests at a63479d0; the configuration ignores the rest. [The credential inventory](2026-11-15-pr-433-shown-remote-mutants.json) lists the 20 mutants of `a63479d0...2bf966da`, and its 13 claimed rows fail their named tests at 3e7f368d. Each named test passed unmutated first. The hand rows make the first inventory's row count exceed its `total`, so the legacy sampler refuses it, as it did the entry limit's.
