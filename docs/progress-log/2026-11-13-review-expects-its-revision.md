`melian review "#N"` takes `--expect-base` and `--expect-head`, for [issue #279](https://github.com/melian-agent/melian/issues/279). It refuses, with exit 2, a pull request whose base or head, as GitHub reports them when Melian fetches it, differs from those given. It also refuses one whose fetched refs, `refs/melian/pull/N/{base,head}`, resolve to another head, or to a base other than the expected base and head's merge base: GitHub's answer decides the policy and origin, and those refs decide the diff the lenses read. A second review of the same pull request in this clone could move the refs between the two. Codex's adversarial review raised it, and the coordinator answered on [pull request #387](https://github.com/melian-agent/melian/pull/387) to check the resolved changeset. The refusal comes before Melian reads a secrets file, opens storage or runs a check, so nothing is reviewed or stored and no login is spent. Both options go together, and only on a pull request; anything else is a usage error.

The `melian round` workflow passes the base and head its gate approved. Before, a push between the workflow's re-read of the pull request and Melian's own fetch was still reviewed with the logins, on a head no gate had checked. The report job keeps its own checks, since the pull request can still move during the round.

`packages/cli/test/compare.test.ts` refuses a moved head and a moved base, each with an unreadable secrets file that would fail the review if Melian read it, and an empty state directory afterwards. A `reference-transaction` hook moves the head ref after Melian's last write, and the review refuses that too. It reviews a pull request at the expected revision as before, and refuses each option alone, both on a range, and both on another command. Moving the refusal after the secrets read fails the first test with the secrets file's error.
