# A probe stands in only for what its sandbox cannot hold

Part B of [issue #511](https://github.com/melian-agent/melian/issues/511) changes the probing wording and the prober's telemetry. Part A, the goldens and their scoring, is in [its own entry](2026-11-16-issue-511-probing-goldens.md).

The wording left three gaps the first live probing measurement could fall into. Nothing told a probe that `probe.mjs` sits in a folder beside the checkout, so `new URL("./src/...", import.meta.url)` reads nothing. Nothing said which file a finding names as its cause, so a finding could cite the workflow that runs a leaking script rather than the script. And nothing said what a probe may stand in for, so a probe could replace the head's own code with a copy and prove nothing about the change.

The wording now says four things. A prober reaches the checkout by a working-directory path or `../tree/`. Each lens's prober cites the file whose code is wrong as the cause, and a file that only runs or calls it as context. The planner plans each attack to run the head's code at every step that can run in the sandbox, and names the stand-ins it needs. The prober stands in only for a CI runner, an upload service, the network or a real login, prints which steps ran and which it stood in for, and says the same in its finding. That last rule is the maintainer's ruling of 2026-11-16, in the coordinator's session; [the decision](../decisions/2026-11-16-probes-stand-in-only-for-infrastructure.md) records it.

The lens request key holds the wording, so every probing lens's key changes, on purpose: a review under the old words is not a review under the new ones. The verifier's instructions are unchanged, so `verifierVersion` and the round fixtures stand.

The prober's stage in telemetry now carries the plan it was given, each skipped attack with its reason, and each probe's script, files and output. Before, it held counts and endings alone, so a reader of a measurement's results file could not tell why an attack went unprobed or what a probe ran. An attack skipped and then probed counts as probed. The text is the model's and the head's, held to the probing tools' limits, and [the evals guideline](../guidelines/evals.md) tells a reader to treat it as data.

The rendered notes line the issue asked for is deferred. Showing it by default needs version 16 of `melian.verdicts`, which [issue #489](https://github.com/melian-agent/melian/issues/489) holds, and the coordinator will fold it into a follow-up with [issue #505](https://github.com/melian-agent/melian/issues/505)'s field. The figures stay visible under `--notes`, and the telemetry carries them to the results file.

Tests first. The new wording tests in core's and the pipeline's `probing-wording.test.ts` failed on `b9e9fe63` for the missing words, and the telemetry test in `probing-level.test.ts` failed with no `plan`, `skips` or probe text in the stage. All pass with the change.

The [mutant inventory](2026-11-16-issue-511-wording-telemetry-mutants.json) lists all 30 mutants of `b9e9fe63...HEAD`. Eight are string literals, ignored by configuration: five of the wording table, which the wording tests and goldens hold whole, and three ending labels, which the telemetry test asserts whole. A scratch runner applied each of the other 22 and ran its named test alone, by its anchored title, and counted a kill only when exactly one test was collected and failed. 21 were killed by the existing tests. One, `+` swapped for `-` in the prober's summed milliseconds, survived, because the telemetry test took any number; the test now asserts the sum, and the mutant is killed.

Codex's adversarial review of the whole pull request found that `scoreGolden` counts an expectation found when any finding fits it, independently of its one-to-one matching. Part A's `lines` let two expectations share a file and rule, so one finding whose lines span both would count as found twice. No golden had such a pair. d090be23 adds a corpus test that refuses two expectations sharing a file, a rule and a source, and leaves scoring as it is, so the second probing measurement compares with the first. The coordinator chose that over changing the count. Its message names the way out: count found from the matching, and let a finding answer more than one expectation only where they differ by source alone. The test failed with `trust-boundary-probe-round-environ-leak` named once a second expectation, differing only in its lines, was added to a scratch copy of that golden, and passes on the corpus. The change adds no source code, so it adds no mutants.

The Claude review of record found two P2s, each fixed test first. First, Node names a linked module by its target, so the syntax-check twins' parse refused the measured attack's output, and the defect twin leaked through its fallback message rather than the quoted line its expectation cites as cause. Second, the corpus test let an expectation that names no source stand beside one that names a source at the same file and rule, though one finding counts as found for both. Its table gained both orders, which failed; f8f9ad8d counts a missing source as sharing any, and they pass. The review's P3s on two stale guideline sentences and three mislabelled inventory rows are fixed in d3fd4d19. Its other P3s stand as advisories: merged claims score by the speaker's lines alone, nothing checks that an alternative rule is one a lens declares, `../tree/` holds only from a file at the top of the probe's folder, and a prober's stage can hold much text.
