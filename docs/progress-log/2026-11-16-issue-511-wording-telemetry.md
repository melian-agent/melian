# A probe stands in only for what its sandbox cannot hold

Part B of [issue #511](https://github.com/melian-agent/melian/issues/511) changes the probing wording and the prober's telemetry. Part A, the goldens and their scoring, is in [its own entry](2026-11-16-issue-511-probing-goldens.md).

The wording left three gaps the first live probing measurement could fall into. Nothing told a probe that `probe.mjs` sits in a folder beside the checkout, so `new URL("./src/...", import.meta.url)` reads nothing. Nothing said which file a finding names as its cause, so a finding could cite the workflow that runs a leaking script rather than the script. And nothing said what a probe may stand in for, so a probe could replace the head's own code with a copy and prove nothing about the change.

The wording now says four things. A prober reaches the checkout by a working-directory path or `../tree/`. Each lens's prober cites the file whose code is wrong as the cause, and a file that only runs or calls it as context. The planner plans each attack to run the head's code at every step that can run in the sandbox, and names the stand-ins it needs. The prober stands in only for a CI runner, an upload service, the network or a real login, prints which steps ran and which it stood in for, and says the same in its finding. That last rule is the maintainer's ruling of 2026-11-16, in the coordinator's session; [the decision](../decisions/2026-11-16-probes-stand-in-only-for-infrastructure.md) records it.

The lens request key holds the wording, so every probing lens's key changes, on purpose: a review under the old words is not a review under the new ones. The verifier's instructions are unchanged, so `verifierVersion` and the round fixtures stand.

The prober's stage in telemetry now carries the plan it was given, each skipped attack with its reason, and each probe's script, files and output. Before, it held counts and endings alone, so a reader of a measurement's results file could not tell why an attack went unprobed or what a probe ran. An attack skipped and then probed counts as probed. The text is the model's and the head's, held to the probing tools' limits, and [the evals guideline](../guidelines/evals.md) tells a reader to treat it as data.

The rendered notes line the issue asked for is deferred. Showing it by default needs version 16 of `melian.verdicts`, which [issue #489](https://github.com/melian-agent/melian/issues/489) holds, and the coordinator will fold it into a follow-up with [issue #505](https://github.com/melian-agent/melian/issues/505)'s field. The figures stay visible under `--notes`, and the telemetry carries them to the results file.
