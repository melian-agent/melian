# Mutation testing as a static check

`static.mutation` landed as the plan's mutation-testing step. It runs Stryker 10.0.0 on Vitest over the lines the head adds or edits and reports each surviving or uncovered mutant as a P2 `mutation/untested-behaviour` finding. Core reads the report in `normaliseMutationReport`, and `MutationRun` in the pipeline runs it under `Run.inWorktree`, fails closed on a missing report or an undocumented exit, and skips a change past `static.mutation.maxLines`. The check is off by default and on in Melian's own `full` tier. [The decision](../decisions/2026-10-08-mutation-testing-as-a-static-check.md) records the settings, the bound, and what the check gives up. Every guard in the new code was proven with a failing mutation, listed in the branch's report. Two real runs on a scratch repository showed two findings, six mutants, for a test that passes either way and none for one that kills them.
