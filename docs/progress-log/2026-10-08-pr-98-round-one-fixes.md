# [Pull request #98](https://github.com/melian-agent/melian/pull/98), round one fixes

Round one of Melian's review of the mutation check failed the check itself, and the cause took three fixes. The check ran Stryker under the 16 MiB file-size limit meant for a static tool's report, and the suite's cache tests write 128 MiB archives, so Stryker's initial run died with SIGXFSZ (7e5a6a71). With that fixed, 80 of the 536 mutants were static and each reruns the whole suite, so Stryker ignores them (422a806d). And Stryker 10.0.0 builds test names with spaces where Vitest 5 uses " > ", so 380 mutants ran no test and survived. A Vitest plugin for the Stryker run fixes it, and the initial-run limit moves to 20 minutes (4d012fb2). The other fixes landed one per finding: a checkout without Stryker records a skip, and Melian carries no copy (797c388a, abb77131). The review grants leave to the skips for no production lines and for a change past maxLines (6f2980c0). A timeout records a skip with leave (461eadd3). The run gets a scratch home and runs only for a trusted writer (e89d2131). Glob characters in paths are escaped, and ignored and unmutated files get notes, with a guardrail for the Stryker disable comment (7850d374). The multi-range filter and the Stryker config as policy are pinned by tests (b03da59a, with the docs in 28d2aa7a). Melian's own mutation run on the result then found the writer trust untested and a few smaller gaps, closed in a82048d8, 8c5691a4, and 1d2631e4. 5e60e428 drops a guard the manifest already enforces. The first of these commits left 797c388a without the `strykerNotInstalled` export its `static.ts` imports, which abb77131 adds, so only later commits build. A sandboxed `ExecutionEnv` for head code stays deferred.
