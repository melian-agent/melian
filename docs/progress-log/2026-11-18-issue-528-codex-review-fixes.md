# Issue #528: two fixes from Codex's adversarial review

Codex's adversarial review of [pull request #557](https://github.com/melian-agent/melian/pull/557) at cc30edc0d found two ways an unchanged revision stays unproven after an upgrade. Both fail closed: the sightings or the dismissal stay unshared.

A run an earlier build completed is reused. The request key had not changed, so the review found the old build's completed check task and reused it, and that task's terminal commit wrote no stamp. Commit d6ef085b2 raises each static check's version in `checkVersions`: Biome 3, tsc 4, Enola 3, mutation 3. The key changes once, so the review asks again. The new case in `packages/pipeline/test/check-requests.test.ts` moves a run to the key the old versions give and deletes its stamp. It failed at cc30edc0d with `expected 'b7ee6513…' not to be 'b7ee6513…'`, since both builds asked under one key, and passes after the bump. `melian mutants list` generates no mutant for that commit: Stryker leaves number literals alone.

A repeated dismissal cannot take a stamp. A dismissal made before stamps carries no `run`. Repeating it with the same reason after a stamped run returned early, so the run was never stored. Commit a6948cc66 counts a different run as a change, for a dismissal that records a sighting. The new case in `packages/pipeline/test/findings-check-stamp.test.ts` failed at d6ef085b2 with `expected undefined to be '2222…'` and passes after the fix.

Files that guard trust or durability: `packages/pipeline/src/findings.ts`. The inventory, [2026-11-18-issue-528-repeated-dismissal-mutants.json](2026-11-18-issue-528-repeated-dismissal-mutants.json), lists the 9 mutants `melian mutants list a6948cc66~1...a6948cc66 --claims-in packages/pipeline/src/findings.ts` generates. A scratch runner applied each at a6948cc66, ran the candidate test files, and confirmed each failing test alone: it passed unmutated and failed mutated, with one test collected. 8 were killed, 6 by existing tests and 2 by the fix's own test. The survivor replaced `severity === undefined` with `false`; a second new test, a repeat that names no severity after a later run, kills it, run the same way.

## An empty result needs its run's proof

Codex's second review, at 89449306c, found that a stale run can hide a blocker. Run B finds a blocker; a stale run A of another request then finds nothing, replaces B's sightings with none, and stamps A's key. The export shared a check with no sightings without proof, so B's record called the revision clean. The coordinator answered on 2026-11-18 that every ran or provisional static check needs the proof; the maintainer has not ruled. Commit 80ed5f65a drops the exemption. The older race, where a stale run's commit replaces a newer run's sightings at all, is [issue #562](https://github.com/melian-agent/melian/issues/562); until it lands the host's own verdict can still pass, and the decision names it as a third limit.

The new case in `packages/pipeline/test/review-records-unproven-run.test.ts`, tsc's empty result stamped by another run, failed at 89449306c with `expected { Object (result, sightings, ...) } to deeply equal { v: 1, result: { …(4) }, …(1) }`, since tsc exported as ran, and passes after the fix. Every end of a static check, ran, provisional, skipped or failed, goes through the check task's one terminal commit, which stamps the run's key, so an honest clean run is proven.

Nineteen tests broke. Fifteen in `recorded-round.test.ts` and one in `review-records-export.test.ts` handed in bare check records, which prove nothing, so their clean static checks were withheld. They compare a reader with its host, and a host's round holds a run, so `test/fixtures/proven-run.ts` writes what a run's terminal commits leave and hands that run in; their assertions are unchanged. Three cases in `review-records-unproven-run.test.ts` asserted that tsc's empty record was shared from an unproven run. Each case now names tsc's record: withheld where the run is unproven, ran where only Biome's stamp fails or the older build asked for today's tsc code.

Files that guard trust or durability: `packages/pipeline/src/review.ts`. The inventory, [2026-11-18-issue-528-empty-result-mutants.json](2026-11-18-issue-528-empty-result-mutants.json), lists the 8 mutants of `80ed5f65a~1...80ed5f65a` in it: 7 generated and 1 ignored by configuration. The scratch runner applied each at 80ed5f65a and confirmed each failing test alone, as above: all 7 were killed, 5 by `recorded-round.test.ts` through the proven run, and 2 by `review-records-planted-sighting.test.ts`.
