# Pull request #341: round three fixes

[Pull request #341](https://github.com/melian-agent/melian/pull/341), for [issue #315](https://github.com/melian-agent/melian/issues/315), took five findings from Melian's third round, at `6e4b5c57`.

- `bb10b6f4` binds a restatement link to the whole root dismissal it came from. It is the third instance of one class: Codex's re-recorded severity and round one's idempotency were the first two. A link named its root by `dismissedAt` alone, and `dismissFinding` lets a caller replace a dismissal's reason or severity at the same time, so the link stood. Each link now stores an identity of the root's dismissal, a hash of its dismisser, reason, time, recorded severity, claim and accepted trigger, stamped in the commit that records the links. Any change lapses it; an identical repeat writes nothing and keeps it. `602f32a6` covers a stored link whose root record is gone, and `fb613f51` keeps three earlier link tests deciding: they had linked to roots never dismissed, which the commit now drops.
- `c522b2ca` keeps a claim's latest sameness answers when an earlier, stronger verdict stays. A corrected `different` was lost, and the stale `same` carried the dismissal.
- `99da0767` tests the severity `recordDismissal` records: a root dismissed at the P2 its verifier lowered it to fences a P1 restatement to a proposal. Recording `"P1"` instead let it inherit.
- `4b4fd37e` takes a dismissal's claim, trigger and proof only from the sightings of the producers the dismissed verdict selected, so a dropped lens's stale sighting never becomes the root's claim.
- `f6b17ae2` holds a root to its proof whatever cause its latest sighting cites. The restatement check now calls `readsProof`, the rule the lifecycle's reopen check uses, so an affected root a lens later sighted as pre-existing still needs its accepted hunks.
