# A head's Packwerk change draws a policy notice, 2026-11-20

[Issue #538](https://github.com/melian-agent/melian/issues/538). Enola's Packwerk check read `packwerk.yml` and each `package.yml` from the head, so a head could turn it off with no notice. The maintainer ruled on 2026-11-18, on that issue, for a notice at acknowledge. The Enola check now raises `guardrail/policy-change-review` for each Packwerk file the head changes. Enola's facts, at base or head, name those files. [The decision](../decisions/2026-11-20-packwerk-changes-draw-a-policy-notice.md) says why the Enola check raises it and how it resolves under Enola's table and the guardrail's, the stricter standing. The checks' recorded code hashes move, so the check request no longer reuses an earlier build's run.

Files that guard trust: `packages/core/src/guardrails.ts`, `packages/core/src/findings.ts`, `packages/core/src/enola-graph.ts`, `packages/pipeline/src/enola-static.ts` and `packages/pipeline/src/checks.ts`. They decide what a head's change draws and how it resolves. None writes a stored shape.

Tests: `packages/core/test/packwerk-notices.test.ts`, a new case in `packages/pipeline/test/checks.test.ts` and one in `packages/pipeline/test/enola-static.test.ts`. On main's source the core file fails, since nothing raises the notice, and the checks case fails with the Enola record counting 0 findings where it should count 1.

Mutation proof, by hand, at 49f21ab68 for the source with the order test added after: `melian mutants list origin/main...HEAD --json --all` with `--claims-in` for the five trust files gave 83 rows, 13 ignored by configuration. Each of the other 70 ran against its named test alone, after that test passed unmutated: 12 killed by existing tests, 55 by this change's tests, and 3 equivalent, with reasons in [the inventory](2026-11-20-issue-538-packwerk-notice-mutants.json). The first run left 16 survivors. Twelve sat in code that was already there, on lines this change touched, and fell to existing tests. One, a dropped `.sort()` in `packwerkNotices`, needed the new order test. The source was clean after every run. `packages/pipeline/src/static.ts` adds only an optional field to a type; the enumerator leaves it unmutated because it sends signals.

Fix pass on the first rounds. The Actions round's design lens said the decision narrowed the [analyser-configuration decision](../decisions/2026-10-03-analyser-configuration-changes.md) without saying so. The decision now declares that amendment, and keeps acknowledge, as the ruling chose. The own-build round's design lens found that the notice resolved under the guardrails table alone, dropping Enola's own, against the [exact-rule decision](../decisions/2026-10-17-acknowledge-status-exact-rule.md). The coordinator chose to resolve it under both, the stricter standing. The test with `static.enola: { P2: block }` and `guardrails: { P2: silent }` failed at 23cd7ec47 with `expected 'silent' to be 'block'`, and passed after the fix in 56884d66b, as did its mirror. The fix's 30 mutants in `findings.ts` left 7 ignored by configuration. Each of the other 23 ran against its named test alone, after that test passed unmutated, and every one was killed, 9 of them by this pass's tests. One survivor of the first run, a guardrails-raised notice also resolving under its whole guardrail's entry, needed a new test. The record is [the inventory](2026-11-20-issue-538-resolve-both-mutants.json).
