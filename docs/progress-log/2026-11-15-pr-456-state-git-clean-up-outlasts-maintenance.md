# State-git tests no longer fail removing a remote that git maintenance still writes

[Issue #453](https://github.com/melian-agent/melian/issues/453): three pull requests left the merge queue, or failed CI, because a state-git test's clean-up failed with `ENOTEMPTY` on the fixture's bare remote: [pull request #399](https://github.com/melian-agent/melian/pull/399), [pull request #431](https://github.com/melian-agent/melian/pull/431) and [pull request #429](https://github.com/melian-agent/melian/pull/429), all on Node 22 runners with git 2.55. After a push, that git runs automatic maintenance and can detach it, so it still writes `packed-refs`, `info/refs` and `objects/info/packs` while the test removes the directory. [Pull request #456](https://github.com/melian-agent/melian/pull/456) turns maintenance off in the fixture's remote and clones, and makes core's `removeDirectory` start a removal over on `ENOTEMPTY`, up to five attempts, since Node's `maxRetries` repeats only the last `rmdir` and fails again on a file added after its listing. The failure did not reproduce plainly in a cloud container, whose git 2.43 detaches `gc --auto` only past its thresholds: 200 runs of the two failing tests all passed. With `receive.unpackLimit` and `gc.autoPackLimit` set to 1 as a stand-in, so gc ran after every push, 5 of 10 runs on `main` failed with `ENOTEMPTY` on `remote.git/objects`, leaving gc's files and two orphaned git processes, and a sixth failed a fetch while gc repacked, which the stand-in caused. With the fix, 10 of 10 passed, and with only the restart in `removeDirectory`, 10 of 10 passed. Two new tests failed on `main` for the reported reason and pass now: `packages/state-git/test/fixtures.test.ts` reads the fixture's maintenance settings, and `packages/core/test/remove-directory.test.ts` removes a directory another process is still writing into, which failed 10 of 10 runs on `main`.
