# Eight lenses leave the standards to conventions

[Pull request #585](https://github.com/melian-agent/melian/pull/585), for [issue #580](https://github.com/melian-agent/melian/issues/580): eight of Melian's own lenses set `standards: false` in `.melian/lenses/`, so only `conventions` receives the repository's `AGENTS.md` files and package guidelines. The maintainer ruled on 2026-11-18, in the coordinator session, for seven of them, and for `design` once its goldens held. On 2026-11-20 the maintainer ruled that Melian's own `standard` tier add `lens.conventions`, after Codex's adversarial review found that the pre-push and comment stages would otherwise check no standard. [The decision](../decisions/2026-11-19-lenses-get-only-the-standards-they-cite.md) records the rule.

On a range review of [pull request #532](https://github.com/melian-agent/melian/pull/532), which touches every package, `removed-behaviour`'s first request fell from 231,553 to 61,791 uncached input tokens, and the review, capped near one request per lens, cost $3.56 instead of $7.86. [The issue](https://github.com/melian-agent/melian/issues/580#issuecomment-7023014792) has each lens's figures.

The live goldens on `openai-codex/gpt-6.1-sol` read 0.90 precision and 0.95 recall before, and 0.87 and 0.93 with the seven lenses changed. Of the five goldens that moved, four scored 1.00 on a rerun at the same head, `conventions-clean` among them, whose lens did not change. The fifth missed both expected leaks before and after. Over the 35 design goldens, turning `design`'s standards off kept recall at 0.95 and added one finding, from `correctness`, in one of three runs.

A test in `packages/core/test/lens.test.ts` fails when a tier of the root `melian.yaml` that runs a lens runs none that reads the standards. It failed with `standard: []` against the tier before the fix. No changed file guards trust or durability, so no mutation inventory is owed. The budgets in `.melian/lenses/` are set from the new request size in a later pull request.
