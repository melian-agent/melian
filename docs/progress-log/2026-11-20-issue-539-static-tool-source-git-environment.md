# Choosing the checkout's tools asks git in core's environment

[Issue #539](https://github.com/melian-agent/melian/issues/539). `staticToolSource` in `packages/pipeline/src/static.ts` asks `git ls-files` whether the checkout tracks `node_modules`, and runs the checkout's own Biome or tsc only when it does not. That call ran with the caller's whole environment, so a `GIT_INDEX_FILE` naming an empty index answered "untracked" for a checkout that tracks `node_modules/.bin/biome`. `melian doctor` then named the checkout's copy, and the check request recorded `from: "checkout"` and that copy's version. The runner never ran it: it asks git again, at `static.ts:586`, under `toolEnvironment`. It is the same defect as the CLI's helper had, a git read that trusts the caller's environment, so the coordinator asked for it here: the call now runs with core's `gitEnvironment`.

The new test in `packages/pipeline/test/static.test.ts`, "takes Melian's own copy when the checkout tracks node_modules, though GIT_INDEX_FILE names an empty index", failed before the change with `expected 'checkout' to be 'melian'`, and passes after it with the other three tests of its block.
