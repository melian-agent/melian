Round four and the reviewer's second pass on [pull request #112](https://github.com/melian-agent/melian/pull/112) both faulted how an unconfined tool's diagnostics were filtered, from opposite sides. Dropping a diagnostic whose message named an outside path turned an introduced error into a clean review, for Enola on every host. Keeping one whose message named no path let stock tsc quote a type it had read from a reviewer's file. One rule replaces both: on a run that was not confined every diagnostic is kept with its rule, file, lines, and level, and its message is the fixed sentence "message withheld: the tool ran unconfined". A diagnostic on a file outside the worktree fails the run with `invalidOutput`. The comparison of base and head keys on rule, file, and the code on the lines, so it still tells what the head introduced; a test with the real tsc shows it. A checkout's Biome or tsc now runs only inside a sandbox, since a patched tsc loads plugins the head names and nothing can detect that; outside one Melian's own runs with a note, or the check is skipped. Enola's output is held to the same principle channel by channel: results keep rule and place, error text and a refused caller query keep only an exit code, the record keeps three validated fields of the receipt, and facts and callers are used only for files that resolve to themselves inside the worktree. What was withheld is written to a file of mode 0600 under the state directory, and `melian review` names it on the terminal's error stream alone. Smaller points: a failure thrown by core carries where the tool ran; a reported version is cut to 64 characters; scratch is removed through the run's environment; the note on a confined tree stuck on a host with no sandbox says how to remove it; the `Sandbox` class is no longer exported from the package; and the teardown test waits for its child. [The confined-tools decision](../decisions/2026-10-13-static-tools-run-confined.md) is rewritten to these rules and lists, as owed work, a test of the real Enola binary against marker files. Follow-up, not in this pull request: tests that call `baseAndHead` in `packages/pipeline/test/fixtures/repo.ts` never delete the repository it makes, and leave `melian-review-*` directories in the temporary directory, 78 in one session; that helper is on main and this pull request does not change it.
