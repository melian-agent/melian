[Pull request #61](https://github.com/melian-agent/melian/pull/61) builds milestone 2 step 4, the review plan. Core's `ReviewPlan` decides which model each tier runs by a lookup over the routes, pi-ai's catalogue, and the credentials present, and [a decision](../decisions/2026-10-05-review-plan-resolution.md) records the order. Without credentials for a committed route, a contributor gets an accepted model, or the same model from another provider such as Bedrock, rather than a review that exits not reviewed. A route gains `accept`, `unavailable`, and `acceptOverridden`, which only the root `melian.yaml` may set. `acceptOverridden: false` fails a check outside `accept` before it asks a model, and a lens a preference file moves to another tier stays under its committed tier's policy. Each lens check records the lineage of the model it finished on, and a review under another plan runs the lenses again. The verdict's provenance keeps the plan, and `melian findings` prints it. Named credentials come from `melian.secrets.yaml` and the user-level secrets file. A command source runs only from the user-level file, which the user must own, of mode 600, and a per-clone file git tracks under any case of its name is refused. The user-level preference file layers under `melian.local.yaml`. `melian doctor` prints the plan, and Melian's own `melian.yaml` commits default routes. Codex, Melian, and an Opus review found a secrets file a head could supply under another case, a parser error that quoted a key, a preference file that could move lenses around `acceptOverridden: false`, and lineage drawn from the plan rather than the run. The pull request fixes each. [design.md](../design.md#the-review-plan), the README, and the core, pipeline, CLI, and evals guidelines follow.
