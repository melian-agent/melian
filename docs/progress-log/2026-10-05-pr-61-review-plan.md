[Pull request #61](https://github.com/melian-agent/melian/pull/61) builds milestone 2 step 4, the review plan. Core's `ReviewPlan` decides which model each tier runs by a lookup over the routes, pi-ai's catalogue, and the credentials present, and [a decision](../decisions/2026-10-05-review-plan-resolution.md) records the order it looks in. Without credentials for a committed route, a contributor gets an accepted model, or the same model from another provider such as Bedrock, rather than a review that exits not reviewed. A route gains `accept`, `unavailable`, and `acceptOverridden`, which only a committed `melian.yaml` may set. `acceptOverridden: false` fails a check outside `accept` before it asks a model. Every check a preference file, `--model`, or a derivation moved off the committed route records that lineage in the verdict and the review body. The verdict's provenance keeps the plan. Named credentials come from `melian.secrets.yaml` and the user-level secrets file, and a command source runs only from a file the user owns. The user-level preference file layers under `melian.local.yaml`. `melian doctor` prints the plan, and Melian's own `melian.yaml` commits default routes. [design.md](../design.md#the-review-plan) and the core, pipeline, and CLI guidelines follow.
