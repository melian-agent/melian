On [issue #480](https://github.com/melian-agent/melian/issues/480)'s branch, a stop now also matches each recorded process by its command. `ps` gives a start time to the second, so before this a pid that passed to another process within the same second still read as the recorded one. The maintainer agreed on 2026-11-16, in the coordinator's session, to add the command check and leave the rest of the window to [issue #352](https://github.com/melian-agent/melian/issues/352).

- `ProcessTable` asks `ps` for `comm=` after `stat=`. `stopTree` records each process's command, and `terminateRecorded` signals a recorded pid only while its command still matches. A record without a command matches by its start alone, so the mutation supervisor and the probe are unchanged.
- The tests came first. On a fake `kill`, "leaves a recorded pid alone when its start second matches and its command does not" sent SIGTERM to pid 10, and `stopTree`'s "never signals a pid whose start second still matches but whose command does not" signalled pid 101. The `ps` request test failed on the missing column, and the real-table test found no command. "signals a recorded pid whose start and command both match" and "signals a recorded pid with no command by its start alone" passed before and after, as the unchanged cases should.
- Core's flood test had its stand-in `exec sleep 30` once the flood was written. A read just before that `exec` would record the shell, and the signal would then find `sleep` and leave it alone. The stand-in now loops on `sleep 1` instead, so its command never changes, and nothing it starts outlives a second. Its outcome is unchanged.
