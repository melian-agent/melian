[Pull request #314](https://github.com/melian-agent/melian/pull/314), the high finding in Codex's adversarial review of a4de0552, under the maintainer's ruling of 2026-11-08.

- A checkpoint snapshotted the copy's files while the publish harness still had the storage open, so a commit by a resumed publish task could fall between the snapshot's reads: Pi writes a commit's sidecars, then its main-log marker, then reclaims sidecars, all inside `commit`. The pushed tree could then hold a marker without the records it names. The maintainer ruled for a lock and a check.
- The lock: a pull request's storage is a `SerialStorage`, whose `commit` and the checkpoint's push take turns. `takes a checkpoint's snapshot only between Pi's commits, never during one` failed first on a4de0552, with the snapshot between a commit's start and end. Removing the lock from `commit`, from the checkpoint, the wrapper itself, or its queue each fails it. A checkpoint that failed must not stop later commits: `commits after a checkpoint that failed` fails when the queue keeps the rejection.
- The check: a push reads each file once, has `validate` open exactly those bytes from a directory of their own, and refuses with `invalidCopy` a copy that does not open. `refuses to push a copy Pi's storage cannot open, and moves nothing` failed first; skipping `validate` fails it. The golden sealing vector's file is not Pi's, so its test gives the clone a `validate` that accepts anything; the vector is unchanged.
