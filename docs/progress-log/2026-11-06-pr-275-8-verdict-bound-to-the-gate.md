An Actions round's comment now posts findings only for the revision the gate approved, in fix pass 2 of [pull request #275](https://github.com/melian-agent/melian/pull/275). `melian review "#N"` reads the pull request again when it starts, so a push between the gate and the review gave a verdict on another head. A force-push back before the report would then have passed the stale-run check and posted that verdict under the approved head. The round job now records the round's own base and head, from `melian findings "#N" --rounds --json`, and the merge base of the gate's base and head. The comment posts findings only when the round reviewed the gate's head from that merge base, and otherwise says what Melian reviewed instead. A failing test first showed a verdict for another head being posted. `scripts/round-comment.mjs` now takes named options.
