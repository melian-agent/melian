On [issue #480](https://github.com/melian-agent/melian/issues/480)'s branch, `parseProcesses` reads `ps`'s lstart as ctime's five fields, so that the state, and later a command, can follow it. Only the C locale promises that form. In a locale whose date has another number of words, every row would misread: the stop would find no process below git, signal nothing and report nothing. The coordinator chose on 2026-11-16 to force the locale, as a choice of approach.

- `ProcessTable` and the mutation supervisor's embedded read now run `ps` with `LC_ALL=C` in the child's environment. This process's own environment is left alone.
- The tests came first, in `packages/pipeline/test/mutation-process.test.ts`, on a fake `ps` that prints a start of two fields unless `LC_ALL` is `C`. Through `ProcessTable`, "stops its recorded child in any locale" failed with "expected [] to deeply equal [ [ 100, 'SIGTERM' ], …(3) ]". The supervisor's zombie test failed because the supervisor could not find itself in the table and gave up before starting its command. The `ps` request test failed on the missing environment. All three pass with the fix.
