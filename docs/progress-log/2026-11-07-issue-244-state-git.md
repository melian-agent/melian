[Issue #244](https://github.com/melian-agent/melian/issues/244), first pull request: the `state-git` package. `StateBranch.checkout` fetches `melian/state`, takes the changeset's lease in `index.json`, and leaves this clone's copy of its Pi JSONL storage as the branch has it. It refuses with `LeaseHeld` while another clone's lease is under two hours old. `StateCheckout.push` stores the copy and releases the lease in one commit, with `--force-with-lease` on the tip it fetched. It refuses, keeping the copy, when the lease or the changeset moved under it; the next checkout sets the copy aside and takes the branch's. Commits are built with git's plumbing in the clone's object database and the branch is never checked out, so two changesets in one clone never touch each other's files. Core's `git` now takes standard input and extra environment variables for that. Pi's storage conformance suite passes on a checkout's storage. Tests cover a fresh clone restoring what another pushed, the lease's two-hour bound on both sides, a race whose loser resumes from the winner's copy, a store a newer build wrote that an older one refuses without overwriting, and a branch file Pi never writes. [The state branch decision](../decisions/2026-11-07-state-branch-storage.md) records the format and the maintainer's two rulings. The CLI's use of the branch follows in the second pull request.
