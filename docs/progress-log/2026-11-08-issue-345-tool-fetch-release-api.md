For [issue #345](https://github.com/melian-agent/melian/issues/345), `ToolCache` now downloads a pinned tool through GitHub's release API when `GITHUB_TOKEN` or `GH_TOKEN` is set. From about 09:00 UTC on 2026-11-08, GitHub's public release URLs answered HTTP 504 while the API served the same assets, so `static.enola` failed and every `melian round` read not reviewed.

The cache asks for the release by the pin's `source`, takes the asset whose `browser_download_url` is the pinned URL, as `scripts/check-tools.mjs` does, and downloads it by id with `Accept: application/octet-stream`. It follows the redirect itself, with no token, so the token reaches `api.github.com` alone. Any API failure falls back to the public URL. A SHA-256 mismatch or an oversized body on the API path is refused, not retried. Release metadata is bounded at 4 MiB. [The decision](../decisions/2026-11-08-tool-fetch-through-release-api.md) records the choice.

The tests' fakes answer only a request with the right token, media type and redirect mode, and each fallback case lists the exact requests it expects. Against the head before the fix, the new tests failed because the cache asked the public URL first. A live fetch of Enola 0.4.27 with a real token went to `api.github.com` twice and then to `release-assets.githubusercontent.com`, while the public URL still answered 504.

Tests that pass a fake fetch to `ToolProvisioning.open` now pass `env: {}`, because CI sets `GITHUB_TOKEN` for the gate and would otherwise route them through the API.

Before the host round's fixes, the enumerator listed 91 mutants. 18 are ignored string literals. One is equivalent: dropping `?.` before `.id` turns a missing asset's guard error into a `TypeError`, and both fall back. The other 72 were each run by hand against their one named test at the final head, and all were killed. The fake host refuses a third request for one URL, so a retry mutant that would recurse forever fails instead of hanging.

Codex's adversarial review found that a token GitHub refuses with HTTP 401, as `scripts/check-tools.mjs` says a cloud session's can be, sent the fetch straight back to the failing public URL. The cache now asks the API once more without the token on a 401. Two new tests failed first, with `Download failed: HTTP 504` and a missing anonymous request, and pass after the fix.

The first own-build round, at `98cbbf1e`, found two test gaps. The provisioning token cases fed the release request an archive, and no downloading test reached the `process.env` default. The fake now answers only the request a pin should make, and a new test stubs `GITHUB_TOKEN` and omits `env`; it fails with the default replaced by `{}` and passes as written. The six provisioning mutants were rerun against the rewritten tests, and all were killed.

The coordinator's host round at `e003858f` blocked on the review of record's R2, raised to P1: `ToolProvisioning.open` fell back to `process.env`, so `melian tools fetch enola` with an `Io.env` holding no token still sent the process's token. The environment is now explicit. `ToolProvisioning.open` defaults to none. `ToolInventory.open` passes its environment. `ReviewHarnessOptions.environment` installs `checksExtensionFor(environment)`, whose check task hands it to `StaticRunInput.environment`. The CLI passes `Io.env` to the harness and to the caller context. Four tests failed first: the CLI with `io.env = {}` sent `Bearer fake-process-token`, the CLI with its own token sent the process's, provisioning with no environment sent the process's token, and checks and callers opened provisioning with no environment at all. All pass after the change. The round also found the 4 MiB bound tested only with one-chunk bodies; a two-chunk body of 4 MiB and one byte now falls back, and the test fails with `size = chunk.byteLength`.

[The inventory](2026-11-08-issue-345-mutants.json) records the final head. Making the check task a factory over the host's environment re-indented its body, so the enumerator lists its unchanged lines again. The inventory now covers 178 mutants at the final head: 33 ignored by the Stryker configuration, the one equivalent above, and 144 each run by hand against one named test, all killed. A guard the change touched only for its argument, `checkout !== undefined` in `ReviewHarness.open`, had no killing test; a new one holds that a harness without a checkout leaves a checks task blocked for want of its definition.
