# A Biome rule reports policy reads by object path

[Issue #539](https://github.com/melian-agent/melian/issues/539), part two. `biome/object-by-path.grit` reports a `<revision>:<path>` object name in a function that runs `git show` or `git cat-file`, since such a read skips the revision source's hash check. `blobText` in `packages/core/src/guardrails.ts` is its one grandfathered offender, and [issue #591](https://github.com/melian-agent/melian/issues/591) moves it onto the revision source. [The decision](../decisions/2026-11-20-policy-reads-by-object-id.md) records the rule's limit: it cannot see an argument array built in another function.

`scripts/object-by-path.test.mjs` holds 14 tests, and all pass. With `guardrails.ts`'s exclusion removed from `biome.json`, `npx biome lint packages/core/src/guardrails.ts` exits 1 with the rule's diagnostic, and the grandfather test fails too, since the recorded list then names a file `biome.json` does not exclude. `npx biome lint packages/` reports no other offender.

The first own-build round found that the exclusion covers the whole of `guardrails.ts`, and the grandfather test asked only for at least one offence there, so a second `<revision>:<path>` read added to that file would ship unlinted. With such a read appended to the file, that test passed. The test now records each excluded file's count, one read for `guardrails.ts`, and requires exactly that with the exclusion lifted. With the same read appended it fails with `expected 2 to be 1`, and on the unchanged file all 14 tests pass.
