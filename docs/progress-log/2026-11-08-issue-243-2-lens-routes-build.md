The build of [plan step 37](../design-implementation-plan.md), [issue #243](https://github.com/melian-agent/melian/issues/243), follows [the lens-route rule](../decisions/2026-11-08-lens-routes.md) the maintainer accepted on 2026-11-08. It landed in six pieces on one branch, each its own commit.

- Configuration: `lenses.<name>.route` takes a tier route's keys. Only the root sets its policy keys, a preference file sets `model`, `thinking` and `fallbacks`, a nested file sets none, and a merged route must name a `model` or an `accept`. The route lineage records committed lens routes and the files that changed one.
- The lens: `Lens.configured` ignores a routed lens's `tier`, so neither its levels nor its version move.
- The plan: each routed lens's route resolves with the code that resolves a tier and is stored as `lensRoutes`. A committed route inherits a guarded tier's `acceptOverridden: false` and `unavailable: fail` unless it states its own. A preference route on an unrouted lens moves it, judged level by level under its committed tier, with fallbacks outside a guarded `accept` dropped. `--model` replaces every lens route. Doctor prints a `route` line, each level on the lens route, an ignored tier and each refused level, and compares only budgets between a routed lens's levels.
- The pipeline: every site that took a level's route from its tier asks the plan's lens route first, so a routed lens whose own tier is unrouted runs.
- Stored shapes: the verdict document took version 14, the rounds document version 4 and the adjudication task version 7. Each carries its previous version unchanged, and `packages/pipeline/test/fixtures/lens-routes-main/`, recorded by main at `33138ec`, reopens all three.
- Melian's own policy: `design` runs on its own route, Sol 5.6 at `high`; `medium` returns to Terra at `low`; the routing-only `quick: { tier: light }` lines are gone and `durability`'s `quick` is back on `medium`. Eight lens versions change, as the rule accepted.

Two choices of the builder's own. The inversion check skips the tier comparison for a routed lens and keeps it for every other, reading "compares only budgets between levels that share a route" as applying to routed lenses. A library caller without a plan runs a routed lens on `lenses.<name>.route` as written; with no plan and no verifier route, the verifier still falls back to the finder run's own route, as it does for a tier.
