The round comment's detail cutting now has no mutant that survives or hangs, in fix pass 9 of [pull request #275](https://github.com/melian-agent/melian/pull/275). Its first form was a `while` loop that picked the longest uncut detail on each turn. Five of its 54 mutants survived. Emptying the body, or dropping its `splice`, spun the loop forever, which no test can fail. The loop now sorts the details longest first once, and cuts in that order until the comment fits. A new test in `scripts/round-comment.test.mjs` sizes one detail so the comment is exactly `maxLength` long, and checks that nothing is cut there, and that one character more cuts the longest.
