# 2026-10-22: `melian/review` on merge-group commits, designed

Step 10, required status on `main`, needs `melian/review` on the commit the merge queue tests, or every queued pull request times out after 30 minutes. [The merge-group decision](../decisions/2026-10-22-melian-review-on-merge-groups.md) chooses a `merge_group` workflow that runs `melian status merge-group` from the group's base build and copies the group's own pull request's status onto the group commit. It rules out a pull-request-only requirement, which GitHub does not offer, and a pinned required workflow, which needs GitHub Team.

The design reads the ruleset, the rehearsal's statuses on [pull request #164](https://github.com/melian-agent/melian/pull/164) and the `MergeQueueEntry` schema, all read-only. The workflow and the command are not built yet; the decision lists twenty-one tests the build must have and the ruleset change the maintainer will make.

An attacking review of [pull request #166](https://github.com/melian-agent/melian/pull/166) found that no workflow edit drew the policy notice the trust argument relied on. The root `melian.yaml` now adds `.github/**` to `policy-change-review.files`, and `packages/core/test/guardrails.test.ts` proves an edited, added or renamed workflow and an edited action each draw a P1 notice, and none without the glob. The revision also binds the status to its reviewed base. It records what an admin bypass skips.

A second attack found that a landed earlier link had no pull request number for status validation, and that a bypass merge races `main`. The bypass section now states the race, narrows it with a base check immediately before the merge, and records the split ruleset as the preferred option pending the maintainer's live probe at step 10.

The review of record found two more races in the position rule: a link that lands between the checkout's fetch and the queue read, and a first entry's `baseCommit` read after an earlier entry lands. Three reviews had each found a new race of one class, so the coordinator replaced the rule rather than fix a third instance. The job now validates only its own pull request: the number and SHA from `head_ref`, the head as the group commit's second parent, and an ALLGREEN, `MERGE` queue rule read from the ruleset, failing closed on any other. Under ALLGREEN each entry lands only if its own group passed, so the job reads no queue and walks no earlier link. An attack tested that rule before this revision. The reviewed base now has an exact suffix format, and `melian publish` will refuse to cut a description. A new guardrails test proves a head that strips the `.github/**` glob and edits a workflow still draws the notice.
