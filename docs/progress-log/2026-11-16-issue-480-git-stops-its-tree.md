[Issue #480](https://github.com/melian-agent/melian/issues/480): core's `git` now stops the programs git started when it stops git, at a call's deadline or past `stderrLimit`. Before, it stopped git alone, and a transport such as ssh waiting at a passphrase prompt outlived the call. [The decision](../decisions/2026-11-16-git-stops-the-programs-it-started.md) records the choice and retires the "Child processes" row of the git record store's table.

- `0617000d` moves `ProcessTable`, `terminateRecorded`, `parseProcesses` and their types from `packages/pipeline/src/mutation-process.ts` to `packages/core/src/process-tree.ts`, byte for byte, and pipeline re-exports them. The new file joins `signalFiles` and the pipeline test of that set in the same commit. The commit missed a second test of the set, `scripts/mutation-paths.test.mjs`, which the first full gate found, and `dbe3719c` adds the file there. Pipeline's tests passed unchanged on that commit.
- `ce4d6692` adds `stopTree`, which reads the table once, before any signal, and stops the root and every process below it by recorded pid and start time. It never signals this process or its ancestors, and refuses a root of 1 or below. Core's `git` calls it from `stop`, and a table it cannot read stops git alone, sets `childrenLeft` on a timed-out result, and adds a clause to `gitOutputTooLarge`.
- The real-process test "stops the transport git started, which would outlive git" was written first. On `06861179`, the head it is stacked on, it failed with "expected true to be false": the transport's pid still ran two seconds after the deadline. On `ce4d6692` it passes.
- `afbeb16b` adds a test that `stopTree` ends on a table where pid 0 is its own parent, as macOS's `ps` shows it. A mutant that dropped the ancestor walk's cycle guard survived every earlier test.

Mutants: Stryker's instrumenter lists 64 for `git.ts` and `process-tree.ts` over this range, since `melian mutants list` leaves signal-sending files unmutated. Each ran alone against its named test, which passed unmutated first, in a cloud container. While a `git.ts` mutant ran, `ProcessTable.kill` sent no signal, so every named test used a fake or recording process table.

- 60 killed by their named tests at `ce4d6692`, one of them by a timeout: mutant 52 turns the tree walk into a loop that never ends. Its Vitest worker outlived the runner's stop, and was stopped afterwards by its pid.
- 2 survived the first run. The `childrenLeft = false` default flipped to `true` was paired with the wrong test, and "leaves a command that ends in time as it is" kills it. The cycle guard needed the new test above, which kills it.
- 4 are equivalent: forcing `child.pid === undefined` false, since `stopTree` refuses an undefined root alike; seeding `kept` or `queue` with a string, which no pid matches; and forcing the walk on past an undefined pid, which `parents.get(undefined)` ends.
