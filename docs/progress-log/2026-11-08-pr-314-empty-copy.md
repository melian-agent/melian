[Pull request #314](https://github.com/melian-agent/melian/pull/314), the first of the two high findings in Codex's adversarial review of b231987.

- Every command that opened a pull request's storage pushed its copy when it closed, even when it wrote nothing: a `melian dismiss` with no review to dismiss, or a command that failed before writing. A copy with no files put an empty tree on `melian/state`, so the branch said it held the pull request, and a clone that kept its SQLite storage from before the branch could no longer reserve it to publish. A push now stores a tree only when the copy changed since the branch's. An unchanged or never-written copy moves only the lease, released or kept, and records no write. A copy emptied since the branch stored it is refused rather than pushed. `stores no tree for a copy nothing wrote, and releases the lease`, `records no write for a copy unchanged since the branch's, and keeps the stored tree` and `keeps the lease for a copy nothing wrote yet, without storing a tree` failed first on 6ef02551, then passed. Seven older tests pushed an empty copy and expected the branch to hold it; each now writes a note first, and its outcome is unchanged.
- A failed command that wrote part of a review still stores what it wrote, by design: the next run resumes from it, on any clone.
