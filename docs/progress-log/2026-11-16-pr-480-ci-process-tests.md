On [issue #480](https://github.com/melian-agent/melian/issues/480)'s branch, [pull request #498](https://github.com/melian-agent/melian/pull/498), two of the pull request's real-process tests now pass on CI's runners. CI had failed on every head since `3a375395`. The gate in the cloud container passed each time, and the builder read only the gate's result.

- "reads the process table while git runs, and signals git and its transport by pid" took git to be the transport's grandparent. Git 2.43, in the container, runs the transport one process below git. Git 2.55, on CI, puts one more process between them, so the test expected that process's pid where `git` had rightly signalled git's own first. The transport now walks up to its ancestor whose parent is the test's process.
- "reads this process from the real table, with its start, its command and a state that is not a zombie's" expected the name to contain `node`. CI's Node, on all three versions, renames its main thread `MainThread`, and `ps` prints that. The test now compares the name with what `ps -o comm= -p <pid>` prints. The code needed no change: a record whose name no longer matches is left unsignalled, and the stop says some programs may still run.
- The red runs are CI's, such as [run 43802368283](https://github.com/melian-agent/melian/actions/runs/43802368283) at `eff71604`, with `expected [ 652934, 'SIGTERM' ] to deeply equal [ 652956, 'SIGTERM' ]` and `expected 'MainThread' to match /node/`. The container cannot reproduce either, since its git and Node differ. Both tests pass here after `a14ea5ef`, and CI's run on the pushed head is the passing run.
