`melian dismiss` lands in [pull request #41](https://github.com/melian-agent/melian/pull/41), milestone 2 step 7. It records a dismissal on the finding's lifecycle record in the changeset's local storage, with a required reason of at most 1,000 characters, the git author as the dismisser, and the time, and in the same commit starts an adjudication over the review's stored input, so the verdict counts the finding out at once and a later review attaches to that decision; [the dismissal decision](../decisions/2026-10-04-dismissal.md) says why the dismisser is the git author rather than a GitHub login. A finding adjudication merged from several reports is dismissed whole, a second dismissal replaces the reason and keeps the first in the finding's history, and a changed trigger still reopens it. `melian findings --all` prints dismissed findings with who, when, and why, and `review` and `findings` print each finding's ID. Publication answers a posted finding's thread with the reason once it is dismissed, counts it out of the status, and refuses a verdict a cut-short dismissal left undecided; [the dismissal publication decision](../decisions/2026-10-04-dismissal-publication.md) replaces milestone 1's rule that a dismissed finding was never resolved. The three skills gain the command, with the rule that an agent dismisses only on the user's say-so. The review fixes that followed make a merged dismissal visible and optional: `review` and `findings` list each finding's merged reports, `dismiss` names every report it takes, and `--only` dismisses one alone. An ID matches exactly before the finding it was merged into, an `affected` finding's dismissal is tied to the union of the hunks that proved it and reopens only when one of them changes, so neither the order nor the number of locations the model cites reopens it, publish requires the indexed adjudication to have recorded the stored verdict from the findings as they are, and replies are keyed by finding, thread, and dismissal version, so a changed reason, a merged report's thread, and a reply owed for removed code are each answered. Reports dismissed apart and merged later keep their own dismissals, so neither thread is told the other's reason.
