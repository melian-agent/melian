Round two on [pull request #112](https://github.com/melian-agent/melian/pull/112) found no block. A tool whose resolved path lies in no `node_modules`, such as a `.bin` entry linked to a standalone program, was granted nothing, so inside the sandbox it could not start and the check read `toolMissing` where main ran it. It is now granted as its one file, readable and startable, with nothing beside it, under seatbelt and bubblewrap alike. A version probe that exits 126 or 127 is `toolMissing`, and any other failure is `toolFailed` with the tool's message. Enola's record now says `unconfined`, with the reason "not yet confined", so that no record implies a confinement that did not happen; that is one line on every review whose tier runs Enola. The GitHub guideline's version numbers for the verdict and published documents are corrected, and two TSDoc blocks on internal symbols become plain comments. [The grants decision](../decisions/2026-10-13-seatbelt-profile-grants.md) and [the confined-tools decision](../decisions/2026-10-13-static-tools-run-confined.md) carry the reasons.
