[Pull request #43](https://github.com/melian-agent/melian/pull/43) writes the convention the maintainer asked for into AGENTS.md as a rule a lens can quote: behaviour belongs to the object it is about, so a function whose first parameter is a `Finding`, `Defect`, `Verdict`, `Manifest`, `Lens`, `Revision`, or `Changeset`, or an array of one, is a method. The rule has no layering carve-out: an outer package adapts a core object through a class of its own, such as `ReviewComment.from(finding)` in github. [decisions/2026-10-04-domain-objects-carry-behaviour.md](../decisions/2026-10-04-domain-objects-carry-behaviour.md) supersedes the class convention, folding its whole choice in, and says where the rule departs from Pi: Pi's stored records are plain data with behaviour on services, while Melian's objects accumulate behaviour across the verifier, triage, and the ledger.

Two checks hold Melian's code to the rule. The `free-domain-function` guardrail in the root `melian.yaml` matches the first parameter's type and catches the common single-line case on every changed line under `packages/*/src`, from the next review of Melian's own pull requests. It tests each added line alone, so it misses a signature Biome wraps over several lines. The Biome GritQL rule `biome/free-domain-function.grit` reads the syntax tree and catches that and other forms. It scans whole files, so `biome.json` excludes the eleven files that break the rule today until [step 12](../design-implementation-plan.md) refactors them. `scripts/free-domain-function.test.mjs` runs Biome with the rule over scratch files and holds the exclusion list to the files the guardrail's pattern matches.
