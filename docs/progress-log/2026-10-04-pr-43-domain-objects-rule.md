[Pull request #43](https://github.com/melian-agent/melian/pull/43) writes the convention the maintainer asked for into AGENTS.md as a rule a lens can quote: behaviour belongs to the object it is about, so a function whose first parameter is a domain object is a method of that class. The root `melian.yaml` gains the `free-domain-function` guardrail, which holds new code to the rule from the next review of Melian's own pull requests, on every line a change adds; the eleven files that break it today wait for [step 12](../design-implementation-plan.md) to refactor core's domain types into classes. [decisions/2026-10-04-domain-objects-carry-behaviour.md](../decisions/2026-10-04-domain-objects-carry-behaviour.md) supersedes the class convention, folding its whole choice in, and says where the rule departs from Pi: Pi's stored records are plain data with behaviour on services, while Melian's objects accumulate behaviour across the verifier, triage, and the ledger. The guardrail tests each added line alone, so it misses a signature Biome wraps over several lines. The Biome GritQL plugin `biome/free-domain-function.grit` reads the syntax tree and catches it; it scans whole files, so it carries the grandfather list. `scripts/free-domain-function.test.mjs` runs Biome with the plugin over scratch files. The rule has no layering carve-out: an outer package adapts a core object through a class of its own, such as `ReviewComment.from(finding)` in github.
