# The decision for `melian mutants verify` is proposed

[Issue #240](https://github.com/melian-agent/melian/issues/240)'s first deliverable is a decision before any code. [The shards decision](../decisions/2026-11-13-mutants-verify-runs-stryker-in-shards.md) sets the rules for the maintainer's reshape of 2026-11-10. Stryker runs over the changed lines with per-test coverage under the base's configuration, sharded across Blacksmith runners by a plan job that runs no head code. A cache entry is Melian's own record of kills, signed and applied only by jobs that run no head code, under one installation, policy and Melian build; shards run Stryker cold. A survivor is answered by a new test, a reason or a hand proof, and only the newest run sets `melian/mutants`. An attacking review and Codex's adversarial review of the first revision found that a force-push could reuse a stale kill and that one pull request's tests could write another's cache; revision 2 closes both. Four choices go to the maintainer: who accepts an answer and where it lives, what a timeout is, how many failures prove a kill, and whether a kill is reused from an earlier head. It awaits the maintainer's ruling. Plan step 34 and `docs/design.md` name it. No code changed.
