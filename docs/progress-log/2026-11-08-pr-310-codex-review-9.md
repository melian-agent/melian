[Pull request #310](https://github.com/melian-agent/melian/pull/310), fixes for Codex's adversarial review of 7dd15b84, under the maintainer's rulings of 2026-11-08.

- A fetch or push could wait forever, holding the copy's lock, on a remote that asked for credentials: core's `git` left the child's input open when it gave none. Core now ends it, and state-git runs fetch and push with `GIT_TERMINAL_PROMPT=0`. `gives git an ended input when it is given none, so a command that reads it cannot wait forever` timed out first, and `never lets a fetch or push wait on a credential prompt` failed first, on 7dd15b84.
- A stalled transfer could still hang. The maintainer ruled for git's own limit: fetch and push run with `http.lowSpeedLimit=1` and `http.lowSpeedTime=60`, through `GIT_CONFIG_COUNT`, so a minute's stall fails and the branch reads as out of reach. `has git abort a fetch or push that stalls for a minute` asks git itself, under each recorded environment, for both settings; it failed first. An SSH remote is bounded only by its own settings.
- A damaged `doc-*` or `task-*` sidecar passed the main-log check that review 8 added: the second round in a row with a new kind of local damage. Raised as a class, the maintainer ruled that Pi's own storage judge the copy. `StateBranchOptions.validate`, which the CLI implements with `openJsonlStorage`, opens it before a checkout keeps it, and a copy it refuses is set aside for the branch's. The main-log check stays, since Pi reads a missing main log as an empty store. `restores the branch's copy over a document sidecar deleted since it synced` and `… cut short since it synced` failed first; ignoring `validate`'s answer fails both.
