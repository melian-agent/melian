[Pull request #314](https://github.com/melian-agent/melian/pull/314), the high finding in Codex's adversarial review of f54d1a61, under the maintainer's ruling of 2026-11-08.

- `publish` checked the lease once, before its first post. A publisher that stalled past the lease's two hours, while another clone took the lease and published a newer round, could then overwrite that round's status, review or ledger, and only its final push would notice. The publish task now runs a fence before every write to the provider, beside its check that the pull request has not moved, and the CLI renews the lease there through `ChangesetStore.checkpoint`. A fence that fails ends the task as `staleTarget`, posting nothing more and counting no refusal against the round.
- `renews the lease on melian/state before every write to GitHub` and `posts nothing more once melian/state refuses the lease` failed first on a30b9ab6: the second write went out with no checkpoint before it, and a refused lease published on. Both pass. `stores the publication's storage before it posts` asserted exactly one checkpoint, which the ruling changes; the first test covers what it held, so it is removed.
- Mutants run by hand, each killed: the fence not awaited, not installed in the extension, not passed through `openPublishHarness`, not given by the CLI, and its rejection not turned into `staleTarget`. The last first survived, since a raw failure also posts nothing before posting starts; the test now asserts the `staleTarget` code.
