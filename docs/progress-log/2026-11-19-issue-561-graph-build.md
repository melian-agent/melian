# Issue 561: the parity run builds Enola's graph of each miss's head

A parity review opened Enola's graph from the cache only, and nothing ever filled the cache, so the graph tools refused in both arms. Each design lens ran without its callers, though the measurement claims to compare arms that both have them. The coordinator asked on 2026-11-19 that the run build the graph with the call the CLI's `static.enola` check makes, only for a vouched head, and record it.

Before a miss's first review, `buildGraph` in `packages/evals/src/goldens.ts` runs `runStaticTool` with the CLI's input: the merge base, the head, the policy commit's Enola settings with `enabled: true`, and the policy commit itself. Both arms then open the graph from the cache. The function returns the head's snapshot ID, and each attempt records it as `graph`. Enola reads the head's own configuration, so a head that `MELIAN_EVAL_PROBE_TRUST` does not vouch for is refused before Enola runs. If the build fails, Enola skips, or no snapshot of the head comes back, the miss is unscored. Its committed attempt says why, and its parity arm is not run, so no review runs without callers. A resume keeps that miss unscored. A dry run says whether each scorable miss's graph is cached, through `graphCached`, and builds none.

Tests: four in `packages/evals/test/parity.test.ts` cover the run, and five in the "an arm that needs the graph" block of `packages/evals/test/probing.test.ts` cover `buildGraph` and `graphCached` with a fake `runStaticTool` and a spied `CallerContext.open`. The entry test in `packages/evals/test/parity-entry.test.ts` checks that the live entry hands `measureParity` the real build. No test runs Enola itself. The pilot's dry run and first live review stand in for one: they build each miss's graph on the host, and the run record names the snapshots.

Mutants: `node scripts/enumerate-mutants.mjs` over the pass listed 57. A scratch script ran each one by hand against its named test, as an anchored pattern that collected exactly one test, and all 46 claimed mutants were killed. The other 11 are string literals that the enumerator's configuration ignores. The first run showed one survivor: the run could save the unscored attempt after printing its line rather than before. The failing-build test now reads the results file when that line prints, and kills it.
