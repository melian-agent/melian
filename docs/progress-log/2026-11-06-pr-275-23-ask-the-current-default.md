The round job's stale-rerun check now asks the repository which branch is the default, in fix pass 3 of [pull request #275](https://github.com/melian-agent/melian/pull/275). Codex's adversarial review of fec68ba found that the check took the default branch's name from the run's event, which a rerun replays. If the repository made another branch the default, and the old one still pointed at the run's commit, the rerun passed. This is the second review running with an instance of the stale-rerun class, so the check now takes both answers from the authority, the repository's current state: its `default_branch`, and that branch's commit, against the run's `github.ref` and `github.sha`. Nothing the event carries is left for a rerun to replay. A failing test first passed the old step after the default became `trunk`. Its fake `gh` answers only those two requests and keeps the old default at the run's commit. Six hand mutants of the step each fail it: dropping either read's fallback, inverting either comparison, skipping the ref check, and asking for `main`'s commit in place of the current default's.
