# The record store sweeps what a killed call left

[Issue #460](https://github.com/melian-agent/melian/issues/460) closes the last open row of the git record store's resource table: a temporary index, a half-made repository or a fetch ref that a killed call, or a call cut off at its deadline, left behind. Each is now named after its owner, a hash of the host's name and the pid, in `packages/state-git/src/owner.ts`. Opening the store sweeps the state directory, in `RecordRepository.sweep`, and removes a leftover only once core's `ProcessTable`, which [issue #480](https://github.com/melian-agent/melian/issues/480) moved into core, lists no process with its pid on this host. It keeps what it cannot prove gone, a reused pid's leftover included, and `melian doctor`'s `records` line names it. [The sweep decision](../decisions/2026-11-16-record-store-sweeps-what-a-killed-call-left.md) records the method, the coordinator's choice of approach on 2026-11-16, and the host hash's limit.

`packages/state-git/test/sweep.test.ts` holds 17 tests, written first. Before the code, 16 failed for the missing sweep or the names' missing owner. The seventeenth passed then, as it must: it asserts that a name falls back to a plain UUID when this process is not in the table, which every name was before. A live owner is a real child process the test spawns, records by pid and stops by that pid; its leftovers survive a second handle's sweep. A fake table plants a leftover between the listing and the table read, and the leftover is kept. Five tests in `packages/cli/test/doctor-record-store.test.ts` assert the whole `records` line for a kept leftover, seven kept and a control character, an unreadable table, a failed removal, and a sweep that removed all it found; the first four failed before the change because the line said nothing of the sweep.

The first form compared the start time `ps` printed when a call named its leftover with the one it printed at sweep time. Codex's adversarial review found that `ps` prints that time in the caller's time zone and locale, so a sweep run under another `TZ` read a live call as gone and removed its index. A test written first, "keeps what a live process holds when the sweep reads the table under another time zone", names a leftover under `TZ=UTC` and sweeps under `Australia/Sydney`. On the start-time code it failed, with every leftover removed; on the fix it passes. The coordinator chose on 2026-11-16 to drop the start time and remove a leftover only when its pid is absent. The tests now also show a leftover whose pid another process holds kept and named, one whose pid the table does not list removed, and a plain UUID name when the table lists this pid with another parent, or this parent with another pid. `packages/state-git` passes 205 tests.

Codex's second review found two more gaps, each fixed test-first. Doctor dropped the sweep's notes when the branch read failed after the store opened; a test with an unreachable origin and a kept leftover failed with no sweep note on the line, and passes now. The sweep ignored the open's deadline while it removed leftovers. The coordinator chose on 2026-11-16 to stop removing once no time is left and count the rest as unswept. Two tests on a fake clock, one at the bound with 1 ms left and one past it with none, failed with every leftover removed; they pass now, and the second shows the next open finishing the sweep. Two doctor tests show the count. `packages/state-git` passes 207 tests, and `doctor-record-store.test.ts` 25.
