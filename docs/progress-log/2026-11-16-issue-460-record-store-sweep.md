# The record store sweeps what a killed call left

[Issue #460](https://github.com/melian-agent/melian/issues/460) closes the last open row of the git record store's resource table: a temporary index, a half-made repository or a fetch ref that a killed call, or a call cut off at its deadline, left behind. Each is now named after its owner, a hash of the host's name, the pid and the start time `ps` gives, in `packages/state-git/src/owner.ts`. Opening the store sweeps the state directory, in `RecordRepository.sweep`, and removes a leftover only once core's `ProcessTable`, which [issue #480](https://github.com/melian-agent/melian/issues/480) moved into core, shows its owner gone on this host. It keeps what it cannot prove gone, and `melian doctor`'s `records` line names it. [The sweep decision](../decisions/2026-11-16-record-store-sweeps-what-a-killed-call-left.md) records the method, the coordinator's choice of approach on 2026-11-16, and the host hash's limit.

`packages/state-git/test/sweep.test.ts` holds 17 tests, written first. Before the code, 16 failed for the missing sweep or the names' missing owner. The seventeenth passed then, as it must: it asserts that a name falls back to a plain UUID when this process is not in the table, which every name was before. A live owner is a real child process the test spawns, records by pid and stops by that pid; its leftovers survive a second handle's sweep. A fake table plants a leftover between the listing and the table read, and the leftover is kept. Five tests in `packages/cli/test/doctor-record-store.test.ts` assert the whole `records` line for a kept leftover, seven kept and a control character, an unreadable table, a failed removal, and a sweep that removed all it found; the first four failed before the change because the line said nothing of the sweep.
