# 2026-10-23: step 24 redesigned around a coverage ledger

On 2026-10-23 the maintainer ruled on [pull request #185](https://github.com/melian-agent/melian/pull/185): the delta is "any changed code that wasn't covered by the checks at the level configured for it", a round reviews exactly the delta, and "any series of reviews that together cover the full diff at the configured level for the files in the diff, are a valid review". The earlier design's rule that only a full round approves goes. The pull request replaces its decision and design with [decisions/2026-10-23-coverage-ledger-and-delta-review.md](../decisions/2026-10-23-coverage-ledger-and-delta-review.md) and [design/coverage-and-delta-review.md](../design/coverage-and-delta-review.md). A coverage ledger, `melian.coverage`, in the changeset's storage records for each changed line and each check which round covered it, at what level and under what identity, built on the review-coverage artifacts plus the hunks each lens's prompt rendered. A line is covered when the base, policy and standards match, it maps unchanged through git, every lens that applies received it in a run recorded `ran` at the required level, and every finding on it is settled at the head. Nine voids restate the earlier anchor rules; `--cold` reviews the whole diff. Stryker mutates the delta's production lines and every carried survivor's line from nothing, so the mutation partition is no longer handed to Stryker and the cold final run is no longer required. The round key stays `<base>..<head>` from one method, `Revision.key(scope)`, which build 0 routes `revisionKey()`'s 54 call sites through; approval comes from the ledger's empty delta, not the key. `melian/review` passes on an empty delta with nothing above advisory open, and the merge-group job is unchanged. For milestone 3, writers and the GitHub App push the ledger to `melian/state`, one writer per changeset by lease, a refused push resumes from the branch's copy, and the agent recomputes the mapping, voids and policy fingerprint itself and accepts no round of a fork's head, a worktree policy or a non-writer's push; no signature is needed while writers are trusted. The decision amends eight decisions, each with a scope, and numbers twelve trust and blocking rules for the attack. The plan's step 24 now has four milestone 2 pull requests of about 600, 1,800, 2,400 and 700 lines, with a fourth golden that plants a defect in unchanged code to measure the residual, and two milestone 3 pull requests for the state branch and the agent.
