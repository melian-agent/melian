Melian's eighth round on [pull request #89](https://github.com/melian-agent/melian/pull/89) confirmed five findings. A check run's identity now includes Melian's bundled tool pins, so a build that pins another Enola runs the checks again instead of returning the finished run of the old one. A tool the host cannot check, such as a platform with no pin or a cache path lstat cannot read, shows as `unavailable` in `melian tools` and as a warning in `melian doctor`; only a cached entry that fails its pin is a mismatch and fails doctor. The cache scratch sweep is best effort, so a read-only or unreadable cache still opens and readiness reports not fetched; [the pipeline guideline](../guidelines/pipeline.md) says so. A test now proves a lens record carries the graph coverage ID.
