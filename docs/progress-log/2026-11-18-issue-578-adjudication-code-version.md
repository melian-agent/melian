# A repeat review decides again when the adjudication code changes

[Issue #578](https://github.com/melian-agent/melian/issues/578): a repeat review at the same head and inputs attached to the verdict an older build had decided, so it printed that build's verdict after the deciding code changed. This builds the mechanism the maintainer ruled for [issue #437](https://github.com/melian-agent/melian/issues/437) on 2026-11-16, with adjudication as its first producer, and [the decision](../decisions/2026-11-18-code-versions-from-recorded-hashes.md) records it.

`scripts/code-hashes.mjs` asks TypeScript which modules `packages/pipeline/src/adjudication.ts` reaches, 114 of them, and writes each one's path and hash to `packages/pipeline/src/code-hashes.ts`. `codeVersion("adjudication")` digests those lines. The task's input carries it as `code`, and `adjudicationKey`, which the review and the dismissal share, is that input in canonical JSON. `scripts/code-hashes.test.mjs` fails the gate when a module changed without its line or the reached set changed without its list, and shows two edits to neighbouring modules merging cleanly. The pack step in `.github/workflows/check.yml` reads `codeVersion` from the installed tarball, which ships no source.

The failing test came first. `review.test.ts`'s "decides again when the build's deciding code differs" failed at `c9b138aa5`, before the key change, with `expected 59 not to be 59`: the repeat review attached to the stored task. It passes at `80a23208e`. `adjudication-key-reopen.test.ts` reopens a store main wrote at `a69fac993`, captured by `test/fixtures/adjudication-key-main/capture.mjs`, and shows it decides again once and attaches after. Three tests in `rounds.test.ts` that attach to main's older stored round now give its key this build's `code` first, since they test the round an attachment keeps, not the key.

The files that guard trust or durability are `adjudication.ts`, `review.ts`, `dismiss.ts`, `code-version.ts` and `scripts/code-hashes.mjs`. [The inventory](2026-11-18-pr-579-adjudication-code-version-mutants.json) is `melian mutants list origin/main...HEAD --json --all`, claims in the four files with mutants. `dismiss.ts` is left out of `--claims-in`: its one changed line, the destructuring that drops `code` from the stored input, has no Stryker mutant, and the sampler refuses a claim file with none. The dismissal tests in `dismiss.test.ts` run through it.

Each of the 142 claimed mutants ran by hand at `08b25258a`, alone against its named test, which passed unmutated first. 109 were killed by existing tests. 33 survived, all in `scripts/code-hashes.mjs`: its failure paths, the sorts that fix the record's order, the scratch cleanup, the import guard and the formatting step. Ten new tests in `scripts/code-hashes.test.mjs` kill 29 of them. The other 4 are equivalent, each with its reason in the inventory.

Codex's adversarial review found that `hashOf` hashes the bytes as checked out, so a checkout with `core.autocrlf=true` would hash CRLF and fail the gate on every module. "records the same hashes from a checkout that converts line endings" in `scripts/code-hashes.test.mjs` reproduced it first, with every hash moved. `.gitattributes` now checks TypeScript out with LF on every platform, which Biome already expects, and the test passes. Git does the conversion; the script strips nothing by hand.

Its second finding was version skew: builds share a store, so a build could resume an adjudication task another build created and decide it under its own code, leaving that verdict under the other build's key. The input now carries `code`, the task is version 8, so an older build refuses it, and the phase fails a task whose `code` is not the running build's, saying why. A failed adjudication is decided again on the next review. Two tests came first. "decides nothing on an adjudication task another build's code created, and says why" in `review.test.ts` failed with the task completed rather than failed. "fails a version 7 task main left pending, which names no code version, and decides again on the next review" in `adjudication-key-reopen.test.ts` reads `test/fixtures/adjudication-key-main/pending.sqlite`, a task main's own code created and left pending, captured by `capture-pending.mjs`, and failed the same way. Both pass with the guard. Three `rounds.test.ts` tests that resumed main's pending task and expected it to decide now expect it to fail and to write no round or verdict.

Five more reopen tests asserted the task's version 7, and now assert 8. Three expected an older task to decide and now expect it to fail: the version 1 and 2 merging cases in `stage-telemetry-reopen.test.ts`, the version 6 routes case in `lens-routes-reopen.test.ts`, and the adjudication cases in `thinking-reopen.test.ts`. So an older input's snippet merging, caller caveat and routes no longer decide through the task; the migrations still run, and the dismissal still reads a migrated input. `stage-telemetry-terminal.test.ts` gives its task this build's `code`, so it still reaches the superseded check it tests.

[The guard's inventory](2026-11-18-pr-579-code-guard-mutants.json) is `melian mutants list 3353ac878...d7af4a0fa --claims-in packages/pipeline/src/adjudication.ts --claims-in packages/pipeline/src/dismiss.ts --json --all`. Each of its 15 claimed mutants ran by hand at `d7af4a0fa`, alone against its named test, which passed unmutated first, and all 15 were killed. Two, `codeVersion("")` in the guard and in `adjudicationInput`, first survived "decides again when the build's deciding code differs", because `review.test.ts` mocks `codeVersion`. Both fall to the reopen test of main's pending task, which runs the real one, so the inventory names that test. The one row left without a claim is a hash string in `code-hashes.ts`, outside `claimsIn`.

The `melian round` workflow's round at `697c6ca5c` found that no test checks the dismissal setting its own build's `code`: deleting that line from `recordDismissal` left every test passing, since each dismissal test reviews and dismisses under one build. "dismisses under the dismissing build's code a review another build decided" in `review.test.ts` reviews, switches the mocked code version, and dismisses. With the line deleted it failed with "the dismissal is recorded, but the verdict was not decided again: another build's adjudication code created this task"; with the line it passes, and the stored input carries the new version.
