# A repeat review decides again when the adjudication code changes

[Issue #578](https://github.com/melian-agent/melian/issues/578): a repeat review at the same head and inputs attached to the verdict an older build had decided, so it printed that build's verdict after the deciding code changed. This builds the mechanism the maintainer ruled for [issue #437](https://github.com/melian-agent/melian/issues/437) on 2026-11-16, with adjudication as its first producer, and [the decision](../decisions/2026-11-18-code-versions-from-recorded-hashes.md) records it.

`scripts/code-hashes.mjs` asks TypeScript which modules `packages/pipeline/src/adjudication.ts` reaches, 114 of them, and writes each one's path and hash to `packages/pipeline/src/code-hashes.ts`. `codeVersion("adjudication")` digests those lines, and `adjudicationKey`, which the review and the dismissal share, puts it in the attach key as `code`, in canonical JSON. `scripts/code-hashes.test.mjs` fails the gate when a module changed without its line or the reached set changed without its list, and shows two edits to neighbouring modules merging cleanly. The pack step in `.github/workflows/check.yml` reads `codeVersion` from the installed tarball, which ships no source.

The failing test came first. `review.test.ts`'s "decides again when the build's deciding code differs" failed at `c9b138aa5`, before the key change, with `expected 59 not to be 59`: the repeat review attached to the stored task. It passes at `80a23208e`. `adjudication-key-reopen.test.ts` reopens a store main wrote at `a69fac993`, captured by `test/fixtures/adjudication-key-main/capture.mjs`, and shows it decides again once and attaches after. Three tests in `rounds.test.ts` that attach to main's older stored round now move its key to the current form first, since they test the round an attachment keeps, not the key.

The files that guard trust or durability are `adjudication.ts`, `review.ts`, `dismiss.ts`, `code-version.ts` and `scripts/code-hashes.mjs`. [The inventory](2026-11-18-pr-579-adjudication-code-version-mutants.json) is `melian mutants list origin/main...HEAD --json --all`, claims in the four files with mutants. `dismiss.ts` is left out of `--claims-in`: its one changed line, the destructuring that drops `code` from the stored input, has no Stryker mutant, and the sampler refuses a claim file with none. The dismissal tests in `dismiss.test.ts` run through it.

Each of the 142 claimed mutants ran by hand at `08b25258a`, alone against its named test, which passed unmutated first. 109 were killed by existing tests. 33 survived, all in `scripts/code-hashes.mjs`: its failure paths, the sorts that fix the record's order, the scratch cleanup, the import guard and the formatting step. Ten new tests in `scripts/code-hashes.test.mjs` kill 29 of them. The other 4 are equivalent, each with its reason in the inventory.
