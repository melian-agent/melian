`ReviewPlan.resolve` now keeps each route, `accept` or `--model` entry the catalogue does not hold on its tier as `unknown`, and `warnings()`, doctor's `lines()` and the review's `summary()` report it with the file that set it and, for an unknown provider, the provider. Before, a misspelt model ID or a renamed provider (`azure-openai-responses` became `azure` in Pi 1.1.0) ran on a fallback unannounced. The review is not refused, since a newer pi-ai may hold the model, so no decision file. Failing tests were written first; seven hand mutations each fail one.
