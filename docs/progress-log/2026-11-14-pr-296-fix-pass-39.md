For [pull request #296](https://github.com/melian-agent/melian/pull/296), fix pass 39 finishes [issue #350](https://github.com/melian-agent/melian/issues/350) and stops a replaced review's probe reruns. Codex's adversarial review found the second at `fe066ec0`.

- **The whole index entry** (`12423ddb`). Four tests in `test/probing-level.test.ts` that replace a review now assert that the replacing review's index entry stands whole after the replaced review ends. With the earlier assertions removed and the source at `10046215`, four of the five failed, as `expected { task: 9, …(4) } to deeply equal { task: 9, …(3) }`. The link test passed there, because its stale write goes to the findings' links, which its own assertion covers. With this, the pull request closes #350, whose condition "ends without error" now reads "ends superseded and writes nothing", as the coordinator answered on the issue.
- **No rerun after the lens task is gone** (`2e1aafcf`). A review whose lens task another replaced kept launching its remaining probe reruns when the replacing review had nothing to verify, since the rerun task checked only its own record in `ProbeReruns`, which that review never takes over. The rerun task's input now carries the lens task, and the task asks `stillOwns` before each launch. The new test, `launches no further rerun once another review with nothing to verify replaces its lens task`, failed first at `12423ddb` with `expected [ …(4) ] to have a length of 3 but got 4`, and passes after the fix. The coordinator chose to fix it here on 2026-11-14. [The decision](../decisions/2026-11-14-a-replaced-review-writes-nothing.md) now records why nothing read the stale runs as evidence.

- **CI's failure on every Node version** (`04495e21`). Pass 38's test `records no verdict for a review whose verification a review sharing its lens task replaced before it links` and its `adjudicates` twin assumed the second review attached to the first's live lens task, and nothing held that task live. On a loaded runner it finished first, the second review started a lens task of its own, and the test timed out or hung. Six parallel runs at a time on this machine reproduced it: 2 of 12 failed at the 5-second timeout, and 1 of 24 hung for the whole 60 seconds of a raised timeout. The first review's planner now waits until both reviews wait on its lens task, as the file's test of a live run under another writer already does. After the change, 108 of 108 cases passed in 54 runs six at a time, and with `stillOwns`'s verification check forced true both cases still fail with `expected undefined to match object { code: 'superseded' }`. Only the test changed. [Issue #435](https://github.com/melian-agent/melian/issues/435) has the same cause in another test and stays open.

`melian.probe-reruns` is new in this pull request, so its input gains an optional field with no version bump and no stored input of the old shape to reopen. The attach key still hashes `input.probes` alone. `runs a probe again once when two reviews of one head verify at once` and `goes on to verify when a review sharing its lens task starts a rerun of the same probes again` passed three runs in a row.

No existing assertion changed. A user sees no new behaviour: the replaced review still ends `superseded`, sooner.
