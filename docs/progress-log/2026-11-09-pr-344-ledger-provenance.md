A fix pass on [pull request #344](https://github.com/melian-agent/melian/pull/344), for [issue #342](https://github.com/melian-agent/melian/issues/342), after Codex's adversarial review at 940d99e8 raised one high finding. The ledger named a closed dismissal's root by joining the closed record to the current verdict by finding ID. A head keeps an answered dismissal's record after the finding is dismissed again. So once that finding inherited from root B, an earlier closure inherited from root A read as B. Once a person dismissed it, the earlier closure lost its root.

Fix commit b99026a9 stores the root on each closed record, beside the reason, from the dismissal the record was written from. Both writers in `packages/pipeline/src/publish.ts` take it through `ledgerDismissal`. `Ledger.render` reads it from the record, and the join to the verdict is gone. `LedgerRound.resolved` in core gains an optional `inheritedFrom`. The published document stays at version 10: an older Melian cannot open a newer document at all, and a record it wrote has no root, so it reads with no inherited label. `docs/guidelines/github.md` says so.

The test in `packages/github/test/publish.test.ts` publishes three dismissals of one finding at one head: inherited from A, then from B, then a person's. It failed at 940d99e8 with A's closure labelled B, and passes with the fix. Only a review links a restatement to its root, so the test writes the root into the stored verdict and round.
