A `melian.yaml` takes `resolution.checks`, keyed by check name, each entry with a mapping, a `ceiling`, and `rules` by rule ID, and `resolution.preExisting`, which caps pre-existing findings at `advisory` or `acknowledge`. A lens declares a default in `LENS.md`. The loader keeps each file's own `resolution` key, and core's `ResolutionWalk` stops at the nearest file that speaks, which decides mapping and ceiling both. A merged defect resolves each report under its own check, rule, severity, and caps, and takes the strictest; the floors then apply to the defect. A guardrail finding names the configured rules it matched, or its notice class, in a typed field outside its ID, so a rule resolves under `guardrail/<name>/<rule>`. The findings and verdict documents rose to version 8, with a fixture step 17's code recorded and a reopen test. A change to a `resolution` key in any `melian.yaml`, or to a lens's declared resolution, always draws the policy-change notice, never below `acknowledge`. `melian findings` and `melian review` name the file and entry that decided each finding, and `melian doctor` lists what each file's resolution overrides.
