A mutation inventory can now say which files' mutants owe a claim, for [issue #418](https://github.com/melian-agent/melian/issues/418), in [pull request #422](https://github.com/melian-agent/melian/pull/422). [Pull request #419](https://github.com/melian-agent/melian/pull/419) narrowed the proof to code that guards trust or durability, but the sampler could not tell those files from the rest, so a builder still claimed every row. A builder who deleted the other rows by hand left nothing to check the result against.

`melian mutants list <range> --claims-in <file>`, and the enumerator script's `--claims-in FILE`, record `claimsIn` in an inventory that still lists every mutant of the range. `--sample` checks and samples only those files' rows, and still refuses an unclaimed row inside them or an inventory with omitted mutants. `melian mutants list <range> <file>...` still filters a listing for reading, as the coordinator asked on 2026-11-14. That listing records the files as `limitedTo`, under a different name so the two can't be confused, and the sampler and verification refuse it. Codex's adversarial review of `c1bde3d6` found that the enumerator script, whose output has no version, could write a filtered listing that main's sampler would accept as whole, because that format lets it ignore `limitedTo`. The script now refuses files after the range and names the CLI command. Its test feeds every filtered listing this build can write to main's sampler, committed as `scripts/fixtures/sampler-528edd15/`, and failed on `c1bde3d6` because that sampler accepted the script's. Main's sampler refuses an inventory that carries `claimsIn` unless every row has a claim, which is the safe direction. Each named file must be one the range changes, so a typo is refused by name and never reads as a file with no mutants. Both fields are optional and the inventory keeps version 2, so every existing inventory reads unchanged. An older Melian refuses a version-2 inventory that carries either field. It does not refuse the script's unversioned output, which is why the script writes `claimsIn` alone. A `claimsIn` file that holds no mutant is refused when sampled, since nothing would prove it, and the sample notes ignored rows only for the files that owe claims. AGENTS.md's Briefs and [the review-of-record brief](../review-of-record.md) now name `--claims-in`, and the brief makes a listed trust or durability file missing from `claimsIn` a P2 finding.

`packages/core/src/mutation-inventory.ts` and `scripts/mutant-sample.mjs` decide what the sampler accepts, so the pull request lists both as guarding trust.
