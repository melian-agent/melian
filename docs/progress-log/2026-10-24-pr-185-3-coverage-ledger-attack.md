# 2026-10-24: the coverage ledger design tightened after its attacking review

A Fable attacking review of [pull request #185](https://github.com/melian-agent/melian/pull/185) at `00520c2a` held the design with changes and failed one rule: a lens could drop a carried finding by refuting its ID through escalation's hand-off with no verifier, past the trust floor, which reads verifier verdicts alone. [The decision](../decisions/2026-10-23-coverage-ledger-and-delta-review.md) now makes a lens's refutation of a carried finding a verifier candidate, never a drop, and keeps a protected claim's trust-floor minimum through it. It also refuses `review.coverage` in any tier or `checks.allowSkip`, since a base `melian.yaml` could otherwise let `Manifest.complete()` pass over a gap; reads lens transcripts and stored prompts itself, because the review-coverage artifact exists only with Enola's graph; computes the delta from the last decided round, since a crashed round has no ledger record; renders the hunks that fit smallest file first and names a hunk no prompt can carry, because `ChangePrompt.renderInput` renders nothing when one file exceeds the cap; voids a provisional record and a head that cannot be resolved, and voids mutation coverage whole on any test, fixture, snapshot or test-imported non-production change, the recorded test list being head-written; carries lens sightings only, and deletes them on `--cold`; keeps `maxLines` omissions uncovered until mutated; names every hand-built key site, display sites included; says the agent voids a head GitHub no longer holds and every mutation record from another Node runtime, and that a writer refuses a live lease; and states the residual in degree, with a cross-round golden to measure it. Dropping the cold final Stryker run is marked pending the maintainer's confirmation.
