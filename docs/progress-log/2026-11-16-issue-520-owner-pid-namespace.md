# A leftover's owner names its pid namespace

[Issue #520](https://github.com/melian-agent/melian/issues/520) stops the record store's sweep from deleting a live call's files when two containers share a host name and a state directory but not a pid namespace. On Linux the owner key now hashes the host's name with the device and inode of `/proc/self/ns/pid`. Where that read fails, a call's names hold no owner, and no sweep removes them. macOS keeps the host's name alone. [The namespace decision](../decisions/2026-11-16-leftover-owner-names-its-pid-namespace.md) records the method and its one remaining limit.

Four tests in "the owner's process namespace", in `packages/state-git/test/sweep.test.ts`, stand another namespace in for `/proc/self/ns/pid` through a mock of `node:fs`. Three were written first and failed on the old key. The first names one exited call's leftover under another namespace and one under this one, using the store's own naming, and sweeps. On the old key it failed with the other namespace's leftover removed, the reported defect. The second failed because the name ignored the namespace. The third failed because a failed namespace read still gave an owner. The fourth, on macOS, passed before and after, as it must: the sweep keeps working there by host name. `packages/state-git` passes 220 tests.

The fix's mutants are in `2026-11-16-issue-520-mutants.json`, enumerated over `e0712b6c...78945daf` with `--claims-in` naming `owner.ts`. All 11 generated there are killed, each by one named test run alone at 78945daf after it passed unmutated, and the runner checked each mutant replaced exactly the text it names. String literals, the namespace's path and the separator among them, are ignored by the enumerator's configuration.

Codex's review of [pull request #519](https://github.com/melian-agent/melian/pull/519) at 083ce20a found that the sweep's listing read any `lstat` failure as an entry another call had removed. So an entry that stayed but could not be stat'ed, on EIO or EACCES, was skipped without a word: not kept, not failed, and the sweep not `unlisted`. The coordinator added it to this issue on 2026-11-16. The listing now passes over only ENOENT, and any other failure fails the listing, which the sweep reports as `unlisted` and removes nothing. Two tests make `lstat` fail with EIO on a half-made repository and on a temporary index. Both failed first, with the other three leftovers removed and nothing reported, and pass now. The state-git and doctor suites pass, 253 of 253.
