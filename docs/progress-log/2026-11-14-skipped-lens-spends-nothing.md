A round that skipped a lens posted its duration but not its tokens or cost, for [issue #408](https://github.com/melian-agent/melian/issues/408). [The round comment on pull request #405](https://github.com/melian-agent/melian/pull/405#issuecomment-6867826835) read `Spend: 283 s` because that round skipped the durability lens. A docs-only change skips it every time, so most rounds would have shown no cost.

The cause was in the review's run details, which the ledger's run table and the round comment both read. A skipped lens is still a model stage, and since it made no request it has no usage. `runStage` in `packages/pipeline/src/telemetry.ts` marked any model stage without usage as "usage incomplete". The round script then left out tokens and cost, as it should for a total it cannot vouch for, and the ledger called the run's total incomplete.

A lens now counts as sending nothing when its record shows both of two things. First, it opened no conversation: a lens that ran has one, and its stage names it. Second, its check says it was `skipped` or `failed`. A missing conversation alone is not enough. An older build's record can say a lens ran and leave no conversation the reader can find, so its usage is unknown, and `projects recorded checks without conversations` keeps it incomplete. A lens reaches the new state in two ways in today's code: triage or the configuration skipped it, or the plan refused it before its first request, as for a missing credential. A lens that sent requests and then failed has a conversation, so it keeps its usage or stays incomplete. The rule needs no change to [the run details decision](../decisions/2026-10-25-run-details-from-telemetry.md): its fourth point marks a stage some of whose requests left no usage, and a stage that sent no request has none.

No stored shape or key changes. `usageIncomplete` was already optional on a run row, and rounds stored before this keep what they recorded.

The tests are in `packages/pipeline/test/run-details.test.ts` and `scripts/round-public.test.mjs`. A skipped lens and a lens the plan refused read as complete. The same skipped lens with a conversation, and a lens recorded as ran with no conversation, stay incomplete; those cases share every input but the one that decides. The ledger's summary and rows show no "incomplete" for a skipped lens beside a complete one. The round script publishes all three numbers from the telemetry the CLI prints for such a review. Each new test of a changed behaviour failed on `main` at `f357d535` for the reported reason: the row carried `usageIncomplete: true`, the summary said "incomplete", and the public spend was `{ seconds: 572 }`. The existing test's `failed` lens loses its incomplete mark, as the issue's comment said it would.

Codex's adversarial review of `e6de86ce` found that the rule reached triage too. Triage has no conversation even when it calls a model, so a triage that failed after sending its request lost its incomplete mark, and the round would have published a cost that missed that request. `5a96defe` limits the rule to lenses, which always have a conversation once they run. Its test, a failed triage with an incomplete request, failed on `e6de86ce` and passes after.
