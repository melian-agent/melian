[Issue #394](https://github.com/melian-agent/melian/issues/394) built the key function the shared record needs, and keyed four of its producers with it: triage, check runs, verification and walkthroughs. [The request keys decision](../decisions/2026-11-14-request-keys-as-built.md) records what the build settled.

Problem: each producer keyed its stored work its own way, from a list of fields written beside the request. Example: a check run was keyed by base, head, tier and a hash of the configuration and source, so a host on another platform, or with another Biome, attached to a run whose results it never produced. Solution: core's `KeyedRequest.of(producer, request, unkeyed)` hashes the canonical bytes of the whole request a producer is given, with the producer's name, and refuses to leave out any field but the four rule 5 names. Each producer builds its request in one place and passes it whole.

- Triage keys the decider's name and version, the question set, the questions, whether the input was cut, and the state under a fixed nonce. A legacy decision task, which names its decider only in its key, still attaches to a decider of that name.
- A check run keys the configuration less its display keys, the policy source, the tool pins and versions, the mutation inputs when mutation is on, and the host facts, which core's `hostFacts` reads once per directory. The run's identity takes the first 16 hex digits of the key.
- Verification keys the review state less its nonce, every candidate, and the verifier's fixed text. A wave's outcome is keyed by its candidate under `verification.candidate`. The outcomes a review reuses stay out.
- A walkthrough keys its revision, prompt, model, thinking level, paths, instructions and record tool.

The lens run is left for [issue #432](https://github.com/melian-agent/melian/issues/432): its request, enclosing functions included, needs lens reuse per run, which that issue builds on [issue #288](https://github.com/melian-agent/melian/issues/288). Until then the lens task attaches through `instructionFingerprint` and `selectionOf`.

The tests: `packages/core/test/request-key.test.ts` covers the key, `requestJson` and the `keyCoverage` helper in `@melian-agent/core/testing`, and `test/host.test.ts` the host probe. Each producer has a coverage test that changes every request field in turn and sees the key change, and changes each exclusion and sees it stay: `triage-request.test.ts`, `check-request.test.ts`, `verification-request.test.ts` and `walkthrough-request.test.ts` in `packages/pipeline/test`. The review, checks, summary and verification suites still attach a repeat review to its earlier work.

The mutation proof covers the thirteen changed files that guard what a key matches, listed as `claimsIn` in [the inventory](2026-11-14-issue-394-mutants.json), enumerated over `15f73559...594f2446`. Each of its 360 generated rows was run by hand against its named test alone, which passed unmutated first: 331 are killed by an existing test, 18 by a test this change added, and 11 are equivalent, each with its reason. The 77 ignored rows are configuration and comment notes. Runs from the early head `9a4ad738` stand only for the five files unchanged since: `core/src/testing.ts`, `core/src/decider.ts`, `decisions/src/fallback.ts`, `pipeline/src/decisions.ts` and `pipeline/src/triage-request.ts`. Every row in a file that changed later, and seven in `review.ts` whose lines moved, was run again at the head. When a mutant failed many tests but the first failing test passed alone, it was run again by hand against the test that pins its behaviour, never counted from the batch. Three equivalence claims in `review.ts`'s `reportedAt` rest on a probe that recorded each severity the verifier was shown across the 171 verifier tests and never saw an undefined one. `core/src/decider.ts` gains only a type field and holds no mutant. The enumerator sets `pipeline/src/static.ts` aside, because the file sends signals, so `staticToolVersion`, which feeds the check run's key, was proved by eleven hand mutants that touch no signal code, recorded in [their own file](2026-11-14-issue-394-static-hand-mutants.json): eight are killed, and three on the path for a missing tool are equivalent, since Melian depends on its own Biome and TypeScript.
