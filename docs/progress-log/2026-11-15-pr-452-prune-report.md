[Pull request #452](https://github.com/melian-agent/melian/pull/452) makes `melian store prune` list every name it leaves, for [issue #440](https://github.com/melian-agent/melian/issues/440). Prune had skipped every dotted name under `graphs/`, `coverage/` and `mutation/` as scratch, though `CacheScratch` sweeps only its own kinds, and it counted any `.sqlite` name at the root as a changeset. `scratchName` in `packages/pipeline/src/cache-scratch.ts` is now the one test of a scratch name, which `CacheScratch` sweeps by and prune skips by. Prune lists a link with a scratch name, which `CacheScratch` never sweeps, and counts as changesets only `pull-` and `range-` IDs of the shape core writes. Nothing prune removes changes. The five new tests failed at d81101e0 because each name was missing from `kept`, and pass after the fix. The [pipeline guideline](../guidelines/pipeline.md#pruning-the-store) says which names prune lists. Codex's adversarial review, at 44a12074, found that `CacheScratch` skips every `entry-` name before it asks `scratchName`, so prune skipped an old `entry-orphan.<uuid>.tmp` that nothing would ever sweep. e9c95c52 has `scratchName` leave `entry-` names out itself; the sweep still skips them first, so it sweeps what it did before. The test from the finding, which ages such a name, opens `CacheScratch` and expects prune to list what survives, failed at 44a12074 with nothing listed and passes after the fix. All 21 enumerated mutants in `store-prune.ts` were killed at e9c95c52, in [the inventory](2026-11-15-pr-452-mutants.json). The enumerator leaves `cache-scratch.ts` unmutated because it sends signals, so Stryker's instrumenter listed `scratchName`'s 20 mutants on a copy of the function. Each was applied to that function alone, which keeps the signal-sending code unmutated, and all 20 were killed, in [their own list](2026-11-15-pr-452-scratch-name-mutants.json).
