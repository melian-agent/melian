# Pull request 646 keys a probing run by the kind of git it found

Builder agent, for [pull request #646](https://github.com/melian-agent/melian/pull/646) and [issue #644](https://github.com/melian-agent/melian/issues/644).

The Melian round at 1584b2c1f found that a probing run's key left out whether the probe sandbox could run git. One host could find git, lose it or gain it, or move from a lookup with a system configuration to one without, and reuse a run that probes made under the other answer. That is an input missing from the key, the first of [the identity guideline's](../guidelines/identity.md) four failures.

The coordinator chose the fix on 2026-11-27; it is not a maintainer ruling. `probingHost` now adds a `git` field, `linked` or `linked-no-system`, naming only the kind of the lookup's answer. It never names a path or a version, since those name the host's install. The field is absent where git is unavailable and on Linux, so every run recorded before probes could run git keeps its key. `probingHost` is now asynchronous, because it asks the sandbox's lookup.

The test "probes again when the host's git lookup changes its kind, and never when only its paths change", in `packages/pipeline/test/probing-level.test.ts`, was written first. On the old code it failed at the step that gains git, with `expected +0 to be 2`: the level reused the run made without git. After the fix it passes. A step that only moves git's paths reuses the run, and a step that changes the kind probes again. `probing.test.ts` names each kind's field, and its absence, and adds the git kind to the host-mismatch cases. No test reopens a store the earlier code wrote. In its place, the same test asserts that a host whose git is unavailable keys exactly the five fields the earlier code wrote, and that such a run is reused. The identity guideline's row and the decision's Keys section change in the same commit.

[The inventory](2026-11-27-pr-646-git-kind-mutants.json) of da6c69e04 lists nine generated mutants in `probing.ts`, and each was run by hand. Each named test was collected alone, passed unmutated, and failed mutated. Five mutants first ran against `probing.test.ts`, whose top-level `probingHost` call failed at load under the mutant, so no test was collected; that is no kill. They were rerun against the named tests in `probing-level.test.ts`, and all five failed there.
