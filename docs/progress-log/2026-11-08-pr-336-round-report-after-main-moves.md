For [issue #335](https://github.com/melian-agent/melian/issues/335), [pull request #336](https://github.com/melian-agent/melian/pull/336) lets a `melian round` run's first report finish after `main` moves: a merge during [pull request #294](https://github.com/melian-agent/melian/pull/294)'s round 2 had refused its report and lost the round. An attacking review of the first ruling, that every job's first attempt carries on, found a run held in the workflow's concurrency queue would run old code with the logins for hours, so the maintainer ruled to relax the report job alone, and [the decision](../decisions/2026-11-08-round-report-finishes-after-main-moves.md) records both. The report step now reads `run_attempt`, refuses an attempt that is not a whole number above 0 and a head that is not 40 hex digits, and refuses a moved commit only in a rerun. Its test runs the step's script with a fake `gh`; it failed before the fix with the report refused at attempt 1, and passes after it. The enumerator lists no mutants for shell in YAML, so 21 hand mutants of the step were each run against their named test, and all were killed once a 41-character head joined the cases.
