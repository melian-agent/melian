# Issue 561: every parity attempt is saved, and unmeasured usage stops the run

Codex's second adversarial review of [pull request #582](https://github.com/melian-agent/melian/pull/582), at b9b63d51, found two more ways the parity run undercounts what it spends. Its first review had found a third. A review stopped by a provider's usage limit added its tokens to a running count that was never saved, so a resumed run forgot them, along with the stopped review's stages and store. A stage whose usage the telemetry did not measure counted as 0 tokens, so a committed review with missing usage gave the parity arm too small a budget and slipped past the token stops.

The coordinator agreed, on 2026-11-19, to remove the class rather than fix each case. The results file now holds every attempt, finished, failed or stopped, and a stopped one carries why. The run's totals are only ever the sum of saved attempts, and a resumed run reviews a stopped arm again under a new store name. One reader measures a review's spend. It asks the telemetry's own run rows, whose `usageIncomplete` applies the pipeline's rule, and a review with any unmeasured model stage is saved unscored and stops the run.

The coordinator also asked that the parity budget's count be named. Each attempt and stage now records `tokens`, with cache reads, as a round's Spend line counts, and `budgetTokens`, input, cache writes and output, as Melian's budgets count. Shares use the budget count; the guideline and the run record template say why, and that the maintainer's yardstick figures are the Spend kind.

Two tests in `packages/evals/test/parity.test.ts` reproduce the findings. Against b9b63d51, the resumed run printed a total of 180 tokens where 280 had been spent, and the review with no usage crashed on a parity budget of 0. Both pass now. Eleven hand mutants, of the budget formula, the finished-arm test, the unmeasured cause, the stop on a stopped attempt, the store-name check, the totals and the stopped attempt's wording, each fail the suite. The test usage helper now puts tokens in output and cache writes, so the budget formula's terms each decide a result.
