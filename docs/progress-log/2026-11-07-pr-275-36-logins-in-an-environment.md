The `melian round` workflow's logins now live in a GitHub Environment, in fix pass 8 of [pull request #275](https://github.com/melian-agent/melian/pull/275). The coordinator's final round found that repository secrets reach every branch's copy of the workflow, so a writer could push a branch whose `melian-round.yml` drops every check and sends the logins out, then run it with `--ref`. The maintainer ruled to keep `CLAUDE_CODE_OAUTH_TOKEN` and `CODEX_AUTH_B64` in an Environment, `melian-round`, whose deployment branches are limited to `main`. The round job, the only job that reads them, declares it.

A failing test in `scripts/melian-round-workflow.test.mjs` first found the round job reading the logins with no Environment. It now requires every job that reads either login to declare `melian-round`, and the workflow to reference no other secret. Dropping the declaration, or naming another Environment, fails it.

AGENTS.md's workflow paragraph and the Actions rounds decision say the Environment, not the workflow's own check, keeps the logins from a branch's workflow. The decision gives the maintainer's setup steps: create the Environment, limit its branches to `main`, move both secrets into it, and delete the repository secrets. The Learning that refreshes `CODEX_AUTH_B64` now sets it with `--env melian-round`.
