# Doctor's records line says who is trusted to write melian/state

[Pull request #487](https://github.com/melian-agent/melian/pull/487), for [issue #479](https://github.com/melian-agent/melian/issues/479), keeps rule 6 of the shared record decision. `melian doctor` names the store and says whom the repository trusts to write it. The `records` line reads `trust.writers` from the committed root policy, on the same base the `trust` line reads. The two lines now share one function for that read. With `trust.writers` on, the line says the branch's writers are trusted as the repository's. With it off, it warns that only the trusted host may write `melian/state`, since doctor cannot check who may push to it. With no readable policy, it warns that who may write the branch is unknown. Four new tests assert the whole line for each case, and the CLI guideline's doctor row says what the line states. Codex's first adversarial review found that the records line said `ok` from local `main` or `HEAD`, where the trust line warns. Commit 43dc27fb fixed that test-first, so both lines now take the caveat from the function that reads the policy. Its second review asked whether doctor should check the cached ref against the remote. The coordinator kept that out of scope as a choice of approach, and [issue #491](https://github.com/melian-agent/melian/issues/491) holds it. The [mutant inventory](2026-11-16-pr-487-mutants.json) lists the 92 mutants of `packages/cli/src/doctor.ts` at 43dc27fb. Each was run by hand against its named test alone, after that test passed unmutated: 89 were killed. The other 3 are equivalent, each with its reason, and the CLI package's whole suite passes against each of them.
