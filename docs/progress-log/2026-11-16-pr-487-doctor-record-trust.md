# Doctor's records line says who is trusted to write melian/state

[Pull request #487](https://github.com/melian-agent/melian/pull/487), for [issue #479](https://github.com/melian-agent/melian/issues/479), keeps rule 6 of the shared record decision. `melian doctor` names the store and says whom the repository trusts to write it. The `records` line reads `trust.writers` from the committed root policy, on the same base the `trust` line reads. The two lines now share one function for that read. With `trust.writers` on, the line says the branch's writers are trusted as the repository's. With it off, it warns that only the trusted host may write `melian/state`, since doctor cannot check who may push to it. With no readable policy, it warns that who may write the branch is unknown. Four new tests assert the whole line for each case, and the CLI guideline's doctor row says what the line states.
