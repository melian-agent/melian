On [issue #480](https://github.com/melian-agent/melian/issues/480)'s branch, [pull request #498](https://github.com/melian-agent/melian/pull/498), a stop of core's `git` can no longer leave Melian running. Codex's review of `9c1a5019` found two ways it could.

- A stop closed git's standard error and left its standard output open. A program git started that the stop could not find, re-parented after git exited, kept that pipe and kept Node alive after the call had settled. `082189cc` closes both. Its test came first: "lets the process exit when git has already exited and one of the programs it started holds its output open" runs `git` in a child Node process under a 300 ms deadline, with a stand-in git whose child holds its output for ten seconds. On `9c1a5019` the child process took 10,094 ms to exit; with the fix it exits in under five seconds, and its result is still `{ code: -1, stdout: "", timedOut: true, childrenLeft: true }`.
- The process-table read ran `ps` synchronously with no limit, so a `ps` that stalled stalled the deadline too. `20e85dd1` gives it five seconds and ends it with SIGKILL through Node's own handle; a read that runs out fails, and the stop signals nothing below git. The coordinator chose this over leaving it as a known risk, as a choice of approach. Two tests came first, with a stand-in `ps` that ignores SIGTERM: on `082189cc`, "fails a read whose ps runs past the limit, though ps ignores SIGTERM, and the stop then signals nothing" read the real table instead and did not throw, and "reads a ps that answers inside the limit" got the real table, not the stand-in's one row. Both pass with the fix. The pipeline test that pins `ps`'s options now pins the limit and the signal too.
- Stryker's instrumenter gave 13 mutants on the two commits' lines. At `20e85dd1` all 13 were killed by their named tests, each run alone after it passed unmutated, the `process-tree.ts` ones on a copy whose `ProcessTable.kill` sent no signal. Emptying the kill signal falls to the stand-in that ignores SIGTERM. [The hand inventory](2026-11-16-pr-480-hand-mutants.json) holds them.
