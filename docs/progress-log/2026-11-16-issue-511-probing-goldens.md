# The probing goldens score what the review found

Part A of [issue #511](https://github.com/melian-agent/melian/issues/511) repairs the three probing goldens and their scoring. The first live probing measurement, on 2026-11-16, scored mean precision 0.07 and recall 0.17, and most of that came from the goldens.

Three goldens scored defects that the review found as missed, or scored right findings as false positives.

- `trust-boundary-probe-claim-lost-release` expected `lens.trust-boundary`. Its defect is a race with no hostile party, and the correctness lens found it under `state-ordering`, verifier confirmed, in every pass. The expectation now names no `source`, by the maintainer's ruling of 2026-11-16 in the coordinator's session that parity is with the review of record, whichever lens finds the defect. It also accepts `state-ordering` beside `fail-open`.
- `trust-boundary-probe-syntax-check-outside-text` expected `secret-exposure`, and one pass reported the leak under `path-traversal`. The expectation accepts both.
- The syntax-check clean twin was not clean. Lenses rightly found three defects in it: a rule a quoted source line can forge, file names rendered unescaped, and `.cjs` skipped. A reviewer's read before the golden settled found a fourth, a place a newline in a file name can move. Both twins now fix all four, so the defect twin is the clean twin plus the measured leak. Neither twin's README makes any of the four an expectation, and each says why.

An expected finding gains two optional fields in `packages/evals/src/goldens.ts`. `alternativeRules` lists rules that name the same defect, by hand, with the reason in the golden's README. `lines` is the first and last line of the defect at the head, and a finding answers only where its own lines overlap them. `trust-boundary-probe-round-environ-leak` names lines on both expectations, `round.mjs` 104-111 and the workflow's 226-239. Before, a finding anywhere in the workflow answered the artefact's expectation by file and rule alone. The dedupe key in `scoreGolden` holds both fields. A corpus test holds every expectation's lines in order and around its cause. [The evals guideline](../guidelines/evals.md) documents both fields, the rule that a clean twin is read for anything else a lens could rightly report, and when a probing golden names a `source`.
