On [issue #480](https://github.com/melian-agent/melian/issues/480)'s branch, [pull request #498](https://github.com/melian-agent/melian/pull/498), the decision now names one more limit of the stop. Codex's review of `96d10748` found that a program git starts while the stop reads the process table is not in the record, and once git is killed it is re-parented, so the call reports a clean stop while it runs. The window is one `ps` read, about 20 ms, at the moment of the stop.

Codex's fix, freezing git's tree with SIGSTOP and reading again until no new process appears, would add a mechanism and a new kind of signal on a trust surface. The builder raised it with the coordinator, which took it to the maintainer. The maintainer ruled on 2026-11-16, in the coordinator's session, that the window is accepted as a limit, as [the pull request records](https://github.com/melian-agent/melian/pull/498#issuecomment-6907010396). No code changed.
