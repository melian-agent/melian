[Pull request #74](https://github.com/melian-agent/melian/pull/74) adds `scripts/codex-sandboxed.sh` and `scripts/codex-seatbelt.sb`, which run a Codex task in full-access mode inside a seatbelt profile of our own. Codex's workspace-write sandbox denies every write under `.git`, so a task could not commit or fetch. It refuses the main checkout. The profile allows writes only to the worktree, scratch, and a per-run temp directory. It also allows `objects`, `refs`, `logs`, the literal state files of the worktree's administrative directory, and Codex's runtime directories under `~/.codex`. The task gets its own npm cache and a scrubbed environment. It denies writes to hooks, `.git/config`, `commondir`, `gitdir`, and Codex's `config.toml`, and reads of `~/.ssh`, credential files, and `.env` files. Reads and the network otherwise stay open. `--print-profile` prints the profile, and `scripts/codex-sandboxed.test.mjs` checks it, and runs `sandbox-exec` against a temporary repository to prove a commit succeeds while renaming `.git` and writing `commondir` fail. It is macOS only. The script no longer ends in `exec`, which skipped the trap that removes the temporary profile. `AGENTS.md` carries the Learnings entry and `README.md` the usage.

A live probe of the wrapper ran Codex GPT-6.1 Sol in a linked worktree. It committed, fetched, pushed, ran `npm ci`, and ran Vitest, and every forbidden write and read was denied. Two defects showed. `gh auth status` and `gh pr list` failed with `hosts.yml: operation not permitted`, because the profile denied reading `~/.config/gh/hosts.yml`. The token lives in the keychain, which `mach-lookup` reaches anyway, so the deny protected nothing and is gone. An earlier probe stalled on `Reading additional input from stdin...`, because `codex exec` reads stdin when it is not a terminal. The wrapper now gives it `/dev/null`. Review then led to four more changes. `rebase-merge` and `rebase-apply` are denied, since their todo files hold `exec` lines the host would run later. The task's environment is an allow-list passed through `env -i`, not a scrub list. A test proves a deny beats a broader allow. The README lists the residual risks.

The tests gained the sqlite regex, a scratch directory apart from the run directory, and one variable per allow-listed pattern.

Hooks, git config, `commondir`, `~/.codex/config.toml`, `~/.ssh`, the home directory, `git init` in a subdirectory, and a `.git` gitfile were all denied, and no secret variable reached the task. Melian's review of that head found two bypasses and a gap. APFS ignores case and git finds a repository at `<dir>/.GIT`, so the nested `.git` deny now spells each letter in both cases, and the root pointer file is a regex of the same form. Git also accepts any directory holding `HEAD`, `objects/`, and `refs/` as a bare repository, so a `HEAD` file anywhere below the worktree root is denied; the worktree's own `HEAD` lives in the administrative directory and is unaffected. `CODEX_HOME` relocates Codex's state directory and passes through the allow-list, so the profile, the `mkdir`, and the regex now use `${CODEX_HOME:-$HOME/.codex}`, and a relative value exits 64. The tests gained an end-to-end run with a stand-in `codex` that tries a home write and a nested `.git`, a relative symlinked `.env`, and a cleanup of the `/private/tmp` probe file.
