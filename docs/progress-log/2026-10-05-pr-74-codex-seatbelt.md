[Pull request #74](https://github.com/melian-agent/melian/pull/74) adds `scripts/codex-sandboxed.sh` and `scripts/codex-seatbelt.sb`, which run a Codex task in full-access mode inside a seatbelt profile of our own. Codex's workspace-write sandbox denies every write under `.git`, so a task could not commit or fetch. It refuses the main checkout. The profile allows writes only to the worktree, scratch, a per-run temp directory, `objects`, `refs`, `logs`, the literal state files of the worktree's administrative directory, and Codex's runtime directories under `~/.codex`; the task gets its own npm cache and a scrubbed environment. It denies writes to hooks, `.git/config`, `commondir`, `gitdir`, and Codex's `config.toml`, and reads of `~/.ssh`, credential files, and `.env` files. Reads and the network otherwise stay open. `--print-profile` prints the profile, and `scripts/codex-sandboxed.test.mjs` checks it, and runs `sandbox-exec` against a temporary repository to prove a commit succeeds while renaming `.git` and writing `commondir` fail. It is macOS only. The script no longer ends in `exec`, which skipped the trap that removes the temporary profile. `AGENTS.md` carries the Learnings entry and `README.md` the usage.

A live probe of the wrapper, Codex GPT-6.1 Sol in a linked worktree, committed, fetched, pushed, ran `npm ci`, and ran Vitest, and every forbidden write and read was denied. Two defects showed. `gh auth status` and `gh pr list` failed with `hosts.yml: operation not permitted`, because the profile denied reading `~/.config/gh/hosts.yml`; the token lives in the keychain, which `mach-lookup` reaches anyway, so the deny protected nothing and is gone. An earlier probe stalled on `Reading additional input from stdin...`, because `codex exec` reads stdin when it is not a terminal; the wrapper now gives it `/dev/null`. Review then led to four more changes: `rebase-merge` and `rebase-apply` are denied, since their todo files hold `exec` lines the host would run later; the task's environment is an allow-list passed through `env -i`, not a scrub list; a test proves a deny beats a broader allow; and the README lists the residual risks.

Melian's review of the same head added five more. Writes to any `.git` below the worktree root are denied, so a task cannot create a nested repository whose `config` runs a program when the host enters it. `real` now resolves a symlinked last path component, so a literal filter names the target. The scratch directory is made absolute before the task gets its npm cache path. The tests gained the sqlite regex, a scratch directory apart from the run directory, and one variable per allow-listed pattern.
