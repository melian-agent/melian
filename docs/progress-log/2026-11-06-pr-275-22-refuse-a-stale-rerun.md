The round job of the `melian round` workflow now refuses a commit the default branch has moved past, in fix pass 3 of [pull request #275](https://github.com/melian-agent/melian/pull/275). Codex's adversarial review of 1aff2d1 found that a rerun keeps the run's first `GITHUB_SHA` and `GITHUB_REF`, so the gate's check of the ref's name still passes after the default branch moves. The rerun then builds the old workflow's code, perhaps from before a fix such as fix pass 3's redaction, and hands it the logins. "Re-run failed jobs" can also skip the gate. A failing test in `scripts/melian-round-workflow.test.mjs` first found no such step. Before any step that holds a secret, the round job now reads the default branch's commit through the API and stops unless it is `github.sha`; an unreadable answer stops it too. A second test runs the step's own shell against a fake `gh` that answers only that request; inverting the comparison, or dropping the fallback for a failed read, fails it.
