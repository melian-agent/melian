# Issue 617, pull request A: retire a finished pull request's records

Builder agent: this is the first of three pull requests for [issue #617](https://github.com/melian-agent/melian/issues/617). `GitRecordStore.retire(seen)` removes whole changeset folders from `melian/state` in one commit, with no mark, and pushes it even on a tip past a limit. It pushes only a commit that passes the removal-only rule. [The retention decision](../decisions/2026-11-21-shared-tip-retires-finished-pull-requests.md) records the maintainer's rulings of 2026-11-21 and the rule, and amends rule 13 of [the shared record decision](../decisions/2026-11-13-shared-record-behind-a-store-port.md).

The attacking review came first, by the coordinator's direction. An agent wrote 48 unit tests against stubs, on a fixture remote with maintenance off, before any of `retire`'s code existed. The tests cover each probe in [the plan's addendum](https://github.com/melian-agent/melian/issues/617#issuecomment-7049676449) and add three the plan missed:

- A removal-only tree on a commit with no parent, or on a merge, would rewrite the branch's history under a lease that still holds. So the rule also checks the commit's one parent.
- Retiring every folder leaves no `changesets` tree, since git keeps no empty tree. That is the most a retirement can remove, so the rule accepts it.
- Retiring a disposed changeset takes its mark too, so a reopened pull request records again.

`retire` shares one fetch, build and push loop with every other write, `#land`, so a lost race decides again on the fresh tip. `folders()` reads the top level of `changesets/` alone, and so answers on a tip past any limit. After a tip passes a limit, the message for every other write now names retirement as the way back under.

Mutants: the enumerator listed 308 over `origin/main...HEAD`, with none omitted. Every mutant ran by hand, each against its named test alone, in four worktrees.

- The first run left 53 survivors. Most were guards that only a listing past its bytes, a folder past the entry limit, or a record or total past the byte limits reaches. The new tests reach each one by faking the single answer that crosses it, at the bound and one past it. They also pin the messages that a closed handle and a refused commit give, and the commit's subject, `melian: retire`.
- Every mutant then ran again against the new tests, since the test file changed. The 53 claims whose named tests changed after that, the survivors among them, ran a third time.
- The result: 255 killed by the attack tests and 50 by the new ones. Three are equivalent, with reasons in the inventory, which is `2026-11-21-issue-617-retire-mutants.json`.

Pull request B adds the tip's sizes and the warning past half of either limit. Pull request C adds the prune command and the scheduled workflow. Reading archived records back is [issue #630](https://github.com/melian-agent/melian/issues/630).
