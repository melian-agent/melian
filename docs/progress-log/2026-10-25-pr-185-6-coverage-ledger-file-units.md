# 2026-10-25: the coverage ledger covers changes that have no hunks

Codex's review of [pull request #185](https://github.com/melian-agent/melian/pull/185) at `ce1c6134` found that the ledger modelled the diff only as hunk lines. A changed file with no hunks gave no lens anything to cover, so each could skip it as "nothing uncovered", and `review.coverage` would pass with no lens having seen a binary update, a mode-only change, an empty file, a pure rename or a type change. [The decision](../decisions/2026-10-23-coverage-ledger-and-delta-review.md) now makes each such file, and each mode or kind change beside hunks, a file unit taken from the changeset's `ChangedFile`. A check covers a unit only by receiving its path, status, modes, kinds and binary flag, with bounded content where the lens tools can read it; the change prompt gains the modes and kinds in build 2. A unit maps between heads only when git's diff between them lists nothing for the file. Attack rule 17 says `review.coverage` cannot pass on a change with no hunks, and the plan's build 1 tests one case per kind. The branch also merges [pull request #189](https://github.com/melian-agent/melian/pull/189) at `c5abb923`.
