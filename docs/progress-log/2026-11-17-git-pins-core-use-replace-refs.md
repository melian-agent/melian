# Melian's git pins `core.useReplaceRefs` off as well

Follows [pull request #537](https://github.com/melian-agent/melian/pull/537), for [issue #502](https://github.com/melian-agent/melian/issues/502), on four review findings.

R1. On git 2.40 and 2.41, which Melian accepts, `core.useReplaceRefs=true` in a repository's configuration outranks `GIT_NO_REPLACE_OBJECTS`. Failing tests first, one per helper, in `packages/core/test/replace-objects.test.ts`, `packages/cli/test/repository.test.ts`, `packages/pipeline/test/static.test.ts` and `packages/pipeline/test/store-prune.test.ts`. Each sets the repository's configuration to `true` and asks what git reads for the setting under Melian's options and environment. The pipeline tests use a `git` shim on the path, in `test/fixtures/replace-refs.ts`, that records the answer and then runs the real git. At `c0b8b02e` each read `true`; after `1adf6a1f` each reads `false`. Core and the CLI call the new `withoutReplacements`, which appends the setting after any the caller's `GIT_CONFIG_COUNT` counts, store prune calls it after its filter, and the static checks pass `-c core.useReplaceRefs=false`. No run on git 2.40 or 2.41 is recorded: this container's git is 2.43, CI's is newer, and the session's permission checks refused building or unpacking 2.40. [The amendment](../decisions/2026-11-17-git-pins-core-use-replace-refs.md) corrects the decision's claim and says what stands in.
