A hand-off now holds per file, in [pull request #57](https://github.com/melian-agent/melian/pull/57), which closes milestone 2 step 13. Before, a lens listed a neighbour's defects only when the neighbour reviewed every file the lens reviewed, so `correctness`, which reviews every changed file, could never hand anything to `durability`, which reviews three source folders. Now a neighbour over some of the lens's files gets an entry naming those files, quoted as the change's data, and the lens keeps the neighbour's defects in every other file; a neighbour over every file renders as before, and a lens running alone keeps its whole coverage. Melian's own `.melian/lenses/correctness/LENS.md` and `.melian/lenses/removed-behaviour/LENS.md` extend the built-ins with a `handoffs` entry for `durability` and nothing else, since a built-in cannot name a repository lens; their versions change, and no built-in's does. [The decision](../decisions/2026-10-05-per-file-hand-offs.md) supersedes the one-sided hand-off of [the durability decision](../decisions/2026-10-05-durability-repository-lens.md). [The eighth live run](../../packages/evals/runs/2026-10-05-live-goldens-8.md) measured three passes: `durability`'s goldens rose from a worst precision of 0.31 to 0.44, with recall 1.00, and other lenses' extras fell from 20 to 11. The lens stays below the bar, and the record names the leaks left for the next tuning round.
