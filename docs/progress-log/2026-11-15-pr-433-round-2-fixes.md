Melian's second own-build round on [pull request #433](https://github.com/melian-agent/melian/pull/433), on the head that merged `main` at 9e3527a9, raised two findings on the code and one on its tests. Each is now fixed.

- A stray path that is not UTF-8 was named by decoding it with replacement characters, so `\x80.json` and `\x81.json` read alike in a refusal and in `melian doctor`. The store now names such a path in git's quoted form, as `git ls-tree` prints it, in 56bfb50e. [Its inventory](2026-11-15-pr-433-quoted-path-mutants.json) runs all 31 mutants by hand against the new test, and each fails it.
- The push read seven refusals as a lost race, and only some had a test. d2da143f gives each its own scripted reply; deleting any one from the pattern fails one test.
- A store opened on a relative directory failed every call, because git runs inside `records.git` and read a relative `--git-dir` from there. The repository makes its path absolute when it opens, in 0d8e068b. The test failed on the old head with `not a git repository`, and removing the fix fails it again.

The round's other advisory, that `melian doctor` would misread a Windows drive-relative `origin` such as `C:remote.git`, is left: Windows is not a target, and the only effect is a warning.

Codex's adversarial review of that head found one more. A push stopped at its deadline counted as lost whenever the tip had not moved. Its lease still matched, so a transport that outlived git, such as ssh, could land it afterwards, and a retried `writeCell` then answered false for a write that had landed. The test from that scenario answered false on the old head. Since dc6185d2, only a tip that has moved without the commit proves it lost; an unmoved tip, or a branch the push would create that is still absent, fails the call as `unreachable`, saying it may have landed. Two tests that held the old retry now hold the new answer, and a deleted branch the push was built on still counts as lost. [Its inventory](2026-11-15-pr-433-unmoved-tip-mutants.json) runs all five mutants by hand, and each fails its test.

A second Codex review found that a call held every record and cell of the tip in memory, each at most 4 MiB, but with no bound on their total. Since eb6f73a3, a tip whose readable records and cells total more than 256 MiB fails the call as `unreachable` before any blob is read, and the read passes git the sizes it reported as a byte limit, so the two cannot disagree. The number is the coordinator's answer of 2026-11-15 on approach, not a ruling, and it is provisional until [issue #455](https://github.com/melian-agent/melian/issues/455) designs a read that does not hold the whole tip. The tests sit at the bound, one byte past it, and on git giving more bytes than it reported. [Its inventory](2026-11-15-pr-433-tip-bound-mutants.json) runs 56 mutants by hand at eb6f73a3: 55 fail their named test, each checked passing unmutated first, and one is equivalent, since core reads an absent `maxBytes` as no limit.
