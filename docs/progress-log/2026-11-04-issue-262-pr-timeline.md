# A pull request's development timeline, from GitHub alone

For [issue #262](https://github.com/melian-agent/melian/issues/262), `node scripts/pr-timeline.mjs <number> [--repo owner/name] [--record file.json]` prints a pull request's timeline as a Markdown table. Its rows are the closing issues' opening, `status:` labels, `Claim:` and `Fix pass` comments, every commit with merges marked, the branch's CI runs and the pull request's merge-group runs with their spans, comments, reviews, ready, the queue, the merge, and one row per item of each `Timing:` line, as [the timing decision](../decisions/2026-11-04-timing-line.md) sets out. A gap row marks more than an hour from the latest end seen to the next event's start; a CI span covers the events inside it, and a Timing item sits at its comment's time and fills no gap. A stage table follows: ready-wait, build, review and queue, each with the Timing minutes and cost reported inside it, then the CI total and the whole span. An item the parser can't read prints as text. The script fails closed when any list it reads has a second page. `--record` writes every `gh` request and answer in the form the test's fixture uses, so a real pull request can become a fixture. The coordinator settled the grammar, stages and gap rule in answer to the builder's questions; the Melian round rows wait for [pull request #221](https://github.com/melian-agent/melian/pull/221). No design decision or plan status changed.

The command line lives in `scripts/pr-timeline.mjs` and the timeline in `scripts/timeline.mjs`, which the test imports, so no mutant can fail the test file's load. The enumeration over `origin/main...HEAD` lists 379 mutants, none omitted: 113 ignored by configuration and 266 run by hand. Each ran against one named test selected by its full name, as [pull request #264](https://github.com/melian-agent/melian/pull/264) sets out, and 263 fail it. Three survive as equivalent: a `$` after a greedy group in two patterns and a `^` before a lazy group that can always start at index 0. Earlier runs found 17 survivors and two main-guard mutants that only failed the file's load; the tests, a refactor removing two unreachable guards and the split fixed them before the final run. In this cloud container `npm run check` passed Biome, the dependency checks, type checking and the audit, with release verification skipped because the container's GitHub token is refused. On the final head, Vitest passed 7,295 tests and failed 15 in four files outside `scripts/`: `compare.test.ts`, `pull-request-stale-export.test.ts`, `enola-spike.test.ts` and `triage.test.ts`. Their causes are a shallow clone, a missing `/usr/bin/time` and a proxied GitHub call. The same tests fail on `origin/main` in this container, so the gate needs a run on the host.

The coordinator ran the script on [pull request #256](https://github.com/melian-agent/melian/pull/256) on the host and recorded its GitHub answers as `scripts/fixtures/pr-timeline/pr-256.json`. A test holds that recording to the coordinator's first cut: nine gaps, 18.2 hours before the claim and a 178.3-hour gap among them, fourteen commits in order with one merge, 14 CI runs over 159.9 minutes, and 212.62 hours in all. The build stage reads 191.70 hours, because it ends at the last commit, so the 178-hour wait before the final fix passes counts as building.
