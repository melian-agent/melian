# Issue #481: a dismissal record is written once

Codex's review of [pull request #551](https://github.com/melian-agent/melian/pull/551) found that a host which kept an old dismissal could set it standing again. Each export rebuilt the dismissal's record, and filled its `supersedes` from that host's listing, so a host holding K and another host's replacement R built K's record again as superseding R. The coordinator answered on 2026-11-18 with option (c): the record is written once, when the dismissal is made with a store, and every export looks it up. That is a coordinator's answer, not a ruling. [The decision](../decisions/2026-11-18-a-dismissal-record-is-written-once.md) records the rule and its limit.

`ReviewRecords.made` writes a new dismissal's record, superseding the dismissals of its finding that stand in the listing. `ReviewRecords.dismissal` now returns the record the listing holds for a dismissal, or one that supersedes nothing. `recordDismissal` takes `records`, and `melian dismiss --records dir:<path>` passes it, under a base that sets `trust.writers: true`. The export writes no dismissal record the store already holds.

Failing tests first. At `36d41caa3`, the stale-host test in `review-records.test.ts` failed with `expected [ Array(1) ] to deeply equal [ Array(1) ]`: R did not stand alone. The four export tests in `review-records-export.test.ts` failed for the defect: no record written at dismissal (`expected [ SharedRecord{…} ] to have a length of 2 but got 1`), a second review adding the record again and an earlier build's record rebuilt (`expected [ { …(5) } ] to deeply equal []`, and `…(6)`), and an export superseding with no store (`expected [ Array(1) ] to be undefined`). All pass on the fix.
