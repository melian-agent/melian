# The record store reads a git run past core's standard error bound as unreachable

[Pull request #472](https://github.com/melian-agent/melian/pull/472) bounds the standard error core's `git` keeps, as [issue #469](https://github.com/melian-agent/melian/issues/469) asks. This entry covers the record store's side, which waited for [pull request #433](https://github.com/melian-agent/melian/pull/433) to land the store. [The amendment](../decisions/2026-11-15-git-bounds-its-standard-error.md) retires the decision row that left that stream unbounded.

Codex's adversarial review, and the review of record, found that a push which lands and then has more than 4 MiB written to its standard error, by a `post-receive` hook, read as a failure: the bound rejected before the store could check whether the push landed. The store also let core's `ChangesetError` escape, where every other failure to reach the remote is its own `unreachable`.

Four tests failed first on #433's code, each for that reason: a fetch whose remote says the ref is missing and then floods, a ref deletion that names a held lock and then floods, and a push that lands and then floods, at the repository and at the store. Each rejected with core's `ChangesetError` where the test expected `RecordError`, or a landed write. `RecordRepository.run` now turns the overflow into `unreachable`, naming the command and the limit and keeping core's error as its cause. `push` answers `stopped` for it, the outcome a push stopped at its deadline had as `timedOut`, and the store checks whether it landed as it did after a deadline. All four pass after the fix, as does the rest of the state-git suite.

The 36 mutants `melian mutants list` gave for the two changed source files are in [2026-11-15-pr-472-record-store-mutants.json](2026-11-15-pr-472-record-store-mutants.json), each with its named test. Each ran against that test alone, after the test passed unmutated. At `6f70d6f1`, 35 were killed. That commit and `e5c6b5b9` were built on [pull request #433](https://github.com/melian-agent/melian/pull/433)'s branch and reached this one as `7f4838ce` and `8e12a29a`, with `packages/state-git` and `packages/core` unchanged. The survivor made `outcome === "stopped"` true in `GitRecordStore.#write`, so a push a newer tip refused ran the landed check, an extra fetch that changed no answer. `e5c6b5b9` makes the lost-race test count the fetches, one for each attempt, and it fails on that mutant: "expected fetch to be called 2 times, but got 3".
