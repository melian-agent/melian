[Pull request #310](https://github.com/melian-agent/melian/pull/310), the lease's incarnation, as the coordinator asked from rules 2 and 3 of the coordination decision at 5a2c5e65.

- Core's `Lease` carries an incarnation: a random identifier minted when a lease record is first created, kept by every later taking, and replaced only when the record is created afresh. `admits` takes the incarnation and generation together, so generations compare only within one record.
- The state branch fences every push and every expiry on the lease the checkout took, by incarnation and generation. A write from a disposed record is refused even when its generation is higher, and one whose holder and generation a recreated record repeats is refused on the incarnation alone. Each push's commit names both.
- Correction to [the review 7 entry](2026-11-08-pr-310-codex-review-7.md): it said a lease another run has since taken is left alone when a failed restore expires it, but at b2f9517 that refusal was reported as an expiry failure. Expiring now ignores a refusal. `leaves alone a lease another run took before the restore failed` fails with the catch removed, with `got 'no space left on device; the lease, g…'`, and passes with it.
- Mutants run by hand: `admits` without its incarnation check is killed by `refuses a write whose holder and generation a record created afresh repeats` and the core recreation test, which first survived both until a same-generation case was added; `take` always minting is killed by both recreation tests.
