[Pull request #60](https://github.com/melian-agent/melian/pull/60) closes [issue #22](https://github.com/melian-agent/melian/issues/22), the first of step 9's three issues. Lens `paths` globs compiled to a backtracking `RegExp` in `packages/core/src/glob.ts` and ran against file paths the head chooses, so `*a*a*a*a*a*b` over a name of 200 `a`s took 164 seconds. The pull request removes `glob.ts`, and `lensCovers` matches through `matchesGlobs` in `packages/core/src/pattern.ts`, the linear-time engine [#18](https://github.com/melian-agent/melian/pull/18) added for guardrails, which takes under a millisecond there. Dotfiles and newlines in names still match every wildcard, the lens tests pass unchanged, and two tests hold three crafted paths to a second each, one on `compileGlob` in `pattern.test.ts` and one through `Lens.select` in `lens.test.ts`. `Lens.load` now compiles every `LENS.md` glob, as `loadConfig` does a `melian.yaml`'s, so a glob past the engine's step limit fails the load as a `LensError` naming the file and the glob, rather than failing a review when the lens is selected. `Lens.load` also refuses braces, character classes, and a trailing slash in a `LENS.md` glob, as `loadConfig` does in a `melian.yaml`, since each loaded and selected nothing, so the review passed without the lens.
