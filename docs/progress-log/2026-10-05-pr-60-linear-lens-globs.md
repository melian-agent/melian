[Pull request #60](https://github.com/melian-agent/melian/pull/60) closes [issue #22](https://github.com/melian-agent/melian/issues/22), the first of step 9's three issues. Lens `paths` globs compiled to a backtracking `RegExp` in `packages/core/src/glob.ts` and ran against file paths the head chooses, so `*a*a*a*a*a*b` over a name of 200 `a`s took 164 seconds. The pull request removes `glob.ts`, and `lensCovers` matches through `matchesGlobs` in `packages/core/src/pattern.ts`, the linear-time engine [#18](https://github.com/melian-agent/melian/pull/18) added for guardrails, which takes under a millisecond there. Dotfiles and newlines in names still match every wildcard, the lens tests pass unchanged, and a test holds three crafted paths to a second each. A `LENS.md` glob past the engine's step limit now throws `Refused` when its lens is selected, since only `melian.yaml` globs are compiled at load; [the core guideline](../guidelines/core.md) records it.
