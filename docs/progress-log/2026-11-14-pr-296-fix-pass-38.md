For [pull request #296](https://github.com/melian-agent/melian/pull/296), fix pass 38 gives every commit a review makes from a task's outcome one question: does the review index still name this review's lens task and the verification it relied on? The coordinator chose the approach on 2026-11-14. [The decision](../decisions/2026-11-14-a-replaced-review-writes-nothing.md) records why it is built here rather than in a follow-up.

- **One ownership predicate** (`169c2626`). `stillOwns` in `src/review-index.ts` answers it. Each of these calls it inside its own commit: starting the verification, detaching a verification when the review finds nothing to verify, recording the restatement links, starting the adjudication with the verification the review relied on, and taking the probe reruns over. A review that fails it throws `superseded` from `replaced()` and writes nothing more. Four new tests in `test/probing-level.test.ts` each failed first at `10046215`:
  - A replaced review starts its verifier late, after the repeat review verified: `expected false to be true`, the repeat review's verdict no longer blocking, because the stale verification had replaced its own and cleared its judgements.
  - A replaced review finds nothing to verify: `expected undefined to be 72`, the repeat review's verification detached.
  - A replaced review with no verifier reaches the link commit: `expected undefined to deeply equal { aa6c527b7d1e4689: … }`, the repeat review's restatement link cleared.
  - Two reviews share a live lens task, and the second replaces the first's verification before the first links or adjudicates: `expected undefined to match object { code: 'superseded' }`, for both.
- **The other commits that write from a task's outcome.** The caller-record commit called a selection check, now `stillOwns`; `runLenses` writes the selection and the task together, so the task alone decides. `startWave` and `VerificationWaves.open` call `stillOwns` too. The decision commit is the replacing side, and asks nothing. `refuseIfBlocked` removes only the review's own tasks, and the dismissal's adjudication in `dismiss.ts` is a dismissal's own, not a review's.
- **A review whose reused wave another retired records no verdict** (`975fa838`). A second review attached to the same lens task can start a final verification that retires a wave the first review reused. The first review's `startVerification` then returns nothing. It used to adjudicate with its verifier check marked failed, so its `not reviewed` adjudication took the index from the other review's. The new test in `test/verification-waves.test.ts` failed first with `expected { task: 66, … } to be undefined`, and the review now ends `superseded`. This case is a builder's choice within the pass's scope.
- **Tests for the rest** (`7e28b0c7`): the predicate's eight answers in `test/review-index.test.ts`, and a review that never takes over another lens task's waves.
- **The stale comment** (`6db57053`): `src/probing.ts` no longer says a fingerprint hashes the wording table.

No existing assertion changed. A user can see one change: a review whose verification or wave a later review replaced now ends `superseded` with no verdict, where it used to end `verifierFailed` or record a verdict over the later review's.
