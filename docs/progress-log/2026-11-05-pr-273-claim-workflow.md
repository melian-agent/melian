The claim workflow, `.github/workflows/claim.yml`, swaps the claim labels so a cloud builder can claim an issue with a comment alone, closing [issue #272](https://github.com/melian-agent/melian/issues/272). On a `Claim:` comment it swaps `status: ready` for `status: in progress` when the commenter is a writer, the issue is ready, and the comment is the earliest writer's claim since the issue was last labelled ready; a writer's `Released:` swaps back. [The decision](../decisions/2026-11-05-claim-labels-by-workflow.md) amends the plan-as-issues rule so that only writers' claims count. `packages/core/test/claim-workflow.test.ts` pins the workflow's shape and runs its own script against a fake client that answers only the exact requests it expects. Each of the script's 30 hand mutants fails its named test. GitHub runs an `issue_comment` workflow only from the default branch, so the four recorded runs on a scratch issue, a writer's claim, a second claim, a non-writer's claim and a release, can follow only once this merges.
