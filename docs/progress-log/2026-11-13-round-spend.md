The `melian round` workflow's comment carries the round's duration, tokens and cost, for [issue #402](https://github.com/melian-agent/melian/issues/402), and `scripts/pr-timeline.mjs` reads them back. A rollup of twenty merged pull requests found only three with any cost, each from a builder's own report, though an Actions round is the most frequent paid step in a build cycle.

The figures were already in the JSON `melian review --json` writes, as its `telemetry` beside the verdict: the run's wall clock in `prepare`, and its tokens and cost in `total.total`. The fix for dcb65174071dfa90 below moved the tokens and cost to the run's rows. No stored shape changes, so no key does either. `publicVerdict` in `scripts/round.mjs` copies them into the public verdict as `spend: { seconds, tokens, cost }`, and nothing else of the telemetry: no stage, model name, note or reason, which a tool or a model could have shaped. Each number is kept only when it is finite and non-negative. A string, a negative value and a missing field are left out. So are a `null`, which is how JSON writes NaN, a `1e309` that parses to Infinity, and a clock that ran backwards. With none left, the spend is left out whole, and a `null` in the telemetry no longer voids the verdict. The report job reads the public verdict a second time, so the spend is read from the public copy then, under the same check. The comment prints `Spend: 572 s, 5644300 tokens, $4.44` on the line after the verdict, inside its code fence, with any refused part left out.

`scripts/timeline.mjs` reads that line only from a `melian-status-bot` comment that opens with the round's marker, and only from the start of a line of its first code fence, where a finding's text cannot reach.
