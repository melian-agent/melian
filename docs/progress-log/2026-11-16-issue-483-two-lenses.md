# [Issue #483](https://github.com/melian-agent/melian/issues/483): a lens of another name probes in the words of the built-in it extends

The maintainer ruled on 2026-11-16, relayed by the coordinator, that Melian's own rounds read and probe through two lenses. `trust-boundary` keeps reading, and a repository lens `trust-boundary-probes`, with `extends: trust-boundary`, probes at its deep level. The first version of [pull request #490](https://github.com/melian-agent/melian/pull/490) refused `probe` on that lens, since it read wording by the lens's name alone.

- `Lens.load` now takes a lens's wording from the built-in its `extends` chain reaches, which `layer()` already resolves, and records it as `probesAs` when that built-in has another name (4c4e49c9). It refuses `probe` on a lens whose chain reaches no built-in with wording, on one whose chain reaches `tests` until [issue #493](https://github.com/melian-agent/melian/issues/493), and on one that takes a built-in's name without extending it.
- The planner, the prober, the planner's reminder, the lens request key and the verifier read `probesAs` before the lens's name. The prober's first line still names the lens itself, which the coordinator chose on 2026-11-16, because the policy after it is that lens's own.
- A lens without `probesAs` keeps its version and its request key, so nothing reviewed before asks again.

Tests first: the core tests for a renamed lens and the reworded refusals failed at 15177603, eight cases across the worktree and revision suites. A renamed lens was refused with "needs probing wording of the lens's own". The pipeline golden for a renamed lens failed on the old pipeline with "the trust-boundary-probes lens has no probing wording of its own, so it cannot probe". Both passed after the change. The golden runs the trust-boundary lens's planner and prober turns through `trust-boundary-probes`, and they match `main`'s byte for byte once the name is swapped back.

A later test runs a lens renamed `tests-probes`, which probes as `tests`, through the verifier, and checks its claim is judged in the `tests` lens's words. With the verifier reading the lens's own name, the review stops with "the verifier did not judge every claim".

Mutation proof: `melian mutants list 15177603...fff66b63 --claims-in` the four changed trust files gives 83 mutants: 76 generated and 7 string literals the configuration ignores. `packages/pipeline/src/probing.ts` changed only a default parameter and a type field, which yield no mutant, so it is not named. At fff66b63, 71 are killed by a named test run alone, which passed unmutated first, and 5 are equivalent with a reason. The first run named the wrong test for 8 of them; a run of each package's suite found the tests that kill 6, and the other 2 are equivalent, since every reader of `probesAs` falls back with `??`.
