The `melian round` workflow's gate now refuses a head whose pusher lacks write permission, in fix pass 1 of [pull request #275](https://github.com/melian-agent/melian/pull/275). It checked only the starter and that the head lived in this repository. [The head-writer decision](../decisions/2026-10-12-trusted-writer-requires-base-repository-head.md) also requires that the identity that pushed the exact head is a writer, so a writer dispatching a round on a Dependabot branch would have run the bot's head with both logins. The CLI exposes no answer from the GitHub provider's `#headWriter`, so `scripts/round-writer.mjs` applies the same rule to every page of the repository's push events. The first event for exactly the head's SHA on exactly its branch names the pusher, and a matching event with no login refuses. With no matching event, the pull request's author stands in. A failed read fails the gate before any job holds a secret. No local test can show the gate refusing a bot's head; a dispatched run stands in, and the script's tests prove the rule.
