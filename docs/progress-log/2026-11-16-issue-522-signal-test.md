[Issue #522](https://github.com/melian-agent/melian/issues/522): the test "reports an ignore command stopped by a signal", in `packages/core/test/source.test.ts`, failed now and then in the merge queue, and ejected pull requests that did nothing wrong. The test alone changed.

- **Cause.** The test stands `git check-ignore --stdin` in for the reader's git, to keep git waiting while it sends SIGTERM on the child's `spawn` event. Since 781b255f on 2026-11-07, `git()` ends git's standard input straight after `spawn` returns, so the `spawn` event comes after the input has closed. A loaded runner let git read end-of-input and exit with 1, "not ignored", before the signal landed. So `isIgnored` resolved, as on [run 43846754110](https://github.com/melian-agent/melian/actions/runs/43846754110). [Pull request #498](https://github.com/melian-agent/melian/pull/498) did not cause it.
- **Reproduction.** A copy of the test that sent the kill 300 ms after `spawn` failed on both source kinds with the CI error. Its call settled in 48 ms, before the kill. The unchanged test passed 40 runs out of 40 under load on Node 22 in a cloud container, so the race is rare there.
- **Fix.** The stand-in sends SIGTERM before it returns, while git's input is still open. The same copy, holding the parent 300 ms after the kill and before `git()` ends the input, passed on both kinds.
- **Runs.** The fixed test passed 200 runs out of 200 under load on Node 22, with eight busy processes on four CPUs.
