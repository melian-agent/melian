# Issue #481: a dismissal replaced during the final judgement

[Issue #481](https://github.com/melian-agent/melian/issues/481)'s restatement test, "asks the verifier again when the root's dismissal is replaced while it judges", failed about one run in three under load with `expected 1 to be 2`. The review asks the verifier again only when an earlier verification wave made the first judgement. When both lenses ended before any wave started, the final step made the only judgement, and it reads the dismissals once. Holding the wave back 500 ms, in a scratch worktree, made the test fail every time; the restatement then showed for attention and `verdict.dismissed` was empty.

The maintainer ruled on 2026-11-18 that a review reads its inputs once, [recorded on the issue](https://github.com/melian-agent/melian/issues/481#issuecomment-6966926120), and [the decision](../decisions/2026-11-18-a-review-reads-its-dismissals-once.md) amends the dismissal record decision for the final judgement. No code changed.

The test now orders its two events: the contracts lens ends only once the wave's judgement has its replacement. A second test turns waves off through a wrapper of `startWave`, so the final step makes the only judgement, and pins one judgement, the restatement under attention and nothing dismissed. Both pass three runs in three with the wave held back 0, 500 and 1,500 ms. Removing the first test's wait fails it three in three with `expected 1 to be 2`, and leaving waves on fails the second three in three with `expected 2 to be 1`.
