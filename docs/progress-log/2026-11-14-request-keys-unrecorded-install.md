Codex's fifth adversarial review of [pull request #436](https://github.com/melian-agent/melian/pull/436) found that a checkout with `node_modules` and no lockfile or install record read as an identified install. The coordinator advised on [issue #394](https://github.com/melian-agent/melian/issues/394#issuecomment-6876467257) to fail closed, as for an unreadable record, and to narrow the decision's one install exclusion. The advice is not a ruling.

Problem: every digest read `unavailable`, so swapping an `@types` package in a hand-built `node_modules` kept the key, and a later review reused the earlier tsc run. Solution: `installDigests` in `packages/pipeline/src/mutation-static.ts` now leaves the install unidentified when `node_modules` exists and no manager's record and no Bun lockfile is present, so `checkReusable` refuses the run. [The decision](../decisions/2026-11-14-request-keys-as-built.md#what-a-check-runs-key-holds-and-leaves-out) now limits the exclusion to a hand edit or `npm link` inside an install a manager recorded.

The fix started with a failing test. At `4bb8dc7a`, "never reuses a run beside a node_modules that no manager recorded" in `packages/pipeline/test/checks.test.ts` failed with `expected 8 not to be 8`. After `fde89e25` it passes, with 303 tests across `checks.test.ts`, `check-request.test.ts`, `mutation-cache.test.ts` and `mutation-enumeration.test.ts`. Bun's test now puts a `node_modules` beside its lockfile, which still reuses, and `aea383e8` adds a test that npm's record alone, with no lockfile, still reuses.

Cost: a checkout with a `node_modules` no manager recorded reruns Biome and tsc on every review. Checks cost no tokens.

The changed code guards trust: it decides what a key matches. The inventory over `4bb8dc7a...fde89e25` is [2026-11-14-issue-394-node-modules-mutants.json](2026-11-14-issue-394-node-modules-mutants.json), with `claimsIn` naming `mutation-static.ts`. [The runs](2026-11-14-issue-394-node-modules-mutant-runs.json) were made at `aea383e8`, each against its named test alone after that test passed unmutated. All nine generated mutants are killed, one by the test `aea383e8` added; one ignored row is a configuration note. Bun's test was renamed, so the ten claims and one hand mutant of [the install records' inventory](2026-11-14-issue-394-records-mutants.json) that named it now name the new test. Their lines had moved, so each was carried by its unchanged line text and run again at `aea383e8`; all eleven are killed.

The rule broke 13 tests whose fixtures faked an install in `node_modules` with no record, so a run under them was never reused. `ba83cfcc` gives `fakeTool` in `packages/pipeline/test/fixtures/repo.ts`, `emptyVitestInstall` in `test/fixtures/vitest-listing.ts` and the `--rerun` test in `packages/cli/test/cli.test.ts` npm's record, as a real install has. The whole gate passed at `ba83cfcc`: 9,267 tests passed and 63 skipped.
