[Pull request #287](https://github.com/melian-agent/melian/pull/287) makes the two slow-response tests in `packages/pipeline/test/stage-telemetry-reader.test.ts` deterministic, closing [issue #283](https://github.com/melian-agent/melian/issues/283). They expected a stage to end at its reply's timestamp plus duration, while [pull request #269](https://github.com/melian-agent/melian/pull/269) caps a stage at its task's end. When the sum passed the terminal commit by 1 to 9 ms, the cap applied and the test failed. The code is right and the test was wrong. A harness clock running 100 ms behind reproduced the failure on every run. The harness clock now runs one second ahead from the terminal commit only, so the reply always ends first. The enumerator lists no mutants for a test-only change. Setting the skew to -100 fails both tests, and the [inventory](2026-11-07-pr-287-telemetry-cap-race-mutants.json) records both runs.
