The first Melian round on [pull request #294](https://github.com/melian-agent/melian/pull/294) blocked on three classes of defect in verification waves. Two waves could run at once, so the eight-conversation cap held per wave, and a later wave could clear a claim an earlier one was still judging, whose stale confirmation then outranked the merged candidate's refutation, live or after a crash. A wave's reuse identity also left out the verifier version. At the maintainer's choice, the smallest fix landed. `ab89a3c` records each wave's verifier version and reuses a wave only under it. `9dd725b` lets a wave own its writes only until a later wave verifies any of its claims, which the report commit and the sweep both check. `f771cd7` and `9cab606` run one wave at a time: the watcher waits on the latest wave before it forms the next. `7430eef` makes the failed-wave test detach the final verification, since it had passed without the failed wave. `5c279b6` pins a second wave starting while a slower lens still runs, and supersession by any later wave. The decision, the verification design and the pipeline guideline say so in `8aea5cf`. The cost is that a lens ending while a wave runs waits for that wave; [issue #313](https://github.com/melian-agent/melian/issues/313) proposes one verification task per revision, which would remove the wait. The pass's inventory, [`2026-11-07-pr-294-2-wave-fixes-mutants.json`](2026-11-07-pr-294-2-wave-fixes-mutants.json), lists all 38 of Stryker's mutants over `c61cf70...HEAD`, each failing a named test run alone. A needless optional chain on `getTask` survived and was removed, and three mutants of an earlier form of the wait made the watcher spin without awaiting; the restructure in `9cab606` removed them.
