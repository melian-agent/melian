[Pull request #310](https://github.com/melian-agent/melian/pull/310), fixes for Codex's adversarial review of 7a1764ec, and for CI on it.

- A copy kept its place whenever its `.synced` marker matched the branch, though nothing tied the marker to the copy's contents. With `main.jsonl` deleted or cut short, Pi would read an empty or shorter store, and the next push would replace the branch's intact one. Pi only appends to its main log and trims nothing but a torn last line, so a copy that grew from the branch's tree starts its main log with the tree's. A checkout now keeps the copy only when it does, and otherwise sets the copy aside and restores the branch's. Sidecars are left to Pi's own recovery, which rewrites and removes them, so no size check on them could tell damage from compaction. `restores the branch's copy over a local main log deleted since it synced` and `… cut short since it synced` failed first on 7a1764ec; `keeps a local copy that has grown past the branch's` guards the other side.
- An index that recorded a write of a changeset whose tree the branch did not hold read the changeset as new and empty, and the next push kept it so. Reading the branch now refuses such an index. `refuses an index that records a write of a changeset the branch holds no tree for` failed first on 7a1764ec.
- CI failed on every Linux job with `checks two changesets out of one clone at once`: two first pushes created the branch at the same moment, and git 2.55, which CI runs, words the loser's porcelain line differently from git 2.43, which this container runs, so the race read as a failed push. The push now retries whenever the remote says it could not lock the branch's ref, whatever the porcelain line says; the push names no other ref. `pushes again when the remote could not lock the branch, however the rejection is worded` fails without the change, with CI's error.
