Enola is pinned at 0.4.40 in place of 0.4.27, for [issue #346](https://github.com/melian-agent/melian/issues/346), through [pull request #385](https://github.com/melian-agent/melian/pull/385). The release is past the two-day window, so the old pin's exception went with it. Commands, flags, exit codes, SARIF, receipts and the impact JSON keep their shape. From 0.4.37 Enola spans a TypeScript symbol to its closing brace, which would have changed every Enola finding's ID. The maintainer ruled that a result keeps the identity of the line it starts on, as [the one-line identity decision](../decisions/2026-11-13-enola-results-keep-one-line-identity.md) records. On eight past merges, `static.enola` finds the same complexity and domain results. Performance results change by v0.4.28's rework, which states loop depth instead of a Big-O. The spike on `main` at `0bde70ca` matches 1,887 of 23,596 call pairs against tsc, up from 1,418, and 608 of 1,651 imports, unchanged. The manifest tests now fix their own release time and exception, so the next upgrade changes only the versions they assert.
