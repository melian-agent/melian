[Issue #244](https://github.com/melian-agent/melian/issues/244), second pull request: the CLI keeps a pull request's storage on `melian/state`. `ChangesetStore` in `packages/cli/src/state.ts` opens a pull request's storage as this clone's copy of the branch's JSONL storage. `review`, `publish`, `dismiss` and the `compare` writes take the lease first and push when they finish; `findings` and `telemetry` read under the copy's lock alone. A range, scripted mode and a pull request with SQLite storage from before keep SQLite, and the last says so. The writers' key comes from the secrets files under the provider `melian-state`, which `createReviewModels` never sees, and doctor's `state key` line names its source. The maintainer ruled that a command which cannot reach the branch warns and works in the clone's copy, and state-git's checkout now keeps the copy's lock when it does, or when no key is set. `packages/cli/test/state-branch.test.ts` reviews, publishes and dismisses through the fake GitHub in one clone, and shows a fresh clone of the same origin restoring the marker secret, the ledger comment and the dismissal, which closes the risk-table row on losing the one clone. Its other cases cover a held lease, a busy copy, legacy SQLite storage, a missing or malformed key, a refused push and its resume, and a branch lost before the push.
