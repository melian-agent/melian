# 2026-10-24: the finding register, as a guideline and a decision

[Pull request #198](https://github.com/melian-agent/melian/pull/198) adds [the findings guideline](../guidelines/findings.md), which sets how a finding reads: seven parts, length targets, voice, certainty through the verifier's word, severity and tone, an emoji table, five worked examples and a checklist. [The decision](../decisions/2026-10-24-finding-register.md) records the maintainer's rulings on language, emojis, their switches, the `AGENTS.md` emoji rule and lens emojis, with the anonymised counts behind them. [Configuration and layering](../design/configuration-and-layering.md#language-and-emojis) gains `language`, `output.emoji` and `publish.emoji`, and [the lens page](../design/lenses.md) the `LENS.md` `emoji` field. Plan step 35, [issue #197](https://github.com/melian-agent/melian/issues/197), builds it.

Checking the draft against the code corrected three readings. `report_finding` takes `explanation.why` and `explanation.fix` and stores them as `whyHere` and `whatToDo`. It has no headline: it stores What as the message, so the terminal prints that sentence twice, and only the GitHub comment skips the copy. Melian's linear pattern engine matches by UTF-16 code unit and refuses `\p{...}`, so the literal-emoji check is a Biome plugin unless the engine gains a property class. The injection example now blocks, since the default table blocks a P1 and the injection floor only sets a minimum of `acknowledge`; a verifier judges it like any lens finding, and cannot lower it.

The language stays out of every reuse identity, including a lens run's instruction identity, so the decision amends [the instruction-identity decision](../decisions/2026-10-06-lens-instruction-identity.md). The `melian/review` commit status keeps its plain description, because the merge-group job reads it back; the rulings' status lines are the findings' own.

Codex's adversarial review found three gaps, fixed in one pass. A refuted claim the trust floor protects, from `lens.trust-boundary` or `lens.tests` or under `untested-behaviour` or `melian/injection-attempt`, stays posted with its refutation and its floor, so the certainty table has a row for it. `runIdentity` in `packages/pipeline/src/checks.ts` hashes the whole effective configuration into a check run's `policy` identity, so step 35 hashes a projection without `language` and the emoji switches, with a same-revision reuse test. The guideline now defines a lens finding's seven parts apart from a deterministic finding's five, and every lens example shows the failure scenario, evidence and verifier's reason that `report_finding` and the verifier supply.
