# Step 14, credential commands run when a model is asked

A repeat review that spends no tokens no longer runs a credential command. `reviewChangeset` takes `unlockModels` and calls it once, ahead of the first lens, triage, or verification task it creates or resumes; it reads the stored task first and skips the call when a finished task of the same selection stands. `hasCredentials` replaces three `checkAuth` calls on the route, verifier, and triage-model paths, since `checkAuth` ran the command. The credential error now fails the review before the first model request but after the storage opens, which [the decision](../decisions/2026-10-07-credential-commands-run-when-a-model-is-asked.md) records, superseding the named-bearer decision's timing.
