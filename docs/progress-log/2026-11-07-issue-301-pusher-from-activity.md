[Issue #301](https://github.com/melian-agent/melian/issues/301): the GitHub provider now names a pull request head's pusher from the repository activity API, not the events feed. The feed lags by hours and keeps only 300 events, so a head pushed minutes ago had no event, and the provider fell back to the author. `#headWriter` in `packages/github/src/provider.ts` reads `GET /repos/{owner}/{repo}/activity` for the head's branch, newest first, a hundred entries a page, and stops at the first `push`, `force_push` or `branch_creation` whose `after` is the head. No matching entry, an entry with no actor and a failed read each record a writer error. The maintainer ruled the author fallback retired everywhere, so the CLI's `writerTrust` takes the pusher alone. [The activity decision](../decisions/2026-11-07-head-pusher-from-repository-activity.md) amends [the head-writer decision](../decisions/2026-10-12-trusted-writer-requires-base-repository-head.md). The fake GitHub answers the activity endpoint only for the ref a request names. `packages/github/test/provider.test.ts` and `packages/cli/test/writer-trust.test.ts` failed first at `origin/main` for the reported reason: the provider read the events feed, and the CLI trusted the author of a head with no pusher. [Pull request #299](https://github.com/melian-agent/melian/pull/299) makes the same switch in the `melian round` workflow's gate.
