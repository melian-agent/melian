[Pull request #310](https://github.com/melian-agent/melian/pull/310), the fix for Codex's adversarial review of 853b4a2d.

- A checkout judged the copy only when it opened it, so a copy damaged afterwards, its main log or a sidecar deleted, could still be pushed over the branch's intact tree. A push now reads each file once, writes those bytes to a directory of their own, and pushes only when they still hold the synced tree whole: the main log starts with the tree's, and `validate` opens them. `refuses to push a copy that lost its main log after checkout, and leaves the branch's` and `… lost a document sidecar …` failed first on 853b4a2d. Judging exactly the bytes it pushes also keeps a torn read from landing. The golden sealing vector's file is not Pi's, so its test gives the clone a `validate` that accepts anything; the vector is unchanged.
