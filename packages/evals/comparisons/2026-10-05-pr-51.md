## Maintainer decisions

- **Objects render themselves.** Rendering is a method of the object rendered, and `Rendering` holds only shared options. From C5.
- **`Lens`'s field order may differ from the loader's where the hash cannot see it.** `file` and `nearer` are outside the version hash, so `version` may precede `file`. From C7.
- **A refactor that promises unchanged stored shapes pins every hash it touches, to literals the old code computed.** The lens tests pin the built-in versions and an override's, and the verdict fingerprints are pinned to values `main`'s code computed at 4403138, beside the render goldens. A one-off comparison proves the claim on the day; only a pinned literal keeps it. From B4, C1, and D2.
- **`Changeset.withId`'s test waits for the follow-up pull request.** #51 was queued at b53fc47 without it. From E3.

## Differences

This is the first pull request in milestone 2 where Codex approved and the review of record found no behaviour defect. It is no small change: fourteen commits refactoring four packages. The byte comparison earns much of the credit. A reviewer reading a refactor of this size can otherwise say only that nothing looked wrong. The Opus review ran `main` and the branch over one scenario set and compared the stored JSON, fingerprints, lens versions, and renderings byte for byte. That turned "no stored shape changed" from a claim in the pull request's body into a measurement, and left the review free to find what the comparison could not: missing pins, two readers of one defect disagreeing, and gaps in the rule.

A measurement on one day is not a test, and Melian found the gap. C1 and B4 found the hole for lens versions: the comparison proved them unchanged once, and no test kept them so. Nobody at 7aaaad9 found the same hole for verdict fingerprints. Codex approved, and the Opus review passed the fingerprint claim on its byte comparison. At round three Melian's `tests` lens showed that every fingerprint test compared the code under test with itself, so a changed hash input would pass the gate and post a second review of every published verdict (D2). It was the only test-level defect in the pull request's central claim, and only Melian raised it. cb004cb pinned the literals `main` computes, and every branch value matched.

What else remained was tests and docs. C2 is the one finding near behaviour, and the comparison saw no difference from `main`, because the two rules disagreed only between the branch's new readers. C5 is the rule the pull request enforces, broken by the class that held the rendering, and only a reader who asked whose behaviour each method was caught it. D5 is the same rule broken in a form neither check can see: a free function that builds a domain object rather than taking one.

Melian's first round was lost to the provider's limit, not to a defect: the second review in the milestone to read not reviewed because of a 429. `conventions` also spent its budget of 30 tool calls on a diff of this size before it finished. With every budget raised, the self-review loop ran three more rounds, four in all. Each round found something the last had not, though every one of those findings was already in the branch at 7aaaad9: round two found B3 and B4, round three D2, D4, D5, and D6, and round four E3. Against the thirteen distinct findings across all rounds, notices aside, Melian's recall is seven in thirteen and its precision seven in seven. The Opus review of record found seven, C1 to C7, one of them B4. Of the six Melian missed, C2, C3, and C5 needed a reader to reason about the new classes rather than about one file's tests or docs. Codex's approve missed all thirteen; it compared lens hashes and fingerprints against `main` but did not ask whether a test kept them.

The branch also left a trap for the next agent. The two agents that gated each commit used `git rebase --exec "npm run check"`, and git sets `GIT_DIR` and `GIT_WORK_TREE` for an exec command. Every git command the test suite ran on its temporary repositories ran against the real checkout instead: it set `core.bare = true` and left commits nobody made on a branch named `feature`. [#52](https://github.com/melian-agent/melian/pull/52) records it in `AGENTS.md`.

One finding overlaps another: B4 is part of C1. B1, B2, D1, and E1 are one notice, and D3 and E2 repeat B3. No reviewer raised a finding the maintainer judged noise.
