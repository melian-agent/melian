## Maintainer decisions

- **Objects render themselves.** Rendering is a method of the object rendered, and `Rendering` holds only shared options. From C5.
- **`Lens`'s field order may differ from the loader's where the hash cannot see it.** `file` and `nearer` are outside the version hash, so `version` may precede `file`. From C7.
- **A refactor that promises unchanged stored shapes pins every hash it touches.** The lens tests pin the built-in versions and an override's, beside the render goldens and the legacy-fingerprint test. From B4 and C1.

## Differences

This is the first pull request in milestone 2 where Codex approved and the review of record found no behaviour defect. It is no small change: fourteen commits refactoring four packages. The byte comparison earns the credit. Codex's approve and the review of record's agreement are only as strong as the evidence, and a reviewer reading a refactor of this size can say only that nothing looked wrong. The Opus review ran `main` and the branch over one scenario set and compared the stored JSON, fingerprints, lens versions, and renderings byte for byte. That turned "no stored shape changed" from a claim in the pull request's body into a measurement, and left the review free to find what the comparison could not: missing pins, two readers of one defect disagreeing, and gaps in the rule.

What remained was tests and docs. C1 and B4 found the same hole: the comparison proved lens versions unchanged once, and no test kept them so. C2 is the one finding near behaviour, and the comparison saw no difference from `main`, because the two rules disagreed only between the branch's new readers. C5 is the rule the pull request enforces, broken by the class that held the rendering, and only a reader who asked whose behaviour each method was caught it.

Melian's first round was lost to the provider's limit, not to a defect: the second review in the milestone to read not reviewed because of a 429. `conventions` also spent its budget of 30 tool calls on a diff of this size before it finished. Round two, with every budget raised, found B3 and B4, both real and both its own in part: no other reviewer raised B3, and B4 names the exact mutation C1 guards against. Against the eight distinct findings, notices aside, Melian's recall is two in eight and its precision two in two. Of the six it missed, C2, C3, and C5 needed a reader to reason about the new classes rather than about one file's tests or docs. Codex's approve missed all eight; it compared lens hashes against `main` but did not ask whether a test kept them.

The branch also left a trap for the next agent. The two agents that gated each commit used `git rebase --exec "npm run check"`, and git sets `GIT_DIR` and `GIT_WORK_TREE` for an exec command. Every git command the test suite ran on its temporary repositories ran against the real checkout instead: it set `core.bare = true` and left commits nobody made on a branch named `feature`. [#52](https://github.com/melian-agent/melian/pull/52) records it in `AGENTS.md`.

One finding overlaps another: B4 is part of C1. B1 and B2 are one notice. No reviewer raised a finding the maintainer judged noise.
