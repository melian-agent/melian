# Comparison review: pull request #55

Pull request: [melian-agent/melian#55](https://github.com/melian-agent/melian/pull/55). It takes `dist/` out of the development loop. In a checkout, the CLI shim runs `src/bin.ts` through a `module.registerHooks` resolve hook that adds the `@melian-agent/source` condition; only the published tarball imports `dist/bin.js`. Each package gains `prepack` and `postpack`, and tsc's build-info files move to `.tsbuild/`. A committed `.vscode/settings.json` hides build output. Docs, skills, and `AGENTS.md` learnings drop the build step. The fixes added a root `npm run pack`, which builds and then packs with `--ignore-scripts`, and a CI step that packs, installs, and runs the published CLI on every Node version.

Reviewers: Codex adversarial review; Melian's own review, as a range, in four rounds; and an Opus review of record. Codex, the Opus review, and Melian's first round reviewed the branch at ed41a73. After a merge of `main`, 9c60ca4, their fixes landed one commit each: 628f562, 79c2760, 1e2bb4f, 562d5c8, and 4437d56. CI passed at 4437d56 on Node 22, 24, and 26, with the new pack step. Melian's second round reviewed 4437d56. Its fixes landed in 25a1296 and cb35b8f, and bb51e19 added a plan line from the Opus review's follow-up suggestion. Round three reviewed bb51e19, and its one fix landed in bc43cb1. Round four reviewed bc43cb1 and found nothing new. CI passed on bb51e19 and bc43cb1, and the maintainer marked #55 ready at bc43cb1 and queued it. Neither Codex nor the Opus review ran on a later head than ed41a73.

Adjudication gives the severity and the maintainer's disposition. Every finding was accepted, and none was judged noise. D20 stands by design, and D23 is left as is; rounds three and four repeated both. The Golden column says whether a golden should be written. None is owed: every finding is a build, packaging, CI, or documentation concern outside what the lenses' goldens measure.

This record links [the decision that `dist` exists only to publish](../../../docs/decisions/2026-10-05-dist-only-at-publish.md), which arrives with #55, so the link resolves once both land.

## Maintainer decisions

- **A linked clone runs its working tree.** A maintainer links a clone kept on `main`, as the decision and `docs/guidelines/cli.md` say. Step 14 of the implementation plan owes `melian doctor` printing the linked clone's commit and whether its tree is dirty, which bb51e19 added from the Opus review's follow-up suggestion. From D20 and F20.
- **The shim is the one exception to the imports rule.** Its resolve hook must register before the CLI's module graph loads, and a static import would load the graph first. From B21 and C5.
- **A release packs through `npm run pack`.** It builds first and packs with lifecycle scripts off, so neither `prepack` nor a user's `ignore-scripts` decides what ships. From A1, B20, and C1.
- **`prepack` and `postpack` stay untested.** The release path never runs them. From D23, E21, and F21.

## Differences

All three reviewers found that nothing ran the published CLI: Codex's A1, Melian's B20, and the Opus review's C1. It is the first finding in milestone 2 that all three raised. Each reached it its own way. Codex asked what the step called a publish check proved. Melian read the base's `cli.test.ts`, which built `dist/` and ran it, and saw the change delete the only test of the published path. The Opus review packed the tarballs itself and found a second way to ship one without `dist/`, under `ignore-scripts`. One commit, 628f562, closed all three.

Codex and the Opus review both found that every `postpack` ran the root `clean` (A2, C2); Melian did not. Its only output on the eight `package.json` files was the policy notice, and no lens asked what a lifecycle script deletes beyond its own package. The fix met a trap neither review named. Deleting `dist/` alone leaves the build-info file, so `tsc -b` finds the package up to date and the next pack ships without `dist/`.

Only Melian saw the imports rule broken (B21), the published CLI's stderr left unchecked (D21), and the scripted-mode docs still promising a built binary (E20). All three came from reading past the diff. B21 quoted `AGENTS.md` and noticed that the `dynamic-import` guardrail looks only under `packages/*/src/`. D21 and E20 both read the base's `cli.test.ts`. D21 found its `stderr: ""` assertions, which once covered the built CLI. E20 found the `beforeAll` that built the CLI, and then the two places that described it. The Opus review read the same lines as B21 and asked only that the comment give a reason (C5). D21 sits in the step 628f562 added, which neither Codex nor the Opus review saw.

The Opus review was the only one to test the author's claims rather than read them. Codex ran the checkout's shim once, on Node 24. The Opus review ran each claim on every Node version CI runs, packed and installed every tarball, and showed why `registerHooks` replaced `module.register` by watching the SQLite warning leak. That is why it could pass the pull request's central claim, that nothing in development needs `dist/`, on evidence rather than on its reading of the diff.

#55 is the first pull request Melian self-reviewed with no build. All four rounds ran from the shim, which ran the branch's source; the change under review is what made that possible. Before it, a self-review needed `npm run build` first: [#51](https://github.com/melian-agent/melian/pull/51)'s round one ran "from the branch's build", as [its record](2026-10-05-pr-51.md) notes. Either way the change under review judges itself, the arrangement D20 describes. The self-review loop accepts that; D20's hazard is a contributor's pull request checked out in a maintainer's linked clone.

Notices aside, the reviews raised thirteen distinct findings: A1, A2, B21, C3 to C7, D20 to D23, and E20. Leaving out C7, which #55 did not introduce, Melian's recall is seven in twelve and its precision seven in seven. The Opus review found six of the twelve, and C7 besides; Codex found two. Two of Melian's seven, D21 and D22, sit in lines the fixes wrote, which neither Codex nor the Opus review saw. Against the ten findings already in the branch at ed41a73, Melian found five, the Opus review six, and Codex two. Round one found two of those ten. Round two found two more, D20 and D23, and round three one more, E20, as #51's later rounds found what its first had missed. Round four found nothing new and closed the loop.

B20 and C1 restate A1, and C2 restates A2. B21 and C5 share a fix but not a claim. E21 and F21 repeat D23, and F20 repeats D20. B1–B19, D1–D19, E1–E19, and F1–F19 are one set of notices. No reviewer raised a finding the maintainer judged noise.
