# Comparison review: pull request #43

Pull request: [melian-agent/melian#43](https://github.com/melian-agent/melian/pull/43), which writes the convention "behaviour belongs to the object it is about" into `AGENTS.md`: a function whose first parameter is a `Finding`, `Defect`, `Verdict`, `Manifest`, `Lens`, `Revision`, or `Changeset` is a method. It adds the `free-domain-function` guardrail to the root `melian.yaml`, a decision file superseding the class convention, and plan step 12 for the refactor. After review it also adds a Biome GritQL plugin, `biome/free-domain-function.grit`, with an exclusion list and a drift test.

Reviewers: Codex adversarial review; Melian's own review through the CLI, with its two built-in lenses, `correctness` and `contracts`; and an Opus review of record. All three reviewed the branch at 3a2dfcb. The fixes landed afterwards in twelve commits, ad145d2 to 4c78657. Melian reviewed 4c78657 in a second round and raised only policy notices. Neither Codex nor the Opus review of record ran on it.

Adjudication gives the severity and the maintainer's disposition. Every finding was accepted, and none was judged noise. Two of Melian's four are `guardrail/policy-change-review` notices, which fire by design on any change to the policy Melian reviews under. The Golden column says whether a golden should be written. One is owed, for the `conventions` lens that milestone 2's step 3 adds: a change that adds a free function over a `Finding`, expected to report it with the rule's wording from `AGENTS.md`. The checks themselves need none. The plugin's scratch-file tests and the drift test, both in `scripts/free-domain-function.test.mjs`, cover them.

This record links [the decision](../../../docs/decisions/2026-10-04-domain-objects-carry-behaviour.md) that arrives with #43, so the link resolves once both land.

## Maintainer decisions

- **Outer packages adapt core objects through their own classes.** The rule has no layering carve-out, and an outer package does not push its concern into core. github renders a comment in `ReviewComment.from(finding)`, the CLI keeps an exit code on a CLI-side object, and a migration is a static `upgrade` on the stored shape. From C2.
- **The guardrail covers every changed line; the lint rule carries the exclusions.** The guardrail runs with no exclusions, so a touched legacy function is refactored then. The Biome rule scans whole files, so only it needs an exclusion list, and the drift test keeps that list equal to the files that break the rule today. From A2 and C4.
- **Transforms are methods, constructions static factories.** A transform from a domain object is `finding.toSarif()`, and a construction into one is `Finding.from(stored)` or `Diff.parse(text)`. What stays free is a definition that returns data, or a module-private helper with no domain object in sight. From C8.

## Differences

Codex found two, and both went to whether the guardrail enforced anything. Its first showed the pattern keyed on names, so it both missed real cases and flagged strings. Its second changed the enforcement split. The pull request had put the grandfather list on the guardrail, but forbidden-patterns scans added lines only, so the list never spared legacy code; it only let new free functions into the eleven files where the debt sits. The guardrail now runs with no exclusions, and the list moved to the whole-file Biome rule, with a drift test that holds it to the files breaking the rule today.

The Opus review of record found nine, six of its own. Beyond the enforcement gaps, it tested the rule as prose: whether an agent can decide it, whether its four lists agree, whether the decision stands alone, whether the Pi analogy holds, and whether layering lets it apply at all. Its second drove the maintainer decision that outer packages adapt through their own classes.

Melian's own review caught two defects in a guardrail written to enforce a rule on Melian. Both came with evidence from the repository: three wrapped signatures the pattern would miss, `dedupeFindings`, `renderLensInstructions`, and `planPublication`, and three string parameters it would wrongly flag. Melian rated both P2; the adjudication rates the wrapped-signature miss high, with Codex's first finding, because it let most real domain functions past. Its two lenses review code for defects and contract breaks, yet both findings sat in a YAML regex. Against the ten distinct findings of the first round, Melian's recall is two in ten and its precision two in two, leaving its two notices aside. It raised nothing about the prose of the rule, the decision, or the plan, where six of the ten sit, nor about the grandfather list exempting new code, a defect in the same file as its two findings.

Melian's second round found no defect in the fix pass. It blocked on `biome.json` instead, because the plugin's exclusion list turns a check off for eleven files, and a changed analyser configuration is exactly what a maintainer must read before the head judges itself with it. The maintainer read it and accepted it.

Five findings overlap others: B3, B4, and C3 restate parts of A1, C4 is A2, and C1 shares B4's cause. No reviewer raised a finding the maintainer judged noise.
