# Comparison review: [Pull request #98](https://github.com/melian-agent/melian/pull/98)

[Pull request #98](https://github.com/melian-agent/melian/pull/98) is milestone 2 step 16, the mutation check: `static.mutation` runs Stryker on Vitest over the lines a head adds or edits and judges them by what survives. It merged at `4471af34` from head `58c6da06`. It took three lives to get there, and this record covers all three.

1. **The original branch.** Twelve rounds on the branch `mutation-check`, the last at `6aadaefc`, tagged `archive/mutation-check-r12`. The head code ran inside a sandbox the branch built itself (a seatbelt profile and bubblewrap binds). Round twelve met the stop rule the maintainer had set for new blocks in the sandbox and its housekeeping, and he approved a split on 2026-10-13.
2. **The rebuild on the sandbox branch.** The split moved the sandbox into [pull request #112](https://github.com/melian-agent/melian/pull/112), "sandbox boundary", and rebuilt [pull request #98](https://github.com/melian-agent/melian/pull/98) on top of it (`d8dcbce7`, branch `mutation-on-sandbox`, force-pushed over `mutation-check` with a lease, `6aadaefc` to `82df2eb7`). [Pull request #112](https://github.com/melian-agent/melian/pull/112) never merged. The maintainer ruled on 2026-10-14 that static analysis tools need no sandbox, only agents do, and closed it. Its head is the tag `archive/sandbox-boundary-r5` (`796935a1`). It has no record of its own, because no pull request that did not merge gets one under the guideline. This record carries its reviews as the second life, and says so below.
3. **The rebuild on `main` with no sandbox.** Branch `mutation-unconfined`, force-pushed over `mutation-check` with a lease (`d8dcbce7` to `3be6f52e`) and retargeted to `main`. Twelve rounds more, then the merge. The run executes the head's tests as an ordinary child of the reviewer, for a head the host allows, and the sandbox, the loopback flag, the scratch home and the confinement field are gone.

Letters identify the reviewers and the rounds.

- **O5 to O12** are Melian's rounds five to twelve on the first life. Rounds one to four are not here: their output files were lost in the reboot of 2026-10-08. See "How this record was made".

## The rulings that shaped the three lives

The pull request moved when a ruling moved it. In date order:

- 2026-10-08. The maintainer decided: head code runs in a sandbox (seatbelt or bubblewrap, else the check skips with leave); the loopback stays open on macOS because Stryker 10 cannot fix its logging port; related tests plus an incremental cache keyed by the exact head.
- 2026-10-09. Three rulings on [pull request #98](https://github.com/melian-agent/melian/pull/98)'s round seven: the `trust-boundary` lens runs on Opus; unmutated lines past the budget become one advisory per run, not a P2 per file; the loop is bounded, with a view on a split.
- 2026-10-12. Selection of tests: "ask Vitest, in the sandbox"; drop the hand parse of the config and the hand-built import graph. Any failure or empty answer falls back to the whole suite. This ended four rounds of selection findings.
- 2026-10-13. Round twelve met the stop rule. The split into [pull request #112](https://github.com/melian-agent/melian/pull/112) and a rebuilt [pull request #98](https://github.com/melian-agent/melian/pull/98) was approved, with one lease-guarded force-push over `mutation-check` after the tag `archive/mutation-check-r12`.
- 2026-10-14. "Static analysis tools don't need to run in a sandbox, only agents do." [Pull request #112](https://github.com/melian-agent/melian/pull/112) was closed unmerged; the mutation check was rebuilt without it, with a guard: it runs the head's tests only for a head the host allows. Then four rulings on the rebuild: a longer timeout (7,200 s, provisional); a fork's mutation result counts like CI tests; a fork's head runs no mutation check on the reviewer's host and reads not reviewed until a credential-free job exists in milestone 3; and no run-time recheck.
- 2026-10-15. Ruling (b) on round eight's P1 `b1fdc833`: a committed range runs the mutation check only with `--trust-head`, and author or committer identity is no evidence. Then, on round nine: under that flag the check's settings come from the working tree and without it from the base; `checkout` leaves `WriterTrust`; the installation identity covers pnpm, Yarn and Bun lockfiles.
- 2026-10-16. The dismissals (below), and the instruction that a rerun at the same head is allowed (`RERUN=1`) when the mutation check times out on a loaded machine.
