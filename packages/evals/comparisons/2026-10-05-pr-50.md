# Comparison review: pull request #50

Pull request: [melian-agent/melian#50](https://github.com/melian-agent/melian/pull/50), the last part of milestone 2's step 3. It adds `durability`, a repository lens under Melian's own `.melian/lenses/`, to the `full` tier of Melian's root `melian.yaml`. The lens states Pi Durable's replay and idempotency contracts as facts and hunts the change that breaks one. Five goldens come with it: four seeded from findings in the records of [#11](https://github.com/melian-agent/melian/pull/11), [#16](https://github.com/melian-agent/melian/pull/16), [#18](https://github.com/melian-agent/melian/pull/18), and [#19](https://github.com/melian-agent/melian/pull/19), and one clean.

Reviewers: Codex adversarial review; Melian's own review, as a range; and an Opus review of record. All three reviewed the branch at 4bda094. The fixes landed in six commits by 993570d: 5525ca6, 6a93bb0, 9cc230c, 0d6222d, f435f78, and 993570d. bddda8a appends the re-measurement of the corrected lens to the run record, and cf7cd70 keeps the clean golden clean under the corrected rule. Melian reviewed cf7cd70 in a second round, which raised only policy notices and closed the loop. Neither Codex nor the Opus review ran on a later head.

Adjudication gives the severity and the maintainer's disposition. Every finding was accepted, and none was judged noise. The maintainer ruled that Pi Durable's source, not any review, settles each contract the lens states, and the fix pass checked each claim against it. The source also added three facts no review stated: a non-finite number fails a commit as a `Map` does, only a direct `document.field = undefined` deletes a key, and `harness.abortTask` starts no scheduler. The source contradicted the reviews twice, and the lens follows the source. Codex's A2 said any `undefined` in a document makes the commit fail; only a nested one does, and a direct assignment deletes the key. Melian's B3 also named a change that touches only docs; such a change already loaded the root's lenses, so the defect held only for a change with no paths. One imprecision stays in the lens: its resume contract says every unfinished task the registry defines restarts, where the scheduler also skips a task already waiting or running. The maintainer judged it too small to fix.

The Golden column says whether a golden should be written. Two are owed, both for `durability`, as Codex recommends: an upgrade golden, where a finished task's result changes shape while an older Melian's result can still be read (A1), and a negative golden, an optional member left `undefined` in a task's input or result (A2). #50 reseeds `durability-resumed-publish` (C1), and the plan tracks a targeted injection golden for the lens (C11). The lens body, tests, or documents cover the rest.

This record links [the decision on the durability repository lens](../../../docs/decisions/2026-10-05-durability-repository-lens.md) and [the seventh live run](../runs/2026-10-05-live-goldens-7.md), which arrive with #50, so the links resolve once both land.

## Maintainer decisions

- **Pi Durable's source is the arbiter for every contract the lens states.** Where a review and the source disagree, the source wins. From A1, A2, C1, C2, C4, C5, and C8.
- **A golden seeds only what its head introduces.** `durability-resumed-publish` is reseeded: its base aborts leftover publish tasks before creating its own, and the head swaps that for resuming and waiting. From C1.
- **The one-sided hand-off is recorded with its cost and a remedy.** The decision file says `durability` hands to `correctness` but nothing hands back, against the boundaries decision, at a measured worst precision of 0.44. The plan's step 13 adds per-file hand-offs after step 12, which moves lenses onto objects. From C3.
- **A repository lens a tier names is an allowed skip when a change has no paths.** With no paths, the root's repository lenses load beside the built-ins. From B3.
- **The corrected lens ships below the bar, with no second tuning round.** Its double report on `durability-attach-key` is its own miss, for the next tuning pass; the per-file hand-offs of the plan's step 13 address the other lenses' extras. From the re-measurement.
- **`durability` reviews the CLI.** The CLI opens each harness and so decides which tasks a resume restarts. From C9.

## Differences

Most findings on this pull request were not in code. Six of the fifteen distinct findings say the lens body states a Pi Durable contract the runtime does not keep: migration (A1), JSON (A2), resumption (C1), hooks (C4), the restart point (C5), and keyed replacement (C8). This is the first pull request whose dominant class of finding was a misstated contract in a lens body rather than a defect in code. Each needed a reviewer to read the dependency's source. Codex read Pi Durable's built files and Chord's JSON tracker before it reported. The Opus review named behaviour only the source shows, such as `afterTool` running on a replay. None of Melian's lenses caught any of the six. `durability` was skipped, and the lenses that ran read a lens body as prose, not as claims about code under `node_modules`. The policy notice on `LENS.md` (B1) asked a maintainer to read the file, and that was as close as Melian came.

It is the second pull request whose new lens never reviewed it. On [#42](https://github.com/melian-agent/melian/pull/42) the four new lenses existed only on the branch, so the first round, a range run from `main`'s build, could not load them. Here `durability` loaded and recorded the allowed `skipped: no paths`: it covers pipeline and GitHub source, and the pull request changed neither. The skip is correct by design. It also meant the lens never met its own defects, which sat in its body, outside its paths.

The live run could not see these defects either. Run 7 measured recall of 1.00 and no extra of the lens's own, before any reviewer read it. No golden exercised migration or a value that is not JSON, so a lens with wrong facts there scored perfectly. In C1's case the golden rested on the misstatement: the lens scored a hit on a defect its change did not introduce. The two goldens A1 and A2 owe are the ones that would have shown it.

Melian's three lens findings were its own; no other reviewer raised B3, B4, or B5. B3 was the only finding about how Melian runs rather than what the lens or its goldens say: naming a repository lens in a tier turned a change with no files into not reviewed. `correctness` traced it through four files and cited the existing test that shows the failure. Against the fifteen distinct findings of the first round, Melian's recall is three in fifteen and its precision three in three, notices aside. It missed both high findings, A1 and C1.

One finding overlaps another: C2 is A2. C1 shares A1's fix, and C10 shares B5's. No reviewer raised a finding the maintainer judged noise.

Correcting the facts cost the lens precision. Tuned on the misstated contracts, `durability` reported nothing of its own; corrected, it reported four extras in three passes, and its goldens' worst precision fell from 0.44 to 0.31. One extra came from the corrected keyed-replace rule itself, which found a real interleaving in a golden written as clean, and the golden changed rather than the rule. The other three are the lens failing its own instruction to report one defect once. A perfect score on wrong facts was worth less than a lower score on the right ones.
