# Comparison review: [pull request #73](https://github.com/melian-agent/melian/pull/73)

Pull request: [melian-agent/melian#73](https://github.com/melian-agent/melian/pull/73), milestone 2's step 8, the ledger. Publication keeps one signed comment per pull request, which Melian owns and edits in place. It holds the current verdict, an optional walkthrough, run details, dismissal reasons, and earlier rounds, collapsed, and the commit status links to it. An addressed finding's comment is edited to name the first commit that addressed it, and its thread is resolved over GraphQL. A JSON stamp under the marker makes ledger edits idempotent after a crash or a lost local record. A new summarise task writes the walkthrough during review, on the light route, through one recording tool. `melian findings` gains a fenced prompt block for agents, and `publish.walkthrough` and `--no-walkthrough` control the summary. The published and verdict documents move from version 3 to version 4. Codex, on GPT-6.1 Sol, wrote it through the Codex companion, and a Sonnet agent committed it as eight commits, 7bb28a2 to 17d20dc.

Reviewers: Codex adversarial review, on GPT-5.6 Sol; Melian's own review, as a range; and two reviews of record, one by Sonnet 5.5 and one by Opus 5.5. The second review of record is a trial: the maintainer wants to know whether a Sonnet review of record is enough. All four reviewed 17d20dc, where CI passed on Node 22, 24, and 26. [Pull request #61](https://github.com/melian-agent/melian/pull/61) landed on `main` after the reviews, and the ledger's branch now conflicts with it. A Codex fix pass answering all four reviews is in progress. Its commits, and the merge of `main`, fill [the fix pass section](#the-authors-fix-pass) when it lands. Melian's second round reviews the fixed head and is pending.

Adjudication gives the severity and the maintainer's disposition, taken from the fix pass's brief. No finding was judged noise. A valid finding Melian missed carries its reason in the Adjudication column, in the words of [the evals guideline](../../../docs/guidelines/evals.md#comparisons). "Fix pending" marks a finding the fix pass answers; its commit replaces the words when it lands.

The Golden column says whether a golden should be written. None is owed from the lenses' goldens. Two candidates are noted. The ledger's untrusted-text paths are a `trust-boundary` candidate: walkthrough prose that GitHub autolinks (D6), and a note with no bound that pushes the ledger's other sections out (C2). In both, text the head can steer reaches a comment Melian signs. The pinned summariser failure (B8–B9) is a `durability` candidate: `durability` found it, and a golden would hold that recall.

This record links [the ledger publication projection decision](../../../docs/decisions/2026-10-05-ledger-publication-projection.md), which arrives with [pull request #73](https://github.com/melian-agent/melian/pull/73). The link resolves once it lands.

## Maintainer decisions

The Opus review would overturn four of the author's calls, and the Sonnet review five; three overlap. The maintainer took every one into the fix pass's brief, along with Codex's four findings.

- **Another commenter cannot block publication.** Discovery ignores a ledger-looking comment the publisher did not write, refuses only Melian's own unverifiable ledger, and runs after the status and the review. A ledger problem sets a status that names the recovery. With an installation token, ownership comes from the recorded comment ID and author, never a permissive default. From A1, A4, C1, and D1.
- **Discovery reads the recorded comment first.** A damaged one is refused with recovery steps, and markers are scanned only when no ID was recorded. From A2.
- **The fingerprint covers the visible body.** It is taken from the final bounded body, checked on read, and compared exactly. From A3 and D2.
- **The summariser's output is bounded, and the walkthrough is cut first.** Its failure note is a fixed phrase. From C2, C3, and D4.
- **Model-written prose cannot autolink.** From D6.
- **A failed walkthrough is retried, and never fails `melian review`.** Only a pull-request target is summarised. From B8–B9, C5, C6, C7, D3, and D4.
- **A finding comment without Melian's marker does not block publication.** From C4 and D5.
- **The abandoned round's status keeps the ledger link.** From B5.
- **Stored history is bounded, and a base-only change does not repeat a round number.** From C8 and D8.
- **The hardcoded verifier line goes.** From the Sonnet review's fifth call.

The brief also takes Melian's other findings, C9 to C11, D10, and D11's first two points. Two of the Sonnet review's findings are not in it: the stale commands in history (D7), and the one-way upgrade (D9). They stay open.
