# Comparison review: [pull request #74](https://github.com/melian-agent/melian/pull/74)

Pull request: [melian-agent/melian#74](https://github.com/melian-agent/melian/pull/74), the Codex seatbelt wrapper. `scripts/codex-sandboxed.sh` runs a full-access Codex task inside a macOS seatbelt profile. Codex's workspace-write sandbox prevents commits and fetches because it denies writes under `.git`. The wrapper allows the git state those commands need. It confines the task to a linked worktree, scratch, a per-run directory, and named git and Codex state paths. Later passes narrow Mach services, unix sockets, the environment, and repository-planting routes. Tests generate the profile and run `sandbox-exec` with temporary repositories and a stand-in Codex.

Reviewers: two Sonnet 5.5 reviews of record, at `24776d7` and `8158233`; and nineteen Melian range reviews, from `6909e44` to `54ee27d`. Rounds one to ten used Claude Opus 5.5. Rounds eleven to nineteen used Codex GPT-6.1 Sol through the wrapper. There was no standalone Codex adversarial review. Claude Sonnet 5.5 agents wrote the implementation and each fix pass from briefs. The pull request merged at `ad303b5`. The live Codex probes exercised the wrapper; they were not adversarial reviews.

The sources are the two Sonnet reports, nineteen printed Melian verdicts, four live probes, the branch's commit history, and its progress entry. Sonnet's first report numbers ten findings. Its second report says all eight round-one findings closed; this record keeps the first report's ten numbered entries. A fix in the next pass is evidence that the maintainer accepted the finding. Severity stays as printed by the reviewer. A separate severity judgement, dismissal, or miss reason that the sources do not show is **not recorded**. Residual risks documented by a fix are distinguished from paths the fix closes.

The Golden column names candidates, not debt the maintainer has adjudicated. No source records an owed golden or a noise judgement. The [evals guideline](../../../docs/guidelines/evals.md#comparisons) requires a named lens before a golden is owed. The reviewers ran on different heads, so their differences are not a recall or precision measurement at one revision.

Most reading candidates belong to `trust-boundary`. A compact series could hold the main `.git` rename, a nested case-folded `.git`, a bare repository, and `HEAD` with `commondir`. A second series could hold an allowed subtree omitted from denies and an exception that reopens a repository form. Service and socket cases need runtime controls beside the reading examples. The branch's fixes support validity; they do not supply a formal `owned-missed`, `no-owner`, or `needs-execution` adjudication. None is invented here.

Nineteen rounds reviewed one script and its profile. Pass after pass found one more route to a planted repository, a credential, or a repair that broke a command. Lenses found concrete defects, but their file-based reports did not establish a complete sandbox boundary. The cost includes nineteen review runs, fix passes, live probes, and incomplete provider runs. A sandbox review needs an inventory of every writable subtree, every exception, and every service that can act outside the process tree. Lenses can attack that inventory; a sequence of narrower findings cannot replace it. The residual-limits decision settles the host boundary: the wrapper confines task writes, while the host remains responsible for what it runs from task-written files.
