# Comparison review: pull request #21

Pull request: [melian-agent/melian#21](https://github.com/melian-agent/melian/pull/21), step 9, the skills over the `melian` CLI.

Reviewers: Codex adversarial review, then an Opus review of record. Each group was applied in turn, in that order.

## Codex adversarial review

Four findings, all adjudicated valid, all on the boundary between a skill, the repository it runs in, and the contributor running it.

| # | Reviewer | File | Summary | Adjudication | Golden |
|---|---|---|---|---|---|
| A1 | Codex | `skills/*/SKILL.md` | Without `melian` on the path, the readiness step treated any checkout holding `packages/cli/bin/melian.js` as Melian's own, ran `npm run build`, and ran `npx --no melian`, pre-approved, so a repository under review could ship that file and have the agent run it | Valid, high; reproduced by reading the skill and its `allowed-tools`. A skill runs only the `melian` on the path, never builds, installs, or runs one from the checkout, and stops with install steps for the user when there is none. `allowed-tools` is exactly `Bash(melian doctor)`. `melian doctor` prints the executable that ran and its real path, and warns when either lies inside the checkout | Yes |
| A2 | Codex | `packages/cli/test/skills.test.ts` | The test checked only commands that began with `melian`, so a skill could run any other executable, or pre-approve `melian publish`, and pass | Valid, medium; the test now parses every fenced line and every inline span that reads as a command, fails on any executable but `melian` and on any command substitution, and checks `allowed-tools` against the exact allowlist. Run against the skill before A1, it reports thirteen foreign executables, from `git clone` to `npx --no melian`; pre-approving `Bash(melian publish)` fails it | No |
| A3 | Codex | `melian.yaml` | The root `melian.yaml` routed every tier to Anthropic, so the repository chose each contributor's provider and spend, and `--model` filled only unrouted tiers, so it could not override them | Valid, medium; the root `melian.yaml` routes nothing. | A4 | Codex | `.claude/skills/melian` | The repository's skill was a symlink, which git writes as a text file where symlinks are off, so the skill did not load | Valid, medium; the directory holds a copy of `skills/claude-code/SKILL.md`, and a drift test fails when the copy differs from the source | No |

Three choices went beyond the brief:

- A1: the skill also stops to ask when `melian doctor` warns that the `melian` on the path lies inside the repository, and reviews only once the user confirms they installed it there. The warning alone would leave the agent to decide whether a checkout's binary may review its own change.
- A2: a span is a command when it reads as one, several words or a bare word, unless it starts with an option or holds one path, number, quoted argument, or word from `melian doctor`'s output. Three prose spans in the skills, a placeholder `N`, the Bash tool's `timeout`, and a message Melian prints, read as commands under that rule, so they are now prose.
- A3: `isPolicyFile` counts `melian.local.yaml`, so a head that commits one with `git add --force` is reviewed as a policy change. A pull request review never reads the local file, so it needs `--model` in a repository that routes nothing; the skills and the CLI guideline say so.

Two choices went beyond the brief:

- B3: under `MELIAN_STATE_DIR` each clone gets its own subdirectory, the first 16 hex digits of a SHA-256 of its common git directory's real path. A range's changeset ID hashes only its ref names, so two clones reviewing `origin/main...HEAD` under one state directory would otherwise share a file.

## Differences

Codex found four, all on the boundary between a skill, the repository it runs in, and the contributor running it: who supplies the `melian` binary, whether the test enforces that, who chooses the models, and whether the repository's own skill loads at all.

The Opus review of record found thirteen and reproduced nine. Its own were about whether the loop works on the hosts and the record it claims: the sandbox that keeps `.git` read-only, the milestone closed without a publication, the review killed at the Bash tool's limit, and Melian's own guardrail blocking this branch on a manifest no build reads. Codex found none of these.

Four findings overlap. Both reviewers found the hostile-checkout bootstrap (A1, B1) and the committed routes (A3, B2); B5 is A2's test seen through a list of hostile edits, and B9 is A4.

Each valid finding marked as golden is to be written for the evals corpus once step 5 of the [implementation plan](../../../docs/design-implementation-plan.md) defines the format.
