- **Policy follows the committed tier.** A lens a preference file moves keeps its committed tier's `accept` and `acceptOverridden`. From A4 and C3.

- **A command runs only from a file git ignores and tracks under no case of its name.** Untracked is not enough. From B1 and C1.

- **A refusing route must accept something.** From C9.
- **Bedrock's bare model ID stays until a live run settles it,** and credential commands on a repeat review are left for step 14. From C10 and C11.

### For the maintainer: mode 600 for a command source

2932128 went beyond its brief. The brief asked for one open with `O_NOFOLLOW`, checks on the handle, a refused shared directory, and `chown` advice for a file another user owns. The commit also requires mode 600 for any secrets file that holds a command, the user-level file as well as the per-clone one. Before, the rule was a file the user owns that neither group nor others can write.

The reason is a path B1 named and d72b387 does not close. #61's `.gitignore` lists `melian.secrets.yaml`, so a head's file that a patch writes there, through `gh pr diff N | git apply`, is untracked and ignored, and passes both of d72b387's checks. Only its mode tells it apart: git writes it as 644 under the default umask. Mode 600 refuses it.

The cost falls on users. A `~/.config/melian/secrets.yaml` of mode 644 that holds a command now fails, though no head can write that file; a file without a command still loads, with a warning. The rule also holds only under the default umask. A maintainer whose umask is 077 gets a patched file of mode 600, and the `git apply` path is open again for them. The decision records the rule. The maintainer should confirm it, or narrow it to the per-clone file and find another guard for the patch path.
