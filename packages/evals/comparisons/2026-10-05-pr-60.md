# Comparison review: pull request #60

Pull request: [melian-agent/melian#60](https://github.com/melian-agent/melian/pull/60), which fixes [issue #22](https://github.com/melian-agent/melian/issues/22). Lens `paths` globs compiled to a backtracking `RegExp` and ran against file paths the head chooses, so a crafted path could hold a review for minutes. `packages/core/src/glob.ts` is deleted, and lens selection calls `matchesGlobs` on the linear engine in `packages/core/src/pattern.ts`. Two timing tests hold the bound, one through `compileGlob` and one through `Lens.select`. `Lens.load` compiles every `LENS.md` glob, so an oversized glob is a `LensError` at load rather than a failure inside a lens run. An `AGENTS.md` learning now names the new engine.

Reviewers: Codex adversarial review; Melian's own review, as a range, in three rounds; and an Opus review of record. Codex reviewed 32c6aba with the author's next fix uncommitted in the working tree. Melian's first round reviewed 31c0eb0 and its second b481598. The Opus review reviewed b481598. CI passed at b481598 on Node 22, 24, and 26. The Opus review's fixes then landed one commit each: 7cb904b, 2dafe34, 058be69, 56c1c43, and 9bc8876, with the pull request body reworded. Melian's third round reviewed 9bc8876, and its one fix landed in 6a5dee6. The maintainer marks #60 ready at 6a5dee6 and queues it without a fourth round, since that change is one sentence. Neither Codex nor the Opus review ran on a later head than b481598.

## Differences

Each reviewer found something the others did not, and no two found the same defect.

Codex found the one defect in the code under review. It asked what happens when selection short-circuits on a matching glob, and ran an oversized glob to see the check record read `ran`. The author's own fix was already in the working tree, uncommitted, so Codex's finding cost nothing but the commit.

Only Melian asked for the proof through lens selection (B2), the thing the issue is about. Its `tests` lens read the timing test, saw that `compileGlob` was already linear on main, and showed that a `RegExp` back in `lensCovers` would pass the suite. The author's fix then failed on main's code after 337 seconds, which is the evidence the first test lacked. The Opus review read b481598, after the fix, so it could not raise it. Melian's second round alone saw the two long sentences (D2), and its third alone saw the guideline C1's fix left stale (E2).

The Opus review's differential comparison was the only evidence on semantic parity: 110 repository globs over 1,828 paths each, 200,000 pairs in all, and a fuzz of 300,000 random pairs. The two differences were impossible git paths. It found the one real gap adjacent to the diff by asking what `loadConfig` refuses that `anchor()` did not (C1). Neither the old matcher nor the new one refused a brace, a class, or a trailing slash. It also measured what no one else timed, the engine's constant on benign long paths, and corrected the body's claim about reach (C5).

Notices aside, the reviews raised eleven distinct findings: A1, B2, C1 to C7, D2, and E2. Leaving out C1 and C2, which predate #60, Melian's recall is three in nine and its precision three in three. The Opus review found five of the nine, C3 to C7, and C1 and C2 besides. Codex found one, A1, which the author had already fixed. Against the eight findings in the branch at b481598, the head the Opus review read, the Opus review found seven and Melian's round two found D2, which the Opus review missed. E2 is the one defect in a fix: Melian's third round found it where no other reviewer read, as its later rounds did on #51, #55, and #57.
