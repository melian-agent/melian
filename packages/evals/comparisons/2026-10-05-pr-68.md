# Comparison review: [pull request #68](https://github.com/melian-agent/melian/pull/68)

Pull request: [melian-agent/melian#68](https://github.com/melian-agent/melian/pull/68), the first pull request of milestone 2's step 15. Core gains `ExternalFinding` and `Comparison`, stored as a `melian.comparisons` document beside the findings. `packages/github` imports a pull request's review threads through GraphQL, CodeRabbit's by default. The pipeline's file importer reads the external-finding shape and Codex's review-output schema. An external finding matches a Melian finding at the Melian finding's location, or at a `cause` location at head, within three lines. A maintainer can match and unmatch by hand, and `melian compare` reaches all of it from the CLI.

Reviewers: Codex adversarial review; Melian's own review, as a range, in two rounds; and an Opus review of record. Melian's first round and the Opus review reviewed the branch at ed24860, where CI passed. Codex's first two attempts there failed with the model at capacity, and a third is running. The fixes landed one commit each: 9161d5c, 4a6c5d8, b77c58e, a1df81b, 3414a72, 5b53ae0, 65d3e1d, df1442d, 36bd89a, 5ef24dc, a03b4fe, 5117a4a, 4cf5e77, and 644c207. d0aad29 fixes a Biome finding in a new test. At 644c207 the gate passed 1010 tests, and CI passed. Melian's second round reviews 644c207 and is pending.

Adjudication gives the severity and the maintainer's disposition. Every finding was accepted, and none was judged noise. A valid finding Melian missed carries its reason in the Adjudication column, in the words of [the evals guideline](../../../docs/guidelines/evals.md#comparisons). The Golden column says whether a golden should be written. None is owed: the comparison counts other reviewers' findings, and that code is outside what the lenses' goldens measure. Two pairs of misses point elsewhere. C2's grouping collapse and C3's silent-finding inflation are the kind the comparison's own counts would have exposed on the first customer repository, as totals a hand count of the threads disagrees with. C5's escape to standard error and C8's ID collision are `needs-execution`, since probes found them. They join step 6's verifier evals and step 11's list for the tool manifest.

This record links [the comparison sites decision](../../../docs/decisions/2026-10-05-comparison-sites.md), which arrives with [pull request #68](https://github.com/melian-agent/melian/pull/68). It also links the records for [pull request #61](2026-10-05-pr-61.md) and [pull request #62](2026-10-05-pr-62.md), which arrive with [pull request #64](https://github.com/melian-agent/melian/pull/64) and [pull request #67](https://github.com/melian-agent/melian/pull/67). ## Maintainer decisions

The Opus review would overturn six of the pull request's calls. They were upsert-only imports, chaining across one reviewer, comparing against silent findings, the category line as the title, the reviewer's name in thread IDs, and a version 1 document with no forward guard. The maintainer overturned all six.

- **An import replaces what its source last imported.** A hand record on a withdrawn finding goes with it. A file finding without a `ref` is known by its file, line, and title, and a repeated `ref` is refused. From C1, C4, and B2–B3.
- **A group holds one finding per reviewer, and each Melian finding is its own group.** From C2 and B4.
- **Only the findings Melian showed or dismissed take part.** From C3.
- **CodeRabbit's first line is its severity, and the next its title.** From C7.
- **An ID hashes its source alone, and a reviewer records whether its author is a bot.** Copilot's bot is `copilot`, a bare bot name matches only a bot, and logins compare without regard to case. From C8, C9, C15, and C16.
- **A comparison keeps the fields it does not know.** The review found that version 1 had no forward guard: an older binary rewriting a comparison would drop a field a newer one stored, such as an adjudication. 5ef24dc carries unknown top-level fields through `toJSON`. The point came from the review's claims, not its eighteen findings, so the counts below leave it out.
- **The agent saves the `result` field of Codex's companion output.** Teaching the importer the envelope was the larger change. From C14.

### For the maintainer: the pull request's own description

At 644c207 two sentences still describe the head before the fixes. The pull request's progress-log entry, and the first bullet of its description, say an external finding's ID hashes the reviewer and the source reference. Since 3414a72 it hashes the source alone. The progress-log entry also says every later import keeps a hand match or unmatch. Since 9161d5c, one on a withdrawn finding goes with it. `design.md`, the plan, and the decision already say both.

### For the maintainer: the free-domain-function check

Neither the `free-domain-function` guardrail nor the Biome rule fired on B6, though `AGENTS.md` names the breach. Both match a first parameter from a fixed list of types, and `Comparison` and `ExternalFinding` are not on it. Adding both to the two lists would have caught all three functions at ed24860. Each new domain class in step 15 widens the gap.

## Differences

Melian found the defect the Opus review rated first: imports that only upsert (B2–B3, C1). Its `correctness` lens raised it at P2, with the rerun that shows it. Melian also found the convention breach on rendering (B6), which the Opus review listed as style (C17). Melian alone found six more, all tests and conventions, and all low.

The Opus review's probes found four defects Melian's reading did not: the grouping collapse (C2), the silent-finding inflation (C3), the ID collision (C8), and the escape to standard error (C5). The last two are `needs-execution`. The first two are not, and they are the more telling. C2 broke a sentence the design states, and the pull request's own test asserted the break. Melian's `tests` lens quoted that test twice, in B4 and B10, and read it as coverage. [The record for pull request #62](2026-10-05-pr-62.md) saw the same shape in its A1: a test that asserts the defect reads as proof the code is right. There Codex read the test against the design; here no reviewer of record did until the probes ran.

C3 is a question about the measurement itself, not the code: which of Melian's findings a comparison should count. The design did not say, and no lens asks. Step 15's next pull request adds `compare stats`, which reports recall from these counts. A comparison that let silent findings absorb misses would have overstated Melian's recall on the first customer repository.

C6 and C13 both need GitHub's GraphQL schema: a field's width, and a thread's two diff sides. No lens reads a query against the schema it runs on. Two in one pull request is not yet a repeat. One on another pull request would make a check against that schema a candidate.

Codex was turned away twice with the model at capacity. It is the second time in the milestone a shadow reviewer was lost to its provider. The first was Codex's second pass on [pull request #61](2026-10-05-pr-61.md), which failed twice the same way before it ran.

Its recall is eight in twenty-four. Of the sixteen it missed, seven are `owned-missed`: five for `correctness` and two for `conventions`. Seven are `no-owner`: C3, C6, C9, C12, C13, C14, and C18.
