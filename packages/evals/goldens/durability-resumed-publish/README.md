# durability-resumed-publish

Seeded from finding A3 of the [comparison record](../../comparisons/2026-10-03-pr-19.md) for [pull request #19](https://github.com/melian-agent/melian/pull/19): `publishReview` resumed every publish task a crash left, so a publish interrupted before its post, followed by a retarget that kept the head, posted the review of the old diff. The base aborts every publish task a crash left before it creates its own, so a task created for an older target ends unposted. The head swaps that abort for resuming each task and waiting for it, so the stale task posts. A wait alone would not do: `waitForTask` starts the harness's scheduler, which resumes every unfinished task, so a base that only created and waited for its own task would carry the defect already.
