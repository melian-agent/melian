# correctness-repeated-shape

The change adds three readers, one per file, with one defect: `slice(-count)` returns every entry for a count of 0, which the change declares hides the section. A lens reports each instance as its own finding, and each names the class: one of three, with the other two cited as `context`.

Three findings are the honest outcome, not one. Folding the instances into one finding would key its identity, its dismissal and its verdict to one instance: a dismissal would hide an instance a later push adds, and a verifier that found the reported instance guarded would take the rest with it. Each finding naming its class still shows the reader the class in one round. The readers sit in three files because scoring matches a finding by file and rule, so three findings under one rule in one file would score as one found and two extra. The shape comes from milestone 2's rounds, which found one instance of a class a round: one more missing input in the adjudication task's attachment key in each early round of [pull request #117](https://github.com/melian-agent/melian/pull/117) ([record](../../comparisons/2026-10-14-pr-117.md)), and one more spelling past the re-scope check's name matching in each round of [pull request #116](https://github.com/melian-agent/melian/pull/116) ([record](../../comparisons/2026-10-14-pr-116.md)).
